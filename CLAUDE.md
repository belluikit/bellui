# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## About

Bellui is a cross-platform GUI toolkit for Go. Module path: `github.com/belluikit/bellui`. Supports desktop (Linux, macOS, Windows), mobile (iOS, Android), and web (WebAssembly).

## Architecture

### Core Interface Pattern

Everything builds on `bellui.CanvasObject` (defined in `canvasobject.go`): MinSize, Move, Position, Resize, Size, Hide, Show, Visible, Refresh.

Widgets implement `bellui.Widget` which adds `CreateRenderer() WidgetRenderer`. The renderer handles layout and drawing, separating logic from presentation. Key interfaces are defined in root-level files: `app.go`, `window.go`, `canvas.go`, `canvasobject.go`, `widget.go`, `driver.go`.

Behavioral capabilities are composed via interfaces: `Tappable`, `Draggable`, `Focusable`, `Scrollable`, `Hoverable`, `LongPressable`, `Disableable`, etc. (all in `event/event.go`).

### Interface Composition Pattern

Core interfaces (`App`, `Window`, `Driver`) are kept minimal. Optional capabilities are exposed via small extension interfaces and type assertions:

**App optional interfaces:** `CloudApp` (cloud provider), `NotifierApp` (system notifications). Standalone functions: `bellui.OpenURL()`, `bellui.SendNotification()`, `bellui.ShowAndRun(w)`.

**Window optional interfaces:** `MasterWindow` (`SetMaster()`), `DroppableWindow` (`SetOnDropped()`).

**Driver optional interfaces:** `DoubleTapDriver` (`DoubleTapDelay()`), `ScreenBlankingDriver` (`SetDisableScreenBlanking()`). Standalone: `bellui.DoubleTapDelay()`.

**Preferences** uses generic free functions instead of typed methods:
```go
// Interface: Value(key) (any, bool), SetValue(key, value), RemoveValue(key), AddChangeListener(func())
bellui.SetPref(prefs, "key", 42)            // type-safe via generics
val := bellui.PrefOr(prefs, "key", 0)       // returns int with fallback
bellui.SetPrefList(prefs, "items", []string{"a", "b"})
items := bellui.PrefListOr(prefs, "items", []string{})
```

### Platform Abstraction

Platform-specific code uses build tags, not runtime checks:
- `mobile` / `ios` / `android` - mobile platforms
- `no_glfw` - skip GLFW-dependent tests (test-only; set in macOS/Wayland CI). NOT a driver selector — all desktop platforms (macOS, Linux, Windows) use the go-gl/glfw driver by default
- `no_native_menus` - disable the native macOS NSMenu bar, falling back to canvas-drawn menus
- `wayland` - **forced** Linux Wayland-only build (single backend). Rarely needed — the default build now selects X11/Wayland at *runtime* (see Runtime Wayland/X11 Selection below), so a plain build runs on both. Kept for packagers who want a lean single-backend binary.
- `x11` - **forced** Linux X11-only build (single backend), the counterpart to `wayland`.
- `wasm` / `js` - WebAssembly
- `ci` - CI test behavior
- `migrated_belluido` - test compatibility tag
- `accessibility` - opt-in screen-reader support (semantic tree walker + platform backends; see Accessibility Semantic Layer below)

Driver implementations live in `internal/driver/` with `common/`, `mobile/`, and shared logic.

### Key Packages

- `app/` - Application lifecycle, preferences, settings
- `canvas/` - Drawing primitives (text, shapes, images, gradients)
- `container/` - Layout containers (VBox, HBox, Border, Tab, Split, Grid)
- `widget/` - UI widgets (Button, Entry, Label, List, Table, Tree, etc.)
- `layout/` - Layout managers
- `dialog/` - Modal dialogs (file, color, confirmation)
- `data/binding/` - Type-safe data binding with change listeners
- `storage/` - URI handling and file system repository pattern
- `theme/` - Theming system and bundled icons
- `test/` - Test utilities and assertions
- `internal/` - Cache, painters (software/GL), SVG handling

### Testing Patterns

Tests use `github.com/stretchr/testify`. The `test` package provides:

- `test.NewTempApp(t)` - Creates a test app with automatic cleanup
- `test.AssertObjectRendersToImage(t, "master.png", obj)` - Visual regression testing against `testdata/` baselines
- `test.AssertObjectRendersToMarkup(t, "master.xml", obj)` - Markup-based rendering verification

Failed visual tests write output to `testdata/failed/` for comparison.

For locale-dependent tests in widget packages, use `lang.SetLocaleForTests("en-US")` to override the system locale.

## Fork-Specific Features

This fork extends upstream Bellui with several features:

### Advanced Text Layout
`bellui.TextStyle` has three new fields for fine-grained text control. All three are **pointer** types with a **nil** sentinel — in struct literals wrap the value with `bellui.Ptr(...)` (e.g. `bellui.TextStyle{Weight: bellui.Ptr(bellui.WeightBold)}`); a bare `bellui.WeightBold` will not compile:
- `Weight *TextWeight` — font weight from 100 (Thin) to 900 (Black). Constants: `WeightThin`, `WeightExtraLight`, `WeightLight`, `WeightNormal` (400), `WeightMedium` (500), `WeightSemiBold` (600), `WeightBold` (700), `WeightExtraBold`, `WeightBlack`. When nil, falls back to the `Bold` bool (Bold=true → WeightBold). Weight >= 600 selects the bold font variant.
- `LineHeightScale *float32` — multiplier for line height. nil (or a pointer to 1.0) = default (font-metric-derived). Values > 1.0 increase vertical space.
- `LetterSpacing *float32` — extra horizontal space in points between glyphs. nil = no extra. Can point to a negative value to tighten.

All three flow through the go-text/typesetting HarfBuzz shaping pipeline and affect both measurement (`MeasureText`) and rendering consistently.

`bellui.TextStyle` also has a `Language string` field (BCP 47 tag, e.g. `"sr-Cyrl"`) that overrides the locale-derived `shaping.Input.Language` for script-specific OpenType feature selection and localized glyph forms. Zero value (empty) follows the active locale. Resolved by `resolveLanguage()` in `internal/painter/font.go` (mirrors `resolveBaseDirection`); only affects content shaping, not font selection or bidi ordering.

### Text Decorations — Underline + Strikethrough (#541)
`TextStyle.Underline` and `TextStyle.Strikethrough` (the latter added for upstream-2.8 parity; matching field name for cherry-pick compat) both render as decoration lines over **general text** — `canvas.Text`, `canvas.StyledText`, Label, RichText — not just TextGrid. All three painters (WebGPU, GL, software) rasterize text through the shared `paint.DrawString`/`DrawStyledRuns` in `internal/painter/font.go`, so the decoration is drawn once there: `drawUnderline` (2/5-descent below baseline) and `drawStrikethrough` (~0.3×ascent above baseline ≈ x-height center) both feed `drawDecorationLine(dst, clr, y, x0, x1, scale)`, which spans the glyph **advance** (so `LetterSpacing` is respected) in the run's own colour (`g.colors[0]` per StyledText run). Decoration bits are in the `fontSizeEntry` texture/metrics cache key (`internal/cache/text.go`) — the #70 lesson — so a toggled decoration re-renders instead of serving a stale texture (they're **not** in `cacheID`, the face-selection key, since they don't change face). Markdown `~~x~~` sets `Strikethrough` (composes with bold/italic); HTML `<s>`/`<del>`/`<strike>` → strikethrough and `<u>`/`<ins>` → underline (`widget/html.go` `htmlStyle`). TextGrid keeps its own cell-level underline path, unchanged.

### Font Fallback (CJK / non-Latin)
Glyphs not covered by the active font fall back per-rune through `dynamicFontMap.ResolveFace` (`internal/painter/font.go`): own faces → **app-registered fallbacks** → system-font scan (`fontscan`) → `.notdef`. The bundled default fonts are Latin-only, and **system-font scanning is unavailable on WebAssembly** (no scannable fonts) and unreliable on some mobile setups, so non-Latin text (CJK especially) renders as tofu there unless a fallback is **compiled in**.
- `bellui.RegisterFontFallback(res bellui.Resource)` (`font.go`) — appends a face to the global fallback chain, consulted (in registration order) *before* the system scan. Portable: works on every platform including wasm. Register once at startup; registering later invalidates the font + metrics caches (`ClearFontCache` + `cache.ResetThemeCaches`). Wired into the painter via the `bellui.SetFontFallbackRegister` hook (mirrors `RegisterTextMeasure`); the painter impl is `registerFallback`/`resolveFallback` in `internal/painter/font_fallback.go`.
- `theme/cjk` — opt-in package bundling a ~6.5 MB subset of Noto Sans CJK SC (common GB2312/Shift-JIS/EUC-KR Han, Hiragana, Katakana, common Hangul, CJK punctuation, Latin; SIL OFL 1.1). `import _ "github.com/belluikit/bellui/theme/cjk"` self-registers it on init (or call `cjk.Register()`); `cjk.Font` is the resource. The font is only linked when the package is imported, keeping default/wasm binaries lean. For glyphs outside the subset, register a fuller font.
- A custom `TextStyle.FontSource` chain also includes the bundled emoji face and benefits from registered + system fallbacks via the same `ResolveFace` path.
- **Bundled UI-symbol fallbacks (#686)** — common symbol glyphs the primary bundled fonts lack (✓ ✗ ☐ ★ ⌘ ⌥ ⇧ arrows, geometric shapes, math operators, enclosed alphanumerics, ‣ ※, …) used to fall through to the host system-font scan, giving **host-dependent text metrics** (macOS vs Linux golden-markup drift, tofu on wasm). Four OFL Noto subsets (`theme/font/NotoSansSymbols2-bellui.ttf` + `NotoSansSymbols-bellui.ttf` + `NotoSansPunct-bellui.ttf` + `NotoSansMath-bellui.ttf`, ~385 KB total, exposed as `theme.DefaultSymbolsFallbackFonts()`) are now part of every chain — appended after theme/emoji faces but **before the host locale face** (`addSymbolsFallbackFaces` in `internal/painter/font_symbols.go`, parsed once, shared across chains; also in the custom-`FontSource` and Symbol-style chains, and the Symbol chain now falls back to the bundled text font so mixed symbol/text strings stay host-independent). Strip with `-tags no_symbols`. Coverage is locked by `TestBundledFacesCoverCommonSymbols` (`internal/painter/font_symbols_test.go`). Diagnostic: set `BELLUI_DEBUG_FONTESCAPE=1` to log every rune whose resolution escapes the compiled-in faces to a host-dependent source (locale face, registered fallback, system scan).

### Per-Subtree / Per-Window Layout Direction
Layout direction is normally a process global (`bellui.SetLayoutDirection`). Two overrides let a subtree flow against the global — e.g. an LTR settings dialog inside an RTL app (#66, RTL Phase 6):
- `container.DirectionScope` / `container.NewDirectionScope(content, dir)` — wraps a subtree in an ambient direction. `DirectionLTR`/`DirectionRTL` force a direction; `DirectionAuto` inherits the enclosing one (no-op). Scopes nest, innermost wins. `SetDirection(dir)` updates it.
- `Canvas.SetDirection(dir)` / `Direction()` — an optional interface on `bellui.Canvas` (implemented by the GLFW/mobile canvas via `internal/driver/common.Canvas`) that scopes a whole window/canvas. Reach it with `w.Canvas().(interface{ SetDirection(bellui.Direction) }).SetDirection(dir)`.

**Mechanism** (mirrors the per-widget `ThemeOverride` two-seam pattern): an ambient direction is layered *under* `lang.IsRTLDirection()` via a per-goroutine stack in `internal/uidir` (`Push`/`Pop`/`Current`, keyed by `thread.GoroutineID()`), so every existing consumer (mirroring, `ResolveAlign`, `resolveBaseDirection`) becomes scope-aware with no call-site changes. `DirectionScope`'s renderer pushes around `Layout`/`MinSize`; `internal/driver/common.Canvas.EnsureMinSize` pushes per-`DirectionScope` node (alongside the existing `ThemeOverride` push) and wraps the whole walk in the per-canvas direction; the GLFW paint walk wraps the paint pass in the per-canvas direction.

**Phase 6/7 scope:** both scopes are now fully direction-correct at layout *and* paint time. Phase 6 delivered layout mirroring, leading/trailing alignment, focus order and measured base direction for both scopes, plus full paint-time text base direction for a *per-canvas* scope (the canvas wraps both layout and paint). Phase 7 (#178, Seam B) closes the remaining gap for a *container* `DirectionScope`: each driver's paint walk now pushes the scope's direction onto the per-goroutine `uidir` stack around its subtree (`internal/driver.Push/PopDirectionScope`, the paint-time mirror of the `EnsureMinSize` layout hook), so paint-time base direction of mixed-bidi text and the alignment of slack-width standalone `canvas.Text`/`StyledText` primitives inside a container scope resolve against the scope rather than the global. The hook is replicated across the GLFW (`glPaintWalk`), mobile (`mobileTreeWalker`) and software/test (`software.Painter`) walks; `DirectionScope.ScopedDirection()` lets the canvas-free painters detect the scope structurally without importing `container`. Per-run `TextStyle.Direction` remains an escape hatch. Live in-place direction toggling without a relayout follows the same runtime-refresh limitation as the global `SetLayoutDirection` (#65); the new direction is applied on the next relayout.

### Event System Enhancements
**HoverEvent + Hoverable** (`event/event.go`): `event.HoverEvent` (position-only, no button/modifier) replaces `desktop.MouseEvent` for hover. `event.Hoverable` interface with `HoverIn(*HoverEvent)`, `HoverMoved(*HoverEvent)`, `HoverOut()`. Deprecated aliases in `driver/desktop/mouse.go`. Cross-platform (not desktop-only).

**ScrollEvent.Source** (`event/event.go`): `ScrollSource` enum distinguishes `ScrollSourceMouseWheel`, `ScrollSourceTouchpad`, `ScrollSourceTouch`. GLFW sets `ScrollSourceMouseWheel`. Zero value `ScrollSourceUnknown` preserves backward compatibility.

**KeyEvent.Modifier** (`event/event.go`, #1042): `event.KeyEvent` carries a `Modifier event.KeyModifier` bitmask (Shift/Control/Alt/Super) so `TypedKey`/`Canvas.SetOnTypedKey` handlers can tell e.g. Shift+F11 from F11 without a shortcut registration. Zero value = no modifiers (backward compatible). Populated by the glfw driver (desktop + wasm, from the native mods argument), the mobile driver (gomobile `key.Modifiers`, hardware keyboards) and the embedded driver via the new `embedded.KeyEvent.Modifiers` field (which also made Shift+Tab focus-previous work there). Desktop routing is unchanged: Control/Alt/Super combos still go to the shortcut system before `TypedKey` (only unmodified and Shift-modified keys reach it); `desktop.Keyable` `KeyDown`/`KeyUp` see every combination with the modifier set. Complementary to the window-wide `desktop.KeyModifierDriver.CurrentKeyModifiers()` query.

**LongPressable** (`event/event.go`): `LongPressable` interface with `LongPressed(*PointEvent)`. Touch handler (`internal/driver/common/touch.go`) tries `LongPressable` first on hold ≥300ms, falls back to `SecondaryTappable`. Desktop right-click always calls `TappedSecondary` (unchanged). `test.LongPress()`/`LongPressAt()` helpers in `test/test.go`.

### Scroll Event Propagation
Nested scrollable containers now propagate scroll events to parent scrollables when the inner container reaches its boundary. Implemented via `ScrollConsumer` interface (`internal/driver/util.go`) and `TryScrolled()` on `widget.Scroll`. The GLFW driver iterates scrollables deepest-first.

### Scrollbar Space Reservation
`widget.Scroll.ReserveBarSpace` (default `true`) reduces content width when a vertical scrollbar is active, preventing the scrollbar from overlapping content and fixing text wrapping at the right edge.

### Date Picker Widget
`widget.DatePicker` and `widget.NewDatePicker()` — calendar-style date picker with month navigation, locale-aware day headers and week-start day. `ShowDatePicker()` displays it as a modal popup with OK/Cancel buttons.

### HTML Parsing
`widget.RichText` supports HTML content via `NewRichTextFromHTML()`, `ParseHTML()`, and `AppendHTML()`. Handles headings, paragraphs, lists, tables, links, images, blockquotes, code blocks, and inline formatting. Nested inline styles (bold+italic) compose correctly. Unsupported tags are stripped with text content preserved.

### Untrusted-Content Security (RichText HTML/Markdown)
Parsed HTML/Markdown is treated as potentially untrusted (#285). Three defenses, all in the `widget` + `internal/repository` layers:
- **Images are not auto-fetched by default.** `RichText.AllowRemoteContent` (`bool`, default `false`) gates loading of `ImageSegment`s whose source is a remote (`http`/`https`) or local-`file` URI. When `false`, such images render `theme.BrokenImageIcon()` instead — no network request, no disk read happens on render. Set it to `true` only for content you trust (local docs, your own markdown). Applies to both the `notweb` and `wasm` image paths via the shared `richImage` (`widget/richtext_objects.go`).
- **No schemeless→file fallback.** A bare/relative `src` (e.g. `/etc/passwd`, `images/x.png`) no longer becomes a `file://` URI (the old `storage.NewFileURI(src)` fallback is gone); it yields a nil source / placeholder. Embed an explicit `file://` URI for genuinely-intended local images.
- **Link-scheme allowlist.** Links from parsed markup (`parsedLinkURL` in `richtext_objects.go`, used by `html.go`/`markdown.go`) only keep `http`/`https`/`mailto` (and relative refs); `file:`, `smb:`, `javascript:`, `search-ms:`, `ms-msdt:` etc. are dropped to `nil` so tapping does nothing.
- **Hardened HTTP repository.** `internal/repository/http.go`'s `safeClient` adds a 30s timeout, a 64 MiB `io.LimitReader` cap (OOM guard), and a dial-time SSRF guard (`isBlockedIP`) that refuses link-local/metadata (`169.254.169.254`, `fe80::/10`), multicast and unspecified targets on the initial request *and every redirect*. Loopback and RFC 1918/ULA are intentionally allowed (localhost/LAN apps).

### Entry Enhancements
- `Entry.Select(startRow, startCol, endRow, endCol)` — programmatic text selection with bounds clamping
- `Entry.SelectionRange() (TextRange, bool)` — reads the selection as a normalized half-open rune range; the caret sits at one end (`CursorTextOffset`), the anchor is the other (#431)
- `Entry.InsertText(text)` — inserts at the caret as one gated, undo-recorded edit with one `OnChanged` (the exported `insertRunesAtCursor`; use instead of routing programmatic inserts through `ComposeCommit`) (#432)
- `Entry.ApplyEdits([]TextEdit)` — atomic multi-range edit for block indent/dedent and replace-all: `TextEdit{Start, End, Text}` rune offsets into the pre-batch content, applied right-to-left, all-or-nothing gating through `ProtectedRanges`/`BeforeChange`, recorded as **one** undo step (compound `entryBatchModifyAction` in `entry_edits.go`) with one `OnChanged`/Validator run (one sync point under `DeferTextSync`); overlapping ranges are rejected (#433)
- `Entry.AddShortcut(shortcut, handler)` — register custom keyboard shortcuts
- `Entry.KeepSelectionVisible` — keeps selection highlight visible after focus loss
- `Entry.OnSelectChanged` — callback fired when text selection changes
- `SelectEntry.OnOptionSelected` — callback fired when a drop-down option is picked, after `SetText`/`OnChanged`; distinguishes a pick (a complete edit — e.g. an inline cell editor committing on pick) from free-text typing, which never fires it (#1047)
- `Entry.StyleOverlayForRow func(row int) []StyleRun` — a settable, pull-based, row-indexed **foreground** style overlay composited over `LineHighlighter` output (#1079). Foreground color only ever reaches glyphs through `StyleRun`, and `LineHighlighter` is line-at-a-time with no row index — so a host that colors from a *whole-document* analysis (LSP semantic tokens: absolute `(row,col,length,tokenType)` ranges, e.g. goed#208/fycoder#175) had no seam to deliver it. The overlay is consulted at render time for the rows the renderer materialises (visible window on large docs, O(viewport)); the runs tile the row from rune 0 by `Text` length (a zero-valued run is a **spacer** leaving its range unstyled, so a sparse overlay is spacer/token/spacer/token, and the tiling may stop short of the row end), and are merged over the base runs by `overlayRunsForRow`→`overlaySubrange`→`mergeStyleRun` (the generalization of the old preedit `underlineSubrange`, which is now `overlaySubrange` with an underline overlay). **Precedence** (`mergeStyleRun`): a non-nil `ForegroundColor` or non-empty `ColorName` on an overlay run replaces the base foreground *as a unit* (so an overlay `ColorName` isn't shadowed by a stale base direct color), `Bold`/`Italic` only switch on, `BackgroundColor` replaces, a set `Underline` carries its style+color, a set `StrikeThrough` carries its `StrikeColor` (#1087 — defaults to the run foreground when nil, like `UnderlineColor`; rendered as a solid mid-glyph line via `newStrikeDecoration`, the strike counterpart of `newUnderlineDecoration`); unset overlay fields keep the base run's values (semantic foreground overrides lexical color without clobbering bold or a diagnostic squiggle). The `StrikeThrough` field is the run-level seam an LSP host uses to render a `deprecated` symbol struck through. **Pure composition**: it runs *after* `HighlightRunsForRow`, never feeds the lexer state chain or invalidates `hlCache`, so a host `Refresh()` on new tokens repaints without re-lexing (`TestEntry_StyleOverlay_DoesNotRelex`). Composition order in `styleRunsForRow` is highlighter → overlay → IME preedit underline (preedit shifts the one composing row's overlay offsets until commit). With no `LineHighlighter`, a base run covering the row is synthesized so the runs still tile it; an overlay of only spacers returns nil (renderer skips the row). Tests: `widget/entry_styleoverlay_internal_test.go`.
- Multi-line entries no longer auto-select-all on focus gain
- Editor-style keyboard navigation (#377): `PageUp`/`PageDown` page the caret by one **viewport screenful** (a `pageRowCount()` = visible-rows-minus-one step) preserving the column, rather than jumping to the document extremes; `Ctrl+Home`/`Ctrl+End` (macOS `Cmd+ArrowUp`/`Cmd+ArrowDown`) jump to document **start/end**, both with `Shift` variants that extend the selection. ### Large-Document Entry Storage (rope, #381/#382)
The lazy single-segment editing path of `Entry`/`RichText` stores its text in `internal/textbuf.Buffer` — a flat-spine rope of ≤4 KiB UTF-8 chunks with per-chunk rune/newline counts. Edits are O(edit + chunks); the logical-line index lives in the buffer (`LineCount`/`LineStart`/`LineOfPos`, vectorized newline search). **Identity contract**: `Buffer.String()` is memoized and returns the *same string object* until the next splice; after every provider-mediated edit `Entry.Text == seg.Text == buf.String()` hold as one object, and `lazyCanEdit()`'s `seg.Text == lazyStr` pointer compare gates the fast path — assigning a *fresh* string to `seg.Text` silently degrades to full rebuilds (guarded by the `lazyFullBuilds` test hook + `TestLazyEdit_NoFullRebuildPerKeystroke`). The **per-keystroke floor** is one document materialization (alloc + memcpy) forced by the exported `Entry.Text` field — everything else is O(edit + window): undo/redo replay is delta-native (`entryUndoAction.Apply` splices the provider), selection reads via `textRange`/`Substring` (zero-copy against the clean memo), IME preedit splices through the buffer (`preeditApplied`), the highlight cache is windowed + edit-local (`ensureHighlightedThrough`, `noteLazyLinesEdited`) and re-chains after edits above a deep viewport jump over the trusted stretches (`hlTrusted`, a sorted list capped at `hlMaxTrustedStretches`; scattered batch edits between renders each split rather than discard the chained lines around them, #418) in O(edits + convergence + window) — only the first deep jump after SetText has to chain from line 0 (#412) and a background prefill (#417, armed in `updateText`, driven by a repeat-forever animation ticking `hlPrefillTick` in ~5 ms/frame slices) usually chains there first — a jump before it finishes pays only the gap above the watermark; and the wrap-off widest-line is cached (`vwLine`/`vwDirty`). `lineWrap` sub-row offsets are **line-relative** (converted at `lazyRowBoundary`/`lazyRowColFromTextPos`). Keystroke ≈0.6 ms at 3 MB / ≈6 ms at 30 MB (memcpy-bound, position-independent); `BenchmarkEntry*BigDoc` + the env-gated `TestEntryTypeFlatLatency` (`BELLUI_PERF=1`) are the perf gates; `internal/textbuf` has an oracle/fuzz suite (`FuzzSplice`).

**Opt-in lazy-Text mode (#410)**: `Entry.DeferTextSync` lifts the per-keystroke floor. Deferred edits splice only the buffer — `lazySpliceText` skips the materialization and sets `RichText.deferredDirty` (buf is ahead), while `Entry.Text == seg.Text == lazyStr` keep the *last-synced* string object so the identity gate still holds and `syncSegments`' store stays a no-op; rendering/caret/selection read the buffer so they are always live. `Text`, `OnChanged`, the `Validator` and binding writes update once per **sync point** — `Entry.SyncText()`, focus loss, Enter/Return submission — via `lazyMaterialize` + `syncDeferredTextNotify` (a sync during IME composition excludes the spliced preedit and leaves the anchor deferred). Direct `Text` writes between sync points discard pending edits (external write wins; `updateRowBoundsLazy`'s rebuild branch clears `deferredDirty`). Deferred keystroke ≈0.15-0.19 ms **flat** 3→30 MB (`BenchmarkEntryTypeBigDocDeferred`); mode off is byte-identical. Related fix: the lazy wrap-off row model is width-independent, so a width-only change (e.g. typing into the document's widest line growing the scroll extent) no longer forces an O(lines) rebuild (`rowBoundsCacheValid`).

### IME / Composition Support
Cross-platform input-method (preedit/composition) support for CJK and other input methods (§9, [#35](https://github.com/trendvidia/fyne/issues/35)).

### Text-Input Mirror Seam (#768)
`internal/textinput` is the neutral seam binding the focused editor to each platform's native text-editing/IME surface — the document-mirror generalization of the mobile driver's old bespoke keyboard-state cache. `textinput.Session` (created per driver, rebound on focus): `Bind(focused any)` binds any `core.AccessibleTexter` as the editor and (additionally) any `event.Composable` for IME; `Sync()` pushes the editor's `(text, selection)` `Snapshot` to the driver's `Backend.SetState` (redundant-push filtered); edit ops `Insert/Delete/Replace/SetSelection`→AccessibleTexter and `Compose/Commit/CancelCompose`→Composable, each auto-syncing. A leaf package (imports only `core`+`event`); drivers own the `Backend` and drive the session. The seam also owns the **pull-side document view** (`textinput.View{Text,SelStart,SelEnd,Caret}` via `Read(ed)`, with `View.Snapshot()` the push subset) and the **edit vocabulary** as package-level primitives over `core.AccessibleTexter` (`InsertText`/`ReplaceRange`/`ReplaceAll`/`Select`); `Session`'s edit methods and `Sync` delegate to them, and the desktop a11y-text backends call them directly, so the read + edit paths have one definition. Phases: P0 seam (#769), P1 Android reference (#770, `keyboardStateBackend`→`app.SetKeyboardState`→shadow EditText) — whose `BelluiInputConnection` **coalesces IME batch edits** (#1080, the corrected redo of the reverted #1015/#1067): while an outermost `beginBatchEdit`/`endBatchEdit` pair is open the per-op committed forwards are **deferred** (`super.*` still mutates the shadow `mBelluiBuffer`, `deferCommitted()` gates every `keyboard*` call) and `endBatchEdit` emits ONE surrogate-safe base→final `keyboardReplace` → one undo step (`flushBatchDiff`, snapshotting `batchBaseText` at the outermost `beginBatchEdit`) — Select-all-then-type / autocorrect delete+commit / chip `replaceText`, the iOS input-view model. The first attempt (#1067) forwarded per-op **and** at the batch boundary, which **doubled ordinary typing** because Gboard wraps even a single-char commit in a batch (device-caught #1071, reverted #1074); deferring the per-op forward is the fix. Crucially, `BaseInputConnection.commitText`/`replaceText`/`deleteSurroundingText`/`setComposingText` **internally** wrap their Editable mutation in `beginBatchEdit()`/`endBatchEdit()`, which dispatch virtually to the overrides — so `super.*` would trigger a spurious snapshot+flush and re-double every edit; a `superEdit` re-entrancy counter raised around every `super.*` edit call makes the batch overrides skip the snapshot/flush for those internal batches, so coalescing keys off the IME's *own* outer batch only (this was the actual on-device failure mode, verified fixed on the OnePlus Pad 2 + Smart Keyboard — the #1071 rig). Composition is excluded — a fresh preedit mid-batch flushes the pending committed diff first then forwards compose events immediately (clearing `batchBaseText`), and ops that don't mutate the buffer (Enter, forward-delete, hardware shortcuts) flush-then-forward too and pushes **partial extracted-text updates** (#1009: a TextWatcher span on `mBelluiBuffer` tracks the dirty region; monitor pushes carry only the delta via `partialStartOffset`/`partialEndOffset`, caret-only changes push nothing, and a direct `getExtractedText` re-baselines windowed at the IME's `hintMaxChars` — keystrokes cost O(edit), not O(document)), **P2 iOS (#771)**, **P3 desktop a11y-text consolidation (#772)** — macOS NSAccessibility (`accessibility_text_darwin.go`) + Windows UIA Text (`accessibility_text_windows.go`) protocols resolve the per-handle editor then read/edit via the seam's `Read`/primitives instead of calling `AccessibleTexter` ad-hoc (behavior-preserving; the duplicated whole-doc "set value" and per-callback reads collapse onto `ReplaceAll`/`Read`); desktop IME stays string-oriented (GLFW `Composable`, no document mirror). P4 RichEntry consumer (#773).
- **Android one-writer key reroute (#1061)**: on Android a hardware key is delivered twice while a prose field is focused — Gboard applies it to the bellui-owned `mBelluiBuffer` through the InputConnection (`commitText`/`setComposingRegion`/`deleteSurroundingText`/`sendKeyEvent` → the IC channel), *and* the raw key still traverses the NativeActivity input queue tagged `Native`. Applying both was the dual write that doubled characters and left a spurious space after autocorrected words, and forced the driver to drop word-boundary autocorrections it couldn't reconcile. `driver.suppressNativeTextKey`/`imeOwnsNativeKey` (`internal/driver/mobile/driver.go`) makes the IC the **single writer** by ignoring the redundant native echo of any bare printable key or Backspace while a **prose** field is focused (`keyboardType` ∈ {Default, SingleLine}); so Gboard's autocorrect/auto-capitalization simply land as the committed edits it already sends. **Password/number fields are excluded** — they disable composition, so Gboard passes their hardware keys *only* through the native queue (device-verified: suppressing there kills all typing). Non-text keys (arrows/Enter/Tab) are never suppressed. This retired the three delivery-keyed reconciliation mechanisms of #1057 (the `ic_echo.go` dedup, the stale-finalize drop, and `composeAdvance`), which are **deleted**. CJK is structurally unaffected (genuine composition keeps the editor composing and flows through the preedit/commit path). Verified on-device with a OnePlus Smart Keyboard (`hack/echoprobe966`).
- **Android hardware-keyboard shortcuts (#1077)**: Ctrl+A/C/V/X/Z/Y from a hardware keyboard used to be lost — Gboard hands a shortcut combo (Ctrl/Alt/Meta held, `getUnicodeChar()==0`) to `BelluiInputConnection.sendKeyEvent`, which delegated to `super` (the inert host `EditText`), never reaching bellui. Because the hardware key **also** dual-delivers on the native queue (like text), `imeOwnsNativeKey` now suppresses the native echo of **any** shortcut combo (Ctrl/Alt/Meta) in every field type — otherwise the shortcut dispatched twice (device-verified: Ctrl+V pasted the clipboard twice; A/C/X are idempotent so only V/Z show it). Verified on-device (`hack/echoprobe966`). Needs the tools-repo dex regen (`GoNativeActivity.java` changed).
- **Android hardware-keyboard Shift+Arrow selection (#1083)**: Shift+Arrow didn't extend an Entry's selection. Hardware arrows are delivered *only* via the IME's `sendKeyEvent` DPAD block → `keyboardArrow` (they never reach the native queue — `convAndroidKeyCode` leaves DPAD unmapped), and that call **dropped the meta-state**; the Shift key itself reaches `processKey` but only as `TypedKey` (never `KeyDown`, so `Entry.selectKeyDown` stays unset), and the #1061 action-inversion would break a `KeyDown`-based fix anyway. Verified on-device. Also needs the same dex regen.
- **iOS backend — `BelluiTextInputView` (#1117/#1119, epic #1115; supersedes the #771 `GoInputView` UITextView proxy):** a hidden **bare `UIView<UITextInput,UITextInputTraits>`** (`darwin_ios.m`), the Flutter `FlutterTextInputView` model, hosted in the app **window** as a sibling of the GLKView — never a GLKView subview, whose CAMetalLayer entanglement froze rendering on keyboard presentation (#1124). It owns an authoritative UTF-16 document mirror (text + selection + marked range) and intercepts edits **at source** (`insertText:`/`deleteBackward:`/`setMarkedText:`/`unmarkText`/`replaceRange:`) — no `textViewDidChange:` diffing — forwarding per-rune `keyboardTyped` (preserves `NumericEntry`'s filter), `keyboardReplace` (#748), `keyboardComposing`/`keyboardComposeCommit` (#747) and `keyboardSetSelection`; Go `SetKeyboardState`→`belluiSetDocument` reseeds the mirror per repaint (no-op while composing). Owning the view means owning its **tokenizer** (`BelluiTokenizer`, #1113 — a UITextView subclass cannot replace its tokenizer) and its **geometry** (the #1107 sidecar answers `selectionRectsForRange:`/`caretRectForPosition:` from bellui's real layout). Under VoiceOver the a11y bridge publishes **the input view itself** as the focused element — first responder and VO-focused element must be the **same object** for insertion-point editing (#1124; a detached forwarding element engages reading/cut but never caret navigation). **Interrupted composition finalizes deterministically** (#1118): an external caret move mid-composition (tap; VO tap arrives via `setSelectedTextRange:`, a bellui-side tap via the push's caret-vs-anchor signal, per the #1057 anchor-collapse invariant) commits the marked text as typed, places the caret at the target, then tells the keyboard via `textWillChange`/`textDidChange` — never wait for the IME to finalize (Apple Pinyin commits then restores *its own* caret); `Entry.ComposeCommit` preserves an out-of-preedit caret (extension of #945). The 1×1 first-responder frame suffices for the CJK candidate bar (device-verified); `autocorrectionType = Default` still required. **Selection sync runs per repaint** (`syncKeyboardState`), skipped mid-composition. ### Mobile Touch Text Selection (#758)
Native-parity touch selection UX for `widget.Entry` on mobile (Android/iOS/embedded):

### Editable Rich Text — widget.RichEntry (epic #648)
`widget.RichEntry` (`widget/richentry.go` + `richentry_doc.go` + `richentry_undo.go` + `richentry_html.go`) is the **editable** counterpart to read-only `RichText`, which it reuses as its measure/render engine (the way `Entry` hosts `textProvider()`). `Entry` is the wrong vehicle for this — it is flat-string / single-`TextSegment` with `int` rune offsets throughout — so RichEntry is a new widget with its own document model. `richtext.go`/`entry.go`/`selectable.go` are **untouched** by the whole epic (same-package internal reuse → no regression surface); the only shared change is additive `ImageSegment` fields.
- **Document / position model** (`richentry_doc.go`): an ordered `[]RichTextSegment` of inline `TextSegment`s plus block `ImageSegment` atoms. A caret position is a global offset where each text rune counts 1 and **each atom counts exactly 1** (`segPositions`) — the `(segmentIndex, runeOffset)` space the epic needed. `insertText` splits a run on a style change, `deleteRange` merges adjacent equal-style runs, `applyStyle` splits a range, `segmentsBetween`/`replaceRange`/`insertSegments` capture and splice styled fragments (shared by undo + paste). Style equality is **value-based** (`richStyleEqual`) because `bellui.TextStyle`'s `Weight`/`LineHeightScale`/`LetterSpacing` are pointer fields — a plain `==` would never merge visually-identical runs.
- **Geometry**: the caret currency is `(row, col)`, because RichText's flat-offset helpers (`textPosFromRowCol`, `selectable.go`) are single-segment-only while `lineSizeToColumn` (`richtext.go`) measures multi-segment rows. **Wrapping is off** — each `\n`-separated line and each block image is one row; the row model is an atom-aware segment walk **validated in tests against `provider.rows()`** so it matches RichText's actual `updateRowBoundsInner` layout. An image row's caret sits at the row's left edge (RichText's column space is zero-width for images). Word-wrap is deferred to #653.
- **Editing**: Focusable; typing / Backspace / Delete / arrows / Home/End / Shift-select; `SetSegments`/`Segments`/`String`/`SelectedText`; `ApplyStyle(RichTextStyle)`; `InsertImage(image.Image)` / `InsertImageResource(bellui.Resource)`.
- **Undo/redo** (`richentry_undo.go`, #656): every mutation is captured as one reversible `richEntryEdit` delta ("replace positions [from,to) with these segments"), derived from the document length change, so insert / delete / type-over-selection / restyle / paste all route through the single `mutate` wrapper → `richEntryUndoStack`. Style- **and image-preserving**; contiguous same-style typing merges into one step with word-granular breaks. `ShortcutUndo`/`ShortcutRedo` wired; `SetSegments` clears history.
- **Change notification**: `OnChanged func()` (any edit) and `OnContentChanged func([]RichTextSegment)` (typed, live segments, #660) — both fire from `afterEditNotify` so they also cover undo/redo.
- **In-memory images** (#655): `ImageSegment` gained `Image image.Image` and `Resource bellui.Resource` sources; `richImage.loadImage` renders them directly (`canvas.NewImageFromImage`/`NewImageFromResource`), **bypassing the `AllowRemoteContent` gate** since nothing is fetched. Also usable from plain `RichText`.
- **Flavor-aware clipboard** (#657/#666): negotiates the #513 optional interfaces (asserted from the passed clipboard). Paste: image → `InsertImage`; HTML → `NewRichTextFromHTML` + `flattenHTMLToInline` (block boundaries → `\n`, styles kept, images as atoms) spliced as one undo step; else plain (CRLF normalized). Copy/cut: a lone in-memory image → `SetImage`; styled text → `SetHTML` (`segsToHTML` — b/i/u/s + `<br>`, escaped) with a plain fallback. Inline boundary whitespace (a space *at a style boundary*) now round-trips through our own HTML (#668 fixed; `TestRichEntry_HTMLRoundTripPreservesBoundaryWhitespace`).
- **IME composition** (#658): implements `event.Composable` (Compose/ComposeCommit/ComposeCancel) + `event.PreeditPositioner`. The preedit is shown inline underlined via **display-only segment injection** (`displaySegments` splices the preedit run at the caret; the document, undo and change callbacks are untouched until commit); the caret is mapped against a display document (`caretDoc`) so it tracks inside the preedit, and `PreeditCursorRectangle` positions the candidate window. A typed rune commits (desktop char-callback path), Escape cancels, focus loss cancels. The existing glfw/wasm driver plumbing drives it (RichEntry is auto-detected as `Composable`). Incremental/lazy measurement for large rich docs (the provider re-lays-out per keystroke) is a separate perf follow-up.
- **Status — feature phases complete** (all #648 sub-issues shipped): inline images (#665), segment-aware undo/redo (#656), flavor-aware clipboard (#657/#666), IME `Composable` (#658), accessibility `AccessibleTexter` + custom actions (#659/#1025), word-wrap (#653), typed `OnContentChanged` (#660), lazy incremental measure, HTML-whitespace fidelity (#668) and the mobile caret drag-handle (#999). **Remaining is verification, not code**: on-device / on-GPU interactive passes via `hack/richentryprobe` (#667/#674) — the epic is otherwise covered by unit tests + software-rendered masters.

### Completion Popup Widget
`widget.CompletionPopup` and `widget.NewCompletionPopup(canvas, items)` — a lightweight, **application-driven** completion/suggestion popup. The host app supplies `[]CompletionItem{Text, Detail, Icon}` (autocomplete, history, snippets, language-server completions) and the popup renders them anchored at a caret rectangle via `ShowAtCaret(rect)`. **This is distinct from the platform IME candidate window**, which the OS owns and positions itself (desktop GLFW only delivers the preedit string, never candidate words) — `CompletionPopup` complements it for app-level suggestions, it does not replace it. Styled deliberately not to compete with the app: **no shadow**, subtle `SizeNameShapeExtraSmall` corners, thin `OutlineVariant` border over a `SurfaceContainer` fill. Each row shows its text with an optional **trailing info icon** (shown when `Detail` is set), which **mirrors to the leading edge under RTL**; optional leading kind-icon per item; optional bold **title** header (`SetTitle`). Placement is **below the caret, flipping above when cramped**, so it never covers the line being edited. Keyboard (↑/↓/Enter/Tab/Esc), hover and tap select; `OnSelected func(index, item)` fires on accept. The active row's `Detail` is revealed in a small inverted tooltip after a short delay, anchored at its info icon, on both hover and keyboard selection (#362). **Documentation side-panel (#435):** `CompletionItem.Documentation` (+ `DocumentationMarkdown`) — when any item carries documentation, a scrollable `RichText` panel (width 320, clamped to half the canvas) appears beside the list on the trailing side (leading under RTL, `OutlineVariant` divider), follows the selection on both keyboard and hover (`refreshDoc`, re-rendered only when the selected index changes), scrolls back to top per item, and `PageUp`/`PageDown` page it while the list keeps focus (consumed only when the panel is visible — otherwise still forwarded to the host Entry). The panel **subsumes the `Detail` tooltip** (suppressed while any item has docs); `rowAt` is x-aware so panel taps/hovers don't select rows. **Companion anchoring (#437):** `Position()`/`Size()` are the final post-flip/post-clamp canvas rectangle, and `OnMoved func(geo.Rectangle)` reports it (deduped) on show, live `SetItems` resize and every placement change while shown; on hide it fires once with the **zero rectangle** so a host-owned companion (e.g. a signature-help card) dismisses even on Escape/outside-tap. Reports are gated by an internal `shown` flag — a fresh `BaseWidget` claims `Visible()` before its first `Show`, which would otherwise leak `ShowAtCaret`'s pre-placement `Resize`. **Bounded height (#436):** `MaxVisibleRows` (0 → default 8) caps how many rows are visible; longer lists scroll behind the window (flat-renderer windowing via a `top` first-visible-row offset — no `container.Scroll`): Up/Down keep the selection in view (incl. wrap-around), the wheel/trackpad scrolls via `Scrolled` (sub-row deltas banked in `scrollAccum`), a thin `ColorNameScrollBar` indicator strip tracks the position (trailing edge, mirrors under RTL), and `rowAt`/`infoIconRect`/`layoutSelection` are all window-offset-aware (an off-window selected row simply hides its highlight; the detail tooltip is dropped when its row scrolls away). `MinSize` reports the capped height, so `ShowAtCaret`'s below/above flip accounts for it automatically. `Entry` integration: `Entry.ShowCompletion(title, items)` / `HideCompletion()` (anchored via the caret rect from `Entry.PreeditCursorRectangle()`) with an `Entry.OnCompletionSelected func(CompletionItem)` callback. **Live filtering (#361):** because bellui routes keyboard to the top overlay, the popup is the focused overlay while open but **forwards typed runes and editing keys back to the host `Entry`** (handling only ↑/↓/Enter/Tab/Esc itself), so the user keeps typing into the Entry — driving its `OnChanged` to re-filter and re-`ShowCompletion` — while the caret stays put. (#130-adjacent.) **Host-driven mode (#442/#472):** `KeepHostFocus` (set before `Show`) replaces the forwarding model for editor hosts (fycoder): keyboard focus never moves — the popup's `OverlayContainer` is `FocusTransparent` (the canvas keeps routing keys/runes/shortcuts to the focused host as if the popup weren't open) and the host offers navigation keys via `HandleKey(*event.KeyEvent) bool` (arrows/Enter/Tab/Escape → consumed). The overlay is also `TapThrough` (#472): the desktop driver dismisses it at *press* time when a click lands outside the popup content and lets the same click re-resolve against the layer beneath (`window.dismissTapThroughOverlay`), so one click both closes the popup and places the caret in the editor; default overlays still swallow the outside tap.

### Slider — Media-Scrubber Seams (#44)
`widget.Slider` conflated *who* changed the value with *that* it changed, which a settings control never notices but a media scrubber cannot work around cleanly. Three additions, all backwards compatible:
- **`Dragging() bool`** — authoritative drag state, so a player can suppress its periodic position updates while the user scrubs (otherwise the thumb snaps back under the pointer every tick). Inferring it from `OnChanged`/`OnChangeEnded` has a real hole: `DragEnd` → `fireChangeEnded` returns early unless `pendingChange`, which `positionChanged` only sets past an `almostEqual` check — so **a press-and-release that doesn't move the value past one `Step` fires neither callback**, latching an inferring consumer on forever. `dragging` is therefore cleared in `DragEnd` *unconditionally and before* the callback.
- **`SetValueSilently(v)`** — programmatic updates that don't look like user interaction. `SetValue` deliberately still fires both callbacks: the arrow keys (`TypedKey`) and the screen-reader increment/decrement (`PerformAccessibleAction`) route through it, so making it silent would have quietly broken keyboard and a11y notification. A silent set does **not** propagate to bound data (the write-back rides the same change notification the callbacks do) — documented on the method; use `SetValue` for a bound slider.
- **`OnHover func(float64)` / `OnHoverEnd func()`** — `HoverMoved` used to discard its event entirely. The reported value is **continuous, not snapped to `Step`** (a scrub preview wants the true pointer position; rounding is recoverable, un-rounding isn't). `OnHoverEnd` fires **even when disabled mid-hover**, so a consumer is never left showing a preview it can't take down.

**`Bind` no longer claims `OnChanged` (#47).** It used to implement the data write-back by *assigning the public `OnChanged` field*, so binding and an app handler silently destroyed each other in both directions — and `NewSliderWithData` made the likelier direction (assign `OnChanged` after the constructor bound for you) completely unsignalled. The write-back now rides an unexported `onChangedInternal` hook invoked from `positionChanged` **before** `OnChanged` (so a handler reading the bound source never sees a stale value), and `Unbind` clears only that hook rather than nilling the app's field. `Check`/`Select` (`OnChanged`) and `Entry` (`Validator`) still have the same pattern — **#49**.

**`widget.RangeSlider` parity (#46)** — the same seams, deliberately reading the same way as `Slider`:
- `Dragging() bool` (cleared unconditionally in `DragEnd`, same hole) plus `DraggingHigh() bool`, since which thumb is being dragged was already tracked internally and a trim control needs it.
- `OnChangeEnded func(low, high float64)` — there was no commit signal at all. Fires from `DragEnd`, `Tapped`, a screen-reader `adjustThumb` and `SetValues`, gated on a `pendingChange` flag exactly like `Slider`.
- `OnChanged` is now **gated on a thumb actually moving** — it used to fire on every `Dragged`/`Tapped` regardless. This is what makes the `Dragging()` hole above real on `RangeSlider` too, and what makes `OnChangeEnded` meaningful.
- **`SetValues` now fires** `OnChanged` + `OnChangeEnded`, with `SetValuesSilently` as the quiet counterpart — resolving the #46 complaint that the two widgets had *opposite* programmatic-set rules. The plain setter reports, the `*Silently` one doesn't; that is now the fork-wide convention for both. `SetValues` also snaps to `Step` via the shared `clamp` (it previously only clamped to `Min`/`Max`), so a reported programmatic value lands in the same value space a drag produces.
- `OnHover func(float64)` / `OnHoverEnd func()` — continuous, clamped to `[Min, Max]` (`RangeSlider.getRatio`, unlike `Slider`'s, doesn't clamp; the drag path launders it through `clamp` but hover reporting can't).

**`RangeSlider` disabled state + keyboard (#51)** — the parity sweep for #46 found `RangeSlider` was drag/tap/hover only: it could not be disabled at all (no field, no methods, no guards, no disabled colours) and **could not be operated from the keyboard at all** (not `Focusable`, no `TypedKey`), which is an accessibility floor rather than a nicety — #810's thumb proxies already gave screen-reader users working increment/decrement, so it was sighted keyboard-only users who had no path.
- `Disable()`/`Enable()`/`Disabled()` with guards on `Dragged`, `DragEnd`, `Tapped`, `TypedKey`, `HoverIn`/`HoverMoved` and `adjustThumb` (the one funnel both the keyboard and the screen-reader actions go through, so guarding it covers both). `OnHoverEnd` **does** fire when disabled mid-hover, same rule as `Slider`. The renderer paints thumbs + active track in `ColorNameDisabled` and hides the focus/hover ring.
- **Focusable, one tab stop.** The arrows along the slider's own axis (Left/Right horizontal, Up/Down vertical) move the **focused thumb**; the **cross-axis** arrows switch which thumb that is. That is the decision #51 left open: `Tab` must keep moving focus *out* of the widget and `Home`/`End` are reserved for a future jump-to-extreme, so the cross-axis arrows are the only keys free to carry the switch — and they are otherwise dead on a single-axis control. `focusedHigh` also follows the thumb the pointer last dragged or tapped, so in practice the switch is rarely reached; `FocusedHigh()`/`SetFocusedHigh()` expose it. The step is `Step` when set, falling back to `a11yStep()` (a hundredth of the range), so unlike `Slider` — whose arrows are dead when `Step` is unset — the keys always do something.
- A11y: the **thumb proxies** report `StateDisabled` via their own `AccessibleState()`, because they are not themselves `core.Disableable` and so cannot inherit the bit structurally the way the `RangeSlider` group node does under #52. The proxies are what a screen reader presents as adjustable, so that is where the state has to land.

### Bind Never Claims a Public Callback Field (#47, #49)
Several `Bind` implementations used to install the data write-back by **assigning a public callback field**, so binding and an app handler silently destroyed each other in both directions — and the `*WithData` constructors made the likelier direction (assign the field after the constructor bound for you) completely unsignalled. Fixed fork-wide in `Slider` (#47) and `Check`/`Select`/`Entry` (#49); the rule is now a convention: **a binder gets its own unexported hook, and `Unbind` clears only that hook** rather than nilling a field the app may own.
- `Check`/`Select` — unexported `onChangedInternal`, invoked from `SetChecked`/`updateSelected` **before** the public `OnChanged` (so a handler reading the bound source never sees a stale value). `Unbind` clears only `onChangedInternal`. `Slider` is the same shape via `positionChanged`.
- `Entry` — the write-back was never on `Validator`; what `Bind` claimed was the **conversion-error report**, which is worse than the `OnChanged` cases because validation is a correctness feature: binding a validated Entry silently dropped the app's rule and `Unbind` left the widget with none. Now an unexported `validatorInternal` is **composed** with the public `Validator` by `Entry.runValidator`, with `Entry.hasValidator()` the "is this entry validated" predicate every call site uses (`Validate`, `validate`, `SetValidationError`, the renderer's icon-space reservation and border styling, `Form`). **Composition rule: a conversion error wins** — text that cannot be written to the bound source is invalid whatever the app's rule says. This also fixes the constructor-installed validators of `NumericEntry`, `SearchField`, `DateEntry` and `DateTimeEntry`, which used to be destroyed the moment the widget was bound.
- Fixed alongside in `Select` (#49): `SetSelected` has no equality guard of its own (unlike `Check.SetChecked`, whose guard is why it never showed), so the write-back's own binding notification re-entered `updateFromData` and reported **one change twice** — invisible while `Bind` owned `OnChanged`, user-visible the moment an app handler could survive. `updateFromData` now returns early when the incoming value already matches `Selected`.

`Label.Bind` and `ProgressBar.Bind` install no callback at all and were always clean.

### Streaming Rasters — Video Frame Upload (#34)
`canvas.Raster.Streaming` + `SetPixels(pix, w, h)` is the video-playback path: the painter keeps the raster's GPU texture alive across frames (`internal/driver/common.Canvas.freeObject` deliberately skips streaming rasters) and re-uploads only the pixels. It used to be **GL-only**, which on the default WebGPU desktop build meant a nil-`Generator` raster — the documented SetPixels-only usage — **segfaulted on first paint**, and supplying a `Generator` to dodge that left the image **frozen on frame 1** (the texture was cached forever). Both are fixed:
- **`Raster.PixelImage(w, h) image.Image`** (`canvas/raster.go`) is the single pixel source every painter reads: SetPixels data when present (copied, so a caller may reuse its frame buffer), else `Generator`, else **nil** — so a raster with neither is skipped rather than dereferenced. The GL (`newGlRasterTexture`), WebGPU (`rasterizeRaster`) and software (`drawRaster`) paths all route through it; a nil return means "no content this frame".
- **WebGPU honours streaming**: `Device.WriteTexturePixels` is the `TexSubImage2D` counterpart (`queue.WriteTexture`), `Texture` now carries its allocated `w,h` (`Texture.Size()`) so a same-size frame updates **in place** and a size change drops the texture (`dropTexture` → `ReleaseTextureAfterFrame`, so draws already recorded this frame stay valid) for `getTexture` to reallocate. `painter.drawRaster` calls `updateStreamingTexture` before drawing, mirroring the GL painter. SetPixels data uploads **without a copy**, under `StreamMu`; the Generator path rasterizes outside the lock.
- GL fix alongside: `newGlRasterTexture` recorded `StreamTexW/H` from the *widget's* size, so a video whose frame size differed from the widget ping-ponged between delete and recreate and never updated in place. It now records the dimensions actually uploaded.
- **`Translucency` now applies to rasters on every painter (#38)**: the GL painter always passed `Raster.Alpha()`, but the WebGPU *and* software painters passed a hard-coded opaque `1.0`, so `Raster.Translucency` silently did nothing on the default desktop build and in every software-rendered test. Both now pass `Alpha()`, matching `canvas.Image`.
- **Verify**: `hack/rasterstream` (`-auto` captures the canvas twice and reports per-raster changed-pixel counts — 0 = frozen — then compares an opaque square against a `Translucency: 0.5` one). Confirmed on-GPU under both painters, and confirmed to reproduce the original segfault, the freeze and the ignored translucency when the fixes are stashed.

### Rendering Engine Enhancements
- **Shader-based ripple** (`canvas.Ripple`) — radial touch feedback with SDF-based rounded-corner clipping. Custom GLSL shader.
- **FBO support** — Framebuffer Objects for off-screen rendering. `CreateFramebuffer`, `BindFramebuffer`, etc.
- **Gaussian blur shadows** (`canvas.BoxShadow`) — 9-tap separable blur via FBO ping-pong. Replaces gradient-strip shadows for `ShadowAround`.
- **Backdrop blur** (`canvas.BackdropBlur`) — Frosted glass effect. Reads framebuffer pixels, blurs, composites. Opt-in, GPU readback is expensive.
- **Stencil clipping** — `StartRoundedClipping`/`StopRoundedClipping` on Painter. Auto-detected via `RoundedClipCornerRadius()` on renderers. Card content clips to rounded corners.
- **Container opacity** — `SetGroupOpacity`/`ClearGroupOpacity`. Disabled widgets render at 38% opacity automatically.
- **Multi-stop gradients** — `GradientStop` type with `Position` (0-1). `LinearGradient.Stops` and `RadialGradient.Stops` fields.
- **RepaintBoundary** (`container.RepaintBoundary`) — FBO-cached subtree isolation. Wrapping a subtree in `NewRepaintBoundary(content)` renders it into an off-screen framebuffer. When the subtree is unchanged, it blits the cached texture as a single quad instead of walking/drawing every object. Dirty propagation: `Refresh()` on any descendant marks only the nearest ancestor boundary's FBO as dirty. Supports GLFW and mobile drivers. Scale changes invalidate all boundary FBOs.
- **Dirty-region culling** — Persistent full-canvas FBO (`DirtyRegionPainter` interface on GL painter) retains frame content across double-buffer swaps. When widgets refresh, the dirty region (union of refreshed objects' bounds) is scissor-cleared and only overlapping objects get draw calls. Objects outside the dirty region are skipped entirely. Falls back to full repaint on resize, scale change, or overlay/content changes.
- **GPU-accelerated 3D** — `canvas.Scene3D` rendered via GL pipeline in the GL painter. Meshes expanded to interleaved VBOs (position + normal + per-face color, stride 10 floats). Dedicated `scene3d.vert`/`scene3d.frag` shaders with MVP transform and Phong-style ambient+diffuse lighting. Rendered to FBO with depth texture attachment for hardware z-buffering. FBO color texture cached via existing texture pipeline — only re-rendered on `Refresh()`. Software `Scene3D.Render()` path preserved for the software painter. `canvas.PerspectiveMatrix()` and `canvas.LookAtMatrix()` exported.

(remove func())` (#92): it calls `apply` with the current translation immediately and again on every locale change, e.g. `lang.BindText("Cancel", btn.SetText)` or `lang.BindText("My App", w.SetTitle)`; call the returned `remove` when the target is gone (long-lived UI may leave it for the app lifetime). - **Translation-catalog workflow** — keep the JSON catalog in sync with code via the fork's patched `bellui` CLI: `bellui translate translations/en.json ./...` recursively scans Go source, extracts message strings and merges *new* keys into the file (existing keys are left untouched unless `-u`; pass `-` as the filename to print to stdout). Then ship the JSON out for translation and register the result with `lang.AddTranslationsFS(fs, dir)` (or `AddTranslations(resource)`) at startup. The scanner recognizes both the classic `lang.L`/`Localize`, `N`/`LocalizePlural`, `X`/`LocalizeKey`, `XN`/`LocalizePluralKey` and — as of #503 — the fork's live-retranslation seams: `lang.BindText` and `binding.NewLocalizedString`/`NewLocalizedPlural` (key-only, key doubles as fallback like `L`/`N`) plus `binding.NewLocalizedStringWithKey`/`NewLocalizedPluralWithKey` (explicit key+fallback like `X`/`XN`); the plural forms land as `{"other": …}` objects. As of #505 it also recognizes the grammatical-select seams `lang.LSelect`/`LSelectPlural`: since the selector is usually a runtime variable, the scanner seeds the mandatory `<prefix>.other` variant (and any *literal* selector variant), never the bare prefix — so an existing key is never clobbered; `LSelectPlural` seeds a `{"other": …}` object. It matches the literal `lang`/`binding` receiver identifier (not the import path), so it works against the fork's module path unchanged. The `translate` command lives in the fork's patched `cmd/bellui` (in the `trendvidia/tools` repo — don't swap to raw upstream `fyne.io/tools`; see the bellui-CLI convention).
- **Locale-aware collation** (`lang/collate.go`, #504) — sort user-visible strings by the active locale's collation order instead of by Unicode code point (which mis-sorts most non-English text: German `äpfel` belongs with `a`, Swedish `ö` sorts after `z`). `lang.Compare(a, b string) int` is the one-call form for a sort closure (`sort.Slice(s, func(i, j int) bool { return lang.Compare(s[i], s[j]) < 0 })`); it is **goroutine-safe** (backed by a `sync.Pool` of collators keyed by the current tag, so it also stays in step with `lang.SetLocale` — no explicit invalidation needed) and is what `widget.FileTree.Sorter` should use for name ordering. `lang.CompareFold` is the case- and accent-insensitive companion for search/filter matching. For sorting a large slice, `lang.NewCollator(opts…) *Collator` returns a reusable collator (`Compare`, `SortStrings`) — captured at the active locale, **not** concurrent-safe (mirrors `x/text/collate`), rebuild on locale change; options are `CollateNumeric` (`file2` < `file10`), `CollateIgnoreCase`, `CollateIgnoreDiacritics`. Wraps `golang.org/x/text/collate` (already in the dep graph). **Binary size**: referencing collation links the collation tables (~1.75 MB); this is dead-code-eliminated in binaries that never call `Compare`/`CompareFold`/`NewCollator`, so `FileTree`'s default `Sorter` stays nil (collated ordering is opt-in — no forced cost).
- **Grammatical select / gender** (`lang/select.go`, #505) — the ICU MessageFormat `select` case (grammatical gender, formality) that CLDR plural rules can't express. The blessed pattern is **one catalog key per variant, suffixed with the selector, plus a mandatory `.other` variant**; no new dependency, translator-visible, composes with plurals as key suffixes. `lang.LSelect(keyPrefix, selector, data…)` looks up `keyPrefix+"."+selector`, falling back to `keyPrefix+".other"`, then to `keyPrefix` itself (`lookupMessage` probes the catalog by MessageID so it can chain — unlike `LocalizeKey` it doesn't substitute a literal for a miss). `lang.LSelectPlural(keyPrefix, selector, count, data…)` picks the variant then resolves plural forms *inside* it via `LocalizePluralKey`, so gender × plurality compose. Worked example (catalog `profile_updated.female/.male/.other`, both en+de in `translations/base.{en,de}.json`): `LSelect("profile_updated", gender, map[string]any{"Name": name})` → en `"Alex updated her/his/their profile"`, de `"Alex hat ihr/sein/ihr Profil aktualisiert"`. Both react to `lang.SetLocale` for free (routed through `X`/`LocalizeKey`). `bellui translate` seeds these keys (see the catalog-workflow bullet).
- **CLDR long-tail formatting** (`lang/list.go`, `lang/unit.go`, #506) — locale-correct formatting beyond dates/numbers/currency:
  - `lang.FormatList(items []string) string` — joins with the active locale's CLDR list pattern (the conjunction word, separators and Oxford comma are per-locale data, sourced from catalog keys `list.two/start/middle/end`): `["a","b","c"]` → en `"a, b, and c"`, de `"a, b und c"`, fr `"a, b et c"`, ja `"a、b、c"`, zh-Hans `"a、b和c"`. Handles 0/1/2/N; items are inserted verbatim (no templating). Never hand-assemble a list with a literal `", "` + `"and"`. **All 15 bundled locales** carry authoritative CLDR `list.*` keys (#860) — cs/fr patterns include the CLDR NBSP / narrow-NBSP verbatim.
  - `lang.FormatUnit(value float64, unit Unit) string` — a **scoped** unit set (length: `UnitMeter/Kilometer/Mile/Foot`; mass: `UnitGram/Kilogram/Pound`; extend on demand, not the full CLDR grid). Numeric part uses `FormatDecimal` (locale separators — de `"3,5 km"`), the label comes from catalog keys `unit.*` (all 15 locales, #860 — Cyrillic `км`, Greek `χλμ.`, Chinese `公里`, Tamil `கி.மீ.`, French narrow-NBSP). The label is **count-inflected via the locale's CLDR plural rules** (#862): each `unit.*` value is a plural message object (`{one,few,many,other}` with a `{{.Value}}` placeholder), and `FormatUnit` routes through the plural machinery (in-package `localizeUnit` → `localize`, since the exported `LocalizePluralKey` is `int`-only and would mis-categorize fractions) keyed on `pluralCount(value)`. So Polish `UnitMile` renders `1 mila` / `2 mile` / `5 mil`, Ukrainian `1 миля` / `2 милі` / `5 миль`. Every `unit.*` message carries exactly the plural categories the locale uses (missing CLDR forms filled from `other`), so an invariant abbreviation (pl `km`) never triggers a "no plural form" error.
  - `lang.PreferredLengthUnit()` reports the locale's road-distance unit (`UnitMile` for US/GB/LR/MM via `mileRegions`, `UnitKilometer` elsewhere). Prefer the convenience helpers `lang.FormatDistance(meters float64)` and `lang.FormatMass(grams float64)` (#861) which take a **base-SI magnitude**, pick the locale unit system *and convert*: metric gets m/g below the 1 km / 1 kg threshold and km/kg above; imperial gets ft/mi (below/above 1 mile) and lb. Converted magnitudes are rounded to two decimals. Use `FormatUnit` directly only when you already hold a value in a specific unit.
  - **Non-Gregorian calendars are an explicit non-goal** of `lang.FormatDate`/`widget.DatePicker` (#506): Go's stdlib has no calendar-system support and `DatePicker` assumes Gregorian month/era structure throughout. Buddhist/Japanese-era/Hijri/Hebrew/Persian calendars are declined-unless-demanded — revisit only with a concrete consumer + vetted dependency.

### Custom Default Theme & Render Style System
The fork replaces Bellui's default theme with `enhancedTheme` (`theme/enhanced.go`), which implements Material Design 3 (MD3) color system and typography:

**MD3 Color System**: Colors are generated dynamically from the primary color using HCT (Hue-Chroma-Tone) tonal palettes (`theme/hct.go`). The `CorePalettesFromPrimary()` function generates 6 palettes (Primary, Secondary, Tertiary, Error, Neutral, NeutralVariant) from the selected primary color. `MD3Scheme` (`theme/md3_scheme.go`) maps these palettes to ~30 named color roles with proper tone assignments for dark/light variants.

**New MD3 Color Roles** (in `theme/color.go`):
- Primary group: `ColorNamePrimaryContainer`, `ColorNameOnPrimaryContainer`
- Secondary group: `ColorNameSecondary`, `ColorNameOnSecondary`, `ColorNameSecondaryContainer`, `ColorNameOnSecondaryContainer`
- Tertiary group: `ColorNameTertiary`, `ColorNameOnTertiary`, `ColorNameTertiaryContainer`, `ColorNameOnTertiaryContainer`
- Error group: `ColorNameErrorContainer`, `ColorNameOnErrorContainer`
- Surface hierarchy: `ColorNameSurface`, `ColorNameSurfaceDim`, `ColorNameSurfaceBright`, `ColorNameSurfaceContainerLowest/Low/Medium/High/Highest`
- On-surface: `ColorNameOnSurface`, `ColorNameOnSurfaceVariant`
- Outline: `ColorNameOutline`, `ColorNameOutlineVariant`
- Inverse: `ColorNameInverseSurface`, `ColorNameInverseOnSurface`, `ColorNameInversePrimary`
- Utility: `ColorNameScrim`

Legacy Bellui color names (Background, Foreground, Button, etc.) are mapped to their MD3 equivalents automatically.

**MD3 Typography Scale** (15 tokens in `theme/size.go`):
- Display: `SizeNameDisplayLarge` (57), `DisplayMedium` (45), `DisplaySmall` (36)
- Headline: `SizeNameHeadlineLarge` (32), `HeadlineMedium` (28), `HeadlineSmall` (24)
- Title: `SizeNameTitleLarge` (22), `TitleMedium` (16), `TitleSmall` (14)
- Body: `SizeNameBodyLarge` (16), `BodyMedium` (14), `BodySmall` (12)
- Label: `SizeNameLabelLarge` (14), `LabelMedium` (12), `LabelSmall` (11)

Pre-built `TextStyle` presets in `theme/typography.go` bundle weight, line-height scale, and letter spacing per MD3 spec (e.g., `TypographyBodyMedium`, `TypographyTitleMedium`).

**Render Style Selection**: Themes can implement the typed `internal/theme.RenderStyleTheme` interface (`RenderStyle() RenderStyle`) to select a visual style; a separate `internal/theme.MobileTheme` (`DeviceIsMobile() bool`) overrides the form factor. These replaced the old type-erased `FeatureTheme.Feature(name) any` lookup (#39), following the codebase's optional-interface pattern (`CloudApp`, `MasterWindow`, etc.) so callers no longer assert at runtime. Widget renderers check `internaltheme.RenderStyleForWidget(w)` and adjust visuals:
- `RenderStyleClassic` (default for themes without `RenderStyleTheme`) — original Bellui look
- `RenderStyleModern` — gradient button backgrounds, card background fills, deeper shadows

`DarkTheme()`/`LightTheme()` still return the original `builtinTheme` for backward compatibility. Only `DefaultTheme()` returns the `enhancedTheme`.

### Native / Portal File Dialogs (#514)
`dialog.UseNativeFileDialogs(bool)` — opt-in (default **off**) global that swaps the canvas-drawn `FileOpen`/`FileSave`/`FolderOpen` for the platform-native picker, behind the **existing** `fileOpenOSOverride`/`fileSaveOSOverride` seam (`file.go:782/786/970/987`, `folder.go:35`; an override returning `true` skips the canvas UI, `false` falls back to it — that *is* the "never lose the feature" guarantee). Same `dialog.File*` API, same `bellui.URIReadCloser`/`URIWriteCloser`/`ListableURI` results, so app code is unchanged. The native call runs in a goroutine and marshals the result back with `bellui.Do` (copy the async idiom in `file_xdg_portal.go`).
- **Linux/BSD (Phase 1, done)** — `org.freedesktop.portal.FileChooser` over D-Bus via `github.com/rymdport/portal` (BSD-3, already a dep); works both sandboxed (**the only correct path under Flatpak/Snap** — the in-canvas dialog browses an empty sandbox) and unsandboxed (the portal falls through to the desktop's own GTK/Qt dialog). `file_xdg_portal.go` (tag `(linux||openbsd||freebsd||netbsd) && !android && !wasm && !js && !tamago && !noos`) is the generalization of what used to be the `-tags flatpak`-only path. A cached D-Bus `NameHasOwner("org.freedesktop.portal.Desktop")` probe (`portalReady`) gates it: **no portal on the bus → override returns `false` → canvas fallback**. **Flatpak builds always use the portal regardless of the toggle** (`build.IsFlatpak` forces `nativeFileDialogsEnabled()` true; the probe is skipped since the sandbox always provides one). X11 window parenting via `RunNative`→`X11WindowContext`; Wayland parenting (`xdg_foreign`) is a TODO (unparented for now).
- **macOS (Phase 2, done)** — NSOpenPanel/NSSavePanel via an MRC ObjC cgo bridge (`file_darwin_native.{go,m,h}`): sheet-modal over the parent `NSWindow` (`RunNative`→`MacWindowContext`), `//export`ed completion handler wraps the path and fires the typed callback via `bellui.Do`; `UTType` filters (ext + MIME on macOS 11+).
- **Windows (Phase 3, done)** — the modern Common Item Dialog (`IFileOpenDialog`/`IFileSaveDialog`) driven **purely through `x/sys/windows` COM syscalls, no cgo** (`file_windows_native.go`). CLSID/IID `windows.GUID` literals + hand-written vtable slot offsets (IUnknown→IModalWindow→IFileDialog; both dialogs share the `IFileDialog` base so `GetResult` covers single-select open + save); `ole32.dll` `CoCreateInstance`/`CoTaskMemFree` + `shell32.dll` `SHCreateItemFromParsingName` (for `SetFolder`). Runs on a dedicated `runtime.LockOSThread`'d goroutine (never unlocked → the STA COM apartment lives and dies with the goroutine; `Show` pumps its own modal loop) with `CoInitializeEx(APARTMENTTHREADED)` (skips the balancing `CoUninitialize` only on `RPC_E_CHANGED_MODE`); result marshalled back via `bellui.Do`, mirroring portal/macOS. Parent `HWND` best-effort via `RunNative`→`WindowsWindowContext.HWND` (0/unparented is fine — Show blocks either way; cross-thread owner isn't auto-disabled, acceptable for v1). Filters → `COMDLG_FILTERSPEC` (`*.ext;…`); MIME filters have no native Windows concept so they're best-effort mapped via `mime.ExtensionsByType` (unmappable → all files). **cgo-free pointer hygiene**: the `comCall` helper stashes args in a `[]uintptr`, which forfeits the `//go:uintptrescapes` liveness guarantee (that only holds for `syscall.SyscallN`/`LazyProc.Call` with the conversion *in* the call expression, as the direct `Show`/`GetResult`/`CoCreateInstance`/`SHCreate…` calls use) — Go's GC is non-moving so addresses stay valid, but every Go pointer handed through `comCall` is pinned in a `pins []any` kept alive to end of function.
- **Canvas-only caveats**: `SetShowHidden` and multi-selection are not expressible on the native surfaces (and the `FileDialog` callback returns a single URI) — documented as canvas-dialog-only. Mobile/wasm keep their existing paths (`file_mobile.go` native pickers; `file_wasm.go` — the web target uses a browser `<input type=file>` for open and a Blob download-on-`Close()` for save (#625), always on (the toggle is desktop-only); directory-open falls back to the canvas dialog).

### System Tray — Linux delivery caveat (#512)
System tray (`desktop.App.SetSystemTray*`) is delivered via **StatusNotifierItem over D-Bus** on Linux/BSD (native status items on macOS/Windows). An SNI item only appears where the desktop environment runs an **SNI host**: KDE Plasma and most Wayland compositors do; **stock GNOME shows nothing** unless the user installs the AppIndicator (KStatusNotifierItem) shell extension, and legacy **XEmbed-only** trays (some minimal WMs) are unsupported by `github.com/belluikit/systray`. This is a desktop-environment property, not a bellui bug (every non-GTK toolkit shares it). **Design rule: never make the tray the only path to a feature** — always keep a window/menu route (the "Show Window" menu-item advice). Doc'd on the `desktop.App` interface.

### Desktop Integration — Explicit Non-Goals (#520)
Two capabilities were reviewed during the desktop-integration gap review (multi-window #497–#499, i18n #503–#506, share/intents #508–#510, tray #511–#512, clipboard #513, native dialogs #514, DnD #515, notifications #516, polish #517, hotkeys #518) and **deliberately not pursued**, recorded here so they stop being re-litigated:
- **Printing — non-goal.** A toolkit print pipeline (pagination, print dialogs, printer enumeration, canvas→PDF) is an enormous, permanently-unfinished surface; no comparable Go toolkit ships one. **Workaround pattern**: render to an image (`software.Render` / canvas capture) or generate a PDF with a dedicated Apache/BSD/MIT library, then hand it to the OS with `bellui.OpenURL(file://…)` — the platform viewer supplies its own print UI. *Revisit trigger*: a concrete consumer whose in-app print flow the PDF handoff can't serve.
- **Session-end veto (logout/shutdown unsaved-changes prompt) — decline-unless-demanded.** `SetCloseIntercept` covers window close but not OS session end. Per-platform vetoes exist (macOS `NSApplicationDelegate` termination reply, Windows `WM_QUERYENDSESSION` + `ShutdownBlockReasonCreate`, Linux session-manager inhibitors) but modern OSes increasingly ignore or time-box them, and half-working veto UX is worse than none. **Durable answer**: crash-safe continuous state save (autosave/journal), so an un-vetoed session end loses nothing. *Revisit trigger*: a concrete, well-scoped demand.

### Runtime Wayland/X11 Selection (#542)
Linux display-server selection is a **runtime** decision, not a build-time one — a single default binary runs correctly on both X11 and Wayland sessions (matching upstream v2.8.0, ports `147177dcb` + the CSD heuristic `4a52a9fe8`). The old `-tags wayland` split (one X11-only binary, one Wayland-only) is gone from the default path.
- **Both backends in one binary**: the fork's `belluikit/glfw` (>= v1.2.0) compiles both C backends by default *and* exposes both Go native-accessor sets (`GetX11Window/Display` + `GetWaylandWindow/Display`) in the default build — the v1.2.0 change that unblocked this (upstream bellui is GL-default and never needs the native surface handle; our WebGPU-default painter does, so both must be linkable). GLFW auto-selects at init.
- **`build.IsWayland` is now a runtime `var`** (`internal/build`), not a compile-time const: `false` in the default/`x11` build, set `true` in `loop_desktop.go`'s `initGLFW` when `glfw.GetPlatform() == PlatformWayland`. The ~11 existing `IsWayland` branches (positioning, content-scaling) plus the native-handle dispatch (`window_x11wayland.go` `RunNative`, `backend_webgpu_x11wayland.go` surface descriptor) key off it, so they are correct per-session. A forced single-backend build hard-codes the right value.
- **`BELLUI_PLATFORM=x11|wayland`** pins the choice via `glfw.InitHint(glfw.PlatformHint, …)` before `glfw.Init()` (`forcePlatform`, adopting upstream's env var name/values verbatim); any other value is ignored.
- **CSD heuristic** (`wayland_csd_linux.go`): on a Wayland session that *also* has XWayland (`DISPLAY` set), prefer X11 when the compositor does not advertise `zxdg_decoration_manager_v1` (no server-side decorations — e.g. GNOME/Mutter), avoiding GLFW's client-side titlebar. Probed with a one-shot `wayland-client` registry roundtrip; adds a `pkg-config: wayland-client` build dep to the default linux driver build. `BELLUI_PLATFORM` overrides it. `wayland_csd_other.go` is the no-op stub for non-runtime builds.
- **Forced builds** stay available: `-tags wayland` (Wayland-only) and `-tags x11` (X11-only) each drop the other backend for a lean binary; their dedicated `window_{wayland,x11}.go` / `backend_webgpu_{wayland,x11}.go` files have narrowed tags so they don't overlap the runtime `*_x11wayland.go` files. Live in-place toggling isn't supported (chosen once at init, like the global `SetLayoutDirection`). BSD stays X11-default (its Wayland accessors remain tag-gated in the glfw fork). Verified end-to-end on GNOME/Wayland+Mutter (auto→X11 via CSD, `BELLUI_PLATFORM` both ways) plus all four build modes compiling on arm64 linux.

### Window Positioning & Screens (#497)
Desktop windows can be placed programmatically (upstream deliberately omits this; upstream 2.8 later added the request half, which we match). All types live in `driver/desktop`:
- `desktop.Window` — **upstream 2.8's interface verbatim** (same names/semantics so upstream fixes cherry-pick cleanly): `RequestPosition(x, y int)` (loose native-coordinate contract — "may be scaled", may span monitors; ignored on Wayland), `RequestAlwaysOnTop()` (call before `Show`; WM may ignore), `RequestFullScreenSecondary()` (fullscreen on a non-primary monitor; primary when there is only one).
- `desktop.PositionableWindow` — fork extension embedding `desktop.Window`: `Position() (x, y int)` read-back (last windowed position — unchanged while fullscreen; zero before first placement and on Wayland) and `SetOnMoved(func(x, y int))` (main goroutine; fullscreen re-seats not reported). Coordinates round-trip through `RequestPosition` verbatim, so save/restore of window geometry needs no unit conversion.
- `desktop.Driver.HasSecondaryDisplay() bool` (upstream 2.8 parity, mirroring-aware) and `desktop.ScreensDriver` — `Screens() []ScreenInfo{Name, Bounds, WorkArea, Scale, Primary}` (`ScreenArea` rects in the same native coords; `Scale` = bellui's detected per-monitor scale; call on the main goroutine). Enough for placement logic — deliberately not a display-configuration API.
- Mobile and wasm windows/drivers do **not** implement the window interfaces (assertion fails — never a silent no-op); the wasm driver reports `HasSecondaryDisplay() == false` because it claims `desktop.Driver` for #460.
- Ported with the interface: upstream's macOS 26 fix seating new windows on the same monitor as a visible sibling when no position was requested (`findSiblingMonitor`), and the fullscreen-target re-seat in `window_darwin.m`.

### Window-Hosted Dialogs (#498, Phase 1)
`Dialog.SetWindowHosted(hosted bool)` (default off; call before `Show`) opens any shared-`*dialog` dialog (information/error, confirm, custom, form, entry, progress, color picker) in its **own native `bellui.Window`** instead of an overlay popup inside the parent canvas — so it can be moved/resized by the OS window manager and appears in the window switcher, and long content is no longer clamped to the parent window. Modality is **window-modal and pure Go**: while open, a `modalScrim` overlay (`dialog/windowhost.go`) blocks the parent canvas (tapping it re-focuses the dialog window, matching window-modal convention); other app windows stay interactive. Native close (the window's close button → `SetCloseIntercept`) and the Escape key both route to `Dismiss()`, reporting a `false` response exactly once. The window is centered over the parent using #497 (`desktop.PositionableWindow.Position()` + `RequestPosition`, scaled via `internal/scale`); parents without the positioning interface are left to the WM. **Mechanism**: `base.go`'s show/hide/refresh/resize seams (`showHostWindow`/`hideHost`/`refreshHost`, `hostWindowClosed`) branch on `d.hostWin`; the shared `d.body` container is re-parented into the window (`SetContent`), and `refreshHost` refreshes the body directly rather than the hidden popup (whose renderer would re-lay-out the body to popup size). A rebuild-while-shown (ColorPicker `updateUI`) re-seats the fresh body. Gated by `windowHostSupported` (const, build-tagged): single-window platforms (mobile/wasm/tamago) ignore the mode and fall back to the overlay. **`FileDialog` parity (#597)**: `FileDialog`/`fileDialog` are separate types with their own show/hide plumbing (the `fileDialog.win` popup, direct `win.Show()/Hide()`, popups anchored to `win.Canvas`), so they get their own host-aware seams in `dialog/file_windowhost.go` (`hosted`/`showHostWindow`/`hostWindowClosed`/`hide`/`show`/`refresh`/`resize`/`minSize`/`canvas`/`dialogParent`) mirroring `base.go`'s — `showFile` branches on `hosted()` to either wrap the modal popup or seat the UI (`d.body`) in a host window; the options-menu popup anchors at `d.canvas()`; and nested dialogs (New Folder form, Overwrite confirm, errors) open over `d.dialogParent()` (the host window when hosted) so they appear above the dialog, not behind the scrim on the blocked parent. The scrim setup is shared via free `addScrim`/`removeScrim` helpers in `windowhost.go`. `FolderOpen` inherits it (it's a `FileDialog`). **Phase 2 — native parent/owner relationship (#598)**: `driver/desktop.ChildWindow` (a `Window` extension: `SetParent(bellui.Window)`, optional-interface / asserted / no-op where unsupported, call before Show) gives the host window a true WM owner relationship *on top of* the Phase-1 scrim — the dialog stays above its parent, minimizes/restores with it, and is treated as owned. The glfw window stores a `parent` field; `applyParent` establishes the native relationship on the main goroutine from `Show` (after the window maps — robust for Wayland's deferred toplevel and WMs that restack on a late hint). Per-platform `doSetParentNative`: macOS `[parent addChildWindow:child ordered:NSWindowAbove]` (`window_darwin.m`); Windows `SetWindowLongPtr(child, GWLP_HWNDPARENT, parent)` (x/sys, no cgo, `window_windows.go`); X11 `XSetTransientForHint` and Wayland `xdg_toplevel.set_parent` **via the glfw fork** (`(*glfw.Window).SetX11Parent`/`SetWaylandParent`, added in **belluikit/glfw v1.3.0** — GLFW keeps the X11 `Window`/Wayland `xdg_toplevel` internal so bellui can't reach them; the bellui side is the 3-file `window_{x11,wayland,x11wayland}.go` split mirroring `RunNative`/WebGPU, runtime-dispatched on `build.IsWayland`). Window-hosted dialogs adopt the parent before Show via `adoptParentWindow` (shared `windowhost.go` + `file_windowhost.go`). No-op on mobile/web (wasm window has a no-op `applyParent`). Verified: macOS addChildWindow (integration test `TestWindow_SetParent`), X11 `WM_TRANSIENT_FOR` == parent (xprop), Windows `GW_OWNER` == parent HWND, Wayland `set_parent` executes clean. **Phase 3 — native OS-modality (#498)**: `driver/desktop.ModalWindow` (extends `ChildWindow` with `SetModal(bool)`, optional-interface / asserted / no-op where unsupported, call after `SetParent`) makes the window manager block input to the *parent* window while the dialog is up (title bar greyed, keyboard can't reach it) — the OS-enforced counterpart to the pure-Go scrim, which stays as the universal fallback and coexists. Plumbing mirrors the Phase-2 `SetParent`/`applyParent`/`doSetParentNative` seam: a `modal` field + `SetModal`/`applyModal` on the glfw window, applied at `Show` right after the parent relationship, and **`releaseModal` in the shared `destroyWindow`** (the single teardown funnel) re-enables a natively-disabled parent before the child is torn down — critical so a disabled Windows parent is never left orphaned when the child closes via any path (dialog dismiss, native close button, raw API). Per-platform `doSetModalNative`: **Windows** `EnableWindow(parent, FALSE/TRUE)` (x/sys, no cgo, `window_windows.go`) — clean owned-modal, re-enabled on close; **X11** `_NET_WM_STATE_MODAL` toggle via the glfw fork (`(*glfw.Window).SetX11Modal`, added in **belluikit/glfw v1.4.0**, mirroring `_glfwSetWindowFloatingX11`'s `_NET_WM_STATE` client-message/property pattern; needs the `WM_TRANSIENT_FOR` owner from Phase 2), runtime-dispatched on `build.IsWayland` in `window_x11wayland.go`; **macOS** parent-key suppression (#676) — macOS has no window-modal primitive for a *free-floating* window (a sheet isn't free-floating; an NSApp modal session is app-modal, blocking every window), so instead of native modality the parent `NSWindow` is prevented from becoming key/main while the dialog is up: `setWindowModalBlocked` (`window_darwin.m`) per-instance **ISA-swizzles** the parent to a dynamically-created subclass overriding `canBecomeKeyWindow`/`canBecomeMainWindow`→`NO` (original class stashed in an associated object, restored on unblock/teardown), so the keyboard can't reach the parent and its title bar greys inactive; `addChildWindow` ordering + scrim cover stacking and mouse. Verified by `glfw.TestWindow_ModalBlocksParentKey` via the `isWindowModalBlocked` introspection helper; **Wayland** `xdg_dialog_v1.set_modal` via the glfw fork (`(*glfw.Window).SetWaylandModal`, added in **belluikit/glfw v1.5.0** — vendors the `xdg-dialog-v1` protocol, binds the `xdg_wm_dialog_v1` global, attaches a per-toplevel `xdg_dialog_v1`; compositors that don't advertise the protocol leave the scrim as the only blocker), runtime-dispatched on `build.IsWayland` in `window_x11wayland.go` (#678). The dialog layer enables it via `adoptModal` in `showHostWindow`, beside `adoptParentWindow`. No-op on mobile/web. The Windows/macOS block (a *single shared parent* state, unlike X11/Wayland's per-child protocol state) is **ref-counted per parent** (`blockParentModal` in `window_desktop.go`, `modalChildren`/`modalBlockApplied` fields): it toggles the native block only on the 0↔1 transition, so two window-hosted modals over one parent keep it blocked until the last clears (#682). Tests: `dialog.TestAdoptModal`, `glfw.TestWindow_SetModal`, `glfw.TestWindow_ModalRefCount`, `glfw.TestWindow_ModalStackedBlocksParentKey`.

### Multi-Window Semantics per Platform (#499)
`App.NewWindow` behaves differently per platform, now documented on the `bellui.App`/`bellui.Window` interfaces:
- **Desktop** (`internal/driver/glfw`, `GOOS != js`) — each window is a real, independent OS window (`gLDriver.createWindow`); any number shown concurrently.
- **Web/wasm** — the **first** visible window owns the single browser `<canvas>`; **additional** windows are emulated as draggable `container.InnerWindow`s inside a `container.NewMultipleWindows()` overlay (`glCanvas.webExtraWindows`) on the root canvas — concurrent, movable/closable, but not separate OS windows (glfw-js `CreateWindow` would append a second `<canvas>` to `body`, which bellui avoids by routing extra windows through `CreateWindow`'s `js` branch → `wrapInnerWindow`). Verified via a headed-Chrome probe: a 2nd `NewWindow().Show()` opens a floating in-canvas window with full chrome, single `<canvas>` in the DOM.
- **Mobile** (`internal/driver/mobile`) — a **stack**: only the topmost *visible* window shows (`driver.currentWindow()` scans back-to-front for the first visible; the event/paint loop always targets it). A window opened over a visible one is a **child** (`isChild`, gets a titlebar with a back/close button); closing/hiding it pops back to the previous. `Test_mobileDriver_MultiWindowStack` locks this in. (Note: `mobile window.Close()` removes itself from `bellui.CurrentApp().Driver()`'s list, not its own driver's — correct in a real app with one driver, but a bare test driver must use `Hide` to exercise pop-back.)

No behavior was degenerate (no panic/blank), so #499 was verify-and-document, not fix. True per-window OS canvases on web (one `<canvas>` each) is a deliberate **non-goal** (large, low demand).

### Single-Instance Mode (#509)
`bellui.SingleInstanceApp` — an **opt-in** optional interface (asserted from the `App`, like `CloudApp`/`NotifierApp`) that enforces one running process per app **UniqueID** and forwards a second launch's command-line arguments to the primary instead of opening a second copy. It is the desktop building block behind OS file-association / URL-scheme handling (#510), where "open with MyApp `<file>`" relaunches the binary with the target in argv.
- `SetSingleInstance(onOpen func(args []string)) (primary bool, err error)` — call **after `NewWithID`, before `Run`**. Returns `primary`; when `false` the args (`os.Args[1:]`) have already been forwarded to the running primary and the caller should exit (no driver/window exists yet → no window flash). `onOpen` fires on the **main goroutine** (via `bellui.Do`) with the forwarded args from each redirected launch — this is the seam #510 layers `OnFileOpened`/`OnURLOpened` onto. Idempotent; errors without a unique ID. Method lives in `app/single_instance.go` (shared: ID guard, main-goroutine dispatch, wire protocol `readArgs`/`writeArgs` = 4-byte length + JSON, 1 MiB cap); `Quit()` closes the endpoint via `a.siCloser`.
- **Unix transport** (`single_instance_unix.go`, linux/darwin/bsd, not android/ios/wasm): primary election via an **advisory `flock`** on a per-user lock file (`$XDG_RUNTIME_DIR`, else `os.TempDir()`, 0600, uid + fnv(id) in the name). flock is atomic (exactly one racer wins) and the kernel **releases it on process death**, so stale-lock recovery is free — no liveness probing. The Unix domain socket beside the lock is used **only for forwarding**; the elected primary removes any stale socket left by a crashed predecessor before binding. **Lesson**: an earlier socket-existence election was racy — `net.Listen` does `bind()` then `listen()` as separate syscalls, so a liveness probe landing in that window gets `ECONNREFUSED` and wrongly unlinks a *live* socket → two primaries (caught by `TestSingleInstance_RaceConvergence` only under `-tags ci`/no-race fast scheduling, not under `-race`). flock is the sound primitive.
- **Windows transport** (`single_instance_windows.go`): classic named **mutex** (`Local\` namespace, atomic create → creator is primary, `ERROR_ALREADY_EXISTS` → secondary) for detection + **named pipe** (go-winio, MIT — now a direct dep) for forwarding, DACL-restricted to the current user SID + SYSTEM + Administrators. Type-checks for windows/amd64 (pure-Go winio + `x/sys/windows`); **runtime verification on a real Windows session is the follow-up** (can't drive two processes over the session-0 SSH window-station — see #487 gotcha).
- **Other platforms** (`single_instance_other.go`, mobile/wasm/exotic): no-op that reports `primary=true`, callback never fires (inherently single-instance).
- **macOS note**: Launch Services normally activates the running instance and delivers `odoc`/`GetURL` Apple Events rather than relaunching, so forwarding is rarely exercised there — but the detection API behaves identically (uniform Unix impl).
- Live-verify: `hack/singleinstance` (`go run ./hack/singleinstance` = primary + window; a second `go run ./hack/singleinstance <args>` forwards and exits; primary logs to `$TMPDIR/bellui-si-probe.log`). Verified with a real **two-process** test on macOS (separate PIDs, args forwarded across the process boundary and delivered on the primary's main goroutine).

### Open-With Events — File/URL Launch & Deep Links (#510, Phase 1)
`bellui.OpenHandlerApp` — an **opt-in** optional interface (asserted from the `App`, like `SingleInstanceApp`) for the receive half of OS "open with" / file-association / custom-URL-scheme handling: `SetOnFileOpened(func(bellui.URI))` and `SetOnURLOpened(func(*url.URL))`. Both fire on the **main goroutine**; register before `Run`. A payload arrives either as the **launch reason** (buffered and delivered once the app is running) or **while already running**.
- **Delivery model** (`app/openevent.go`, shared): payloads buffer in `pendingOpens` until the app is `running` *and* a matching handler is set; `startOpenDelivery()` (called from `Run` before `driver.Run`) flips `running` and flushes; a late `SetOnXOpened` also flushes. Delivery hops to the main goroutine via `queueOnMain` = `go bellui.Do(fn)` — the `go` matters: `bellui.Do` from the main goroutine *before* the loop starts executes **synchronously** (loop.go's `!running && IsMainGoroutine()` shortcut), so a bare call would fire the launch callback too early; the goroutine forces it to enqueue and fire once the loop pumps.
- **Classifier** (`classifyOpenArg`): skips `-`/`--` flags; a real URL scheme (`http`, `mailto`, custom `myapp:`) → URL; `file://`, bare or absolute path → file. **Windows drive letters** (`C:\...` parses as scheme `"c"`) are guarded by `isWindowsDrivePath` and treated as files. Non-flag positional argv is treated as an open target, so an app that also has its own positional CLI args should be aware.
- **Platform delivery** (`platformLaunchOpen`, one per build via disjoint tags): **non-macOS desktop** (`openevent_desktop.go`) parses `os.Args[1:]`; **macOS** (`openevent_darwin.{go,m}`) registers `NSAppleEventManager` `kAEOpenDocuments` (odoc) + `kAEGetURL`/`kInternetEventClass` (GURL) handlers (the `'GURL'` FourCharCodes are `#define`d — not in the CoreServices umbrella header) **and** parses argv (harmless for a Finder launch, which carries none); **wasm** (`openevent_wasm.go`) reads `window.location`; **ci/mobile/other** (`openevent_other.go`) no-op.
- **Already-running desktop path composes with #509**: `SetSingleInstance`'s forwarding now routes through `onForwardedArgs`, which fans out to both the app's own single-instance callback *and* `dispatchOpenArgs`. So on Windows/Linux an app that enables single instance (which it does anyway to avoid a second copy) gets already-running "open with" **for free** — no hidden auto-enable (that would forward a secondary's argv without giving the app the `primary` bool it needs to exit). On **macOS** the already-running case is automatic via Apple Events (Launch Services re-activates the instance; the glfw event loop **does** pump Apple Events — verified).
- **Verified** end-to-end on macOS via `hack/openwith`: launch-file, launch-URL, two-process already-running forward (argv+socket), **AE odoc** (`open -a <bundle> <file>`) and **AE GURL** (`open myapp://…` against a Launch-Services-registered bundle) all deliver. Classifier unit-tested on every build; delivery tests gated to `-tags ci` (need the test driver's inline event queue; glfw needs a real `Run` loop). **Phase 1 does not** cover mobile (Android intents / iOS `openURL` — follow-up) or the `bellui` CLI packaging metadata (Info.plist `CFBundleDocumentTypes`/`URLTypes`, AndroidManifest intent filters, `.desktop` MimeType, Windows registry) that makes the OS *route* events to the app — **the API is inert without it** (tools-repo follow-up).

### Clipboard Flavors (#513, Phase 1)
The clipboard carries images, file lists and HTML beyond the text-only `bellui.Clipboard`. Three **optional capability interfaces** (clipboard.go) are asserted from `bellui.CurrentApp().Clipboard()` — on platforms/flavors without support the assertion fails (never a silent no-op):
- `bellui.ImageClipboard` — `Image() (image.Image, bool)` / `SetImage(image.Image)`
- `bellui.FileClipboard` — `Files() []bellui.URI` / `SetFiles([]bellui.URI)` (file-manager copy/paste interop; only `file`-scheme URIs are written, others skipped with a logged error)
- `bellui.HTMLClipboard` — `HTML() (string, bool)` / `SetHTML(html, plainFallback string)` — **always writes the plain flavor alongside** in one transaction (`Content()` reports the fallback afterwards)
- `bellui.MultiFlavorClipboard` (#583) — `SetFlavors(ClipboardContent)` writes **several flavors in one transaction** (e.g. a rendered chart as image + HTML data table + text fallback), which the single-flavor setters cannot express (each replaces the whole clipboard). `bellui.ClipboardContent{Text, HTML, Image, Files}`: zero-valued fields are omitted, a wholly zero value clears, `Content()` reports `Text` afterwards. Sugar: `bellui.SetClipboardFlavors(content) bool`. Per platform: Linux maps 1:1 onto the glfw fork's transaction-native `SetClipboardData`; macOS writes one `NSPasteboardItem` carrying text/HTML/PNG+TIFF plus one file-URL item per file via a single `writeObjects:` (a >1-item write sleeps 50 ms afterwards — item delivery to the pasteboard server is async and items beyond the first are lost if the process exits immediately; the SetFiles readback trick does not cover this); Windows one `Empty`+multiple-`SetClipboardData` transaction (`belluiWinClipboardSetFlavors`, composing the extracted `putClipboardText`/`buildDropFiles` helpers); wasm one ClipboardItem with text/html/png MIMEs — `Files` is skipped there with a logged error (no portable browser flavor, consistent with wasm not implementing `FileClipboard`); mobile (#1142) iOS = one pasteboard item published as an **`NSItemProvider`** with explicit fidelity order `public.html` → `public.png` → `public.utf8-plain-text` (a bare `UIPasteboard.items` dictionary carrying all three UTIs pastes **nothing** into Notes — any two paste fine; device-bisected #1144 — and provider-promised data is materialized by the pasteboard daemon, surviving writer exit), Android = one `ClipData.Item(text, htmlText, null, imageUri)` (a single item natively carries all three; PNG staged through BelluiFileProvider like #580, MIMEs listed in the `ClipDescription`; Java `doSetClipboardFlavors` — dex regen required) — `Files` skipped with a logged error on both. Test driver stores all flavors simultaneously (the one non-exclusive write). Live-verified macOS (pbpaste/Swift readers), Linux X11 (xclip: 5 MIME targets on one selection), Windows (in-session round-trip). Probe: `clipboardprobe set-multi [file…]`.

Package-level sugar follows the `AnnounceToScreenReader` fallback pattern: `bellui.ClipboardImage/SetClipboardImage/ClipboardFiles/SetClipboardFiles/ClipboardHTML/SetClipboardHTML`; **setters return `bool`** = "clipboard supported this flavor". Getters return `(zero, false)` for both "empty" and "unsupported"; capability absence is signalled only by the assertion / sugar bool.

**Platform matrix**: macOS + Windows + **Linux desktop (X11 + Wayland, Phase 2)** = all three flavors; **wasm = image + HTML only** (no portable browser file-list flavor; best-effort behind clipboard permission + transient user activation — reads start synchronously in the post-gesture turn, rejection degrades to `(zero, false)`); test driver = all three in-memory (exclusive-flavor semantics); mobile = image paste (#580) plus multi-flavor `SetFlavors` (#1142) — `HTMLClipboard`/`FileClipboard` stay unimplemented there (no HTML getter, no file flavor).

Implementation: `internal/driver/glfw/clipboard_flavors_{darwin,windows,linux,wasm}.go` add methods to the shared `clipboard` struct per-platform (upstream GLFW is string-only, so darwin uses an ObjC NSPasteboard bridge — PNG+TIFF, `writeObjects:` promises force-flushed by reading each item back — and windows a plain-C Win32 bridge — registered "PNG"+CF_DIB, CF_HDROP, "HTML Format"+CF_UNICODETEXT, retry only on failed `OpenClipboard`). **Linux rides on the forked GLFW's generic MIME clipboard API** (C: `glfwSetClipboardData`/`glfwGetClipboardData`/`glfwGetClipboardTargets`; Go: `glfw.SetClipboardData([]ClipboardFlavor)` etc.): the C layer owns the X11 CLIPBOARD selection (dynamic TARGETS, MULTIPLE, outgoing **INCR** transfers for large payloads, both directions) and the Wayland `wl_data_source`/`wl_data_offer` MIME negotiation (offers record the full MIME list; image-only selections are no longer dropped on arrival), dispatched at runtime per platform — compatible with the #542 runtime-selection plan. Linux flavor MIMEs: `image/png`; `text/html` + `text/plain;charset=utf-8` companion (UTF-16 BOM guard on read); files = `text/uri-list` **and** `x-special/gnome-copied-files` ("copy" op) for GNOME/KDE file-manager interop — both written, both read (the gnome decode rejects payloads whose first line isn't `copy`/`cut` because xclip serves its data for *any* requested target). **Wayland platform limitation**: selection read/write needs keyboard focus (`set_selection` needs a serial from a real input event) — writes from an unfocused window are refused by the compositor. Native calls run via `runOnClipboardThread` (inline on the main goroutine — queueing with wait from the running main loop would self-deadlock). The payload codecs (CF_HTML header block, DIB encode/decode incl. V5/bitfields, text/uri-list + gnome-copied-files in `urilist.go`) are **pure Go in `internal/clipboard`**, unit-tested on every CI leg. Live-verify harness: `hack/clipboardprobe` (CLI ops on desktop; **`--run` managed mode for Linux** — clipboard ops need the running GLFW loop and set-ops must stay alive serving the selection; button UI for wasm). Headless Wayland verify recipe: headless sway + `wtype -k Escape` (instantiates a virtual keyboard on the seat) + `swaymsg '[title=…]' focus`.

### Rich Notifications — Click Activation + Action Buttons + Icon (#516, Phase 1)
`bellui.NotifierWithOptionsApp` — an **opt-in** optional interface (asserted from the `App`, like `NotifierApp`/`BadgeApp`) for notifications richer than the fire-and-forget `{Title, Content}` `bellui.Notification`. `SendNotificationWithOptions(*bellui.NotificationOptions)` where `NotificationOptions{Title, Content string; Icon bellui.Resource; OnTapped func(); Actions []NotificationAction}` and `NotificationAction{Label string; Callback func()}`. The plain `SendNotification` API is untouched.
- **Free function** `bellui.SendNotificationWithOptions(n) bool` mirrors `bellui.SendNotification`: it asserts the interface and returns whether the rich form was delivered; an app that only implements plain `NotifierApp` **degrades to a title+content notification** (callbacks/actions dropped, never the whole notification). The concrete `belluiApp` implements the rich method on **every** platform, so degradation happens *inside* the platform method where a capability is missing — the "never lose the feature" guarantee.
- **Callbacks are session-scoped and delivered on the main goroutine**: `OnTapped` (body click, the #1 ask) and each action `Callback` fire only while the sending app is still running (activation of a *terminated* app is out of scope — that is #510 open-with launch-activation territory). Shared plumbing in `app/notification.go`: `registerNotifyCallbacks(opts) → token` (0 when nothing to track), `fireNotifyTapped`/`fireNotifyAction`/`forgetNotify`, all hopping onto the main goroutine via the #510 `queueOnMain` (`go bellui.Do`) seam; a per-notification temp icon is written by `writeTempNotificationIcon`.
- **Linux/BSD (full)** — `app/app_notification_xdg.go` uses the raw `org.freedesktop.Notifications` D-Bus interface (the portal wrapper has no actions channel, so **Flatpak degrades** to plain). The `actions` array is `["default", "", "bellui-action-0", <label>, …]` — `default` is the body-click, each button an indexed key; a one-time `AddMatchSignal` + `conn.Signal(ch)` goroutine routes `ActionInvoked`→`fireNotify*` and `NotificationClosed`→cleanup (removes the temp icon), keyed by the native notification id returned from `Notify`. **Live-verified end-to-end on GNOME/Wayland**: real `Notify` with the actions array + per-notification icon reaches gnome-shell; emitting `ActionInvoked default`/`bellui-action-0`/`bellui-action-1` + `NotificationClosed` on the session bus fires BODY CLICK / REPLY / LATER callbacks on the main goroutine and removes the temp icon.
- **macOS/iOS (full)** — `app/app_darwin.{go,m}` migrates the rich path to a `UNUserNotificationCenter` **delegate** (`BelluiUNDelegate`): actions become a per-notification `UNNotificationCategory` (identifier `bellui-cat-<token>`, actions `bellui-action-<i>`), the token rides in `content.userInfo`, the icon is a `UNNotificationAttachment`, and `didReceiveNotificationResponse` maps the action id → `//export notifyCallbackDarwin(token, idx)` (idx −1 = body click, ≥0 = action, other = cleanup-only) which fires + forgets. `willPresentNotification` shows banners while foreground. **Requires a bundled app with a valid identifier** — an unbundled/`go run` binary or a bundle whose linker signature carries the wrong identifier can't get notification authorization, so it degrades to the osascript path (the `bellui package` bundle is fine; ad-hoc `codesign -s -` with the real bundle id makes the OS permission prompt appear). Verified live on macOS to the point of the OS permission prompt + `rich=true` send path; the final banner-click callback is interactive-only (the private UN delegate has no injection point like Linux's bus — the shared registry + main-goroutine dispatch it feeds is fully proven by the Linux run).
- **Degraded (documented follow-ups)** — Windows (#722: needs AUMID + WinRT toast activator; the PowerShell sender has no callback channel), Android (#723: PendingIntent), wasm actions (#724: Service Worker; **wasm OnTapped + icon already work** via the `Notification` `onclick`). All degrade to a plain notification; the test-driver app records both the rich options and the reduced plain form.
- Live-verify harness: `hack/notifyprobe` (`-auto` scripted mode). Unit tests: `app/notification_test.go` (registry bookkeeping), `app/app_notification_xdg_test.go` (`parseNotifyActionKey`), `test/notification_test.go` (free-function routing).

### Data Model Layer — Sort/Filter/Selection (#539)
`data/model` is a generic, observable data layer that sits **between** app data and the `List`/`Table` widgets (Qt `QSortFilterProxyModel`/`QItemSelectionModel`-style), so apps stop hand-rolling sort state, filter re-indexing and the selection-remap bugs. It is **widget-free** (imports only `data/binding` + `lang`); the widget adapters live in `widget` (the B2 placement — one-way `widget → data/model`, no cycle).
- **`model.Model[T]`** — read-only observable sequence (`Len`, `Item(i)`, `AddListener`/`RemoveListener` reusing `binding.DataItem`; a new listener fires immediately). `model.SliceModel[T]` is the in-memory backing (`Set`/`Append`/`SetItem` notify; `Set` defensive-copies). `model.FromDataList(binding.DataList)` adapts an existing binding for free.
- **`model.SortProxy[T]`** (`SetLess(func(a,b T) bool)`) and **`model.FilterProxy[T]`** (`SetPredicate(func(T) bool)`) — each is *itself* a `Model[T]` holding an index permutation into its source, rebuilt **once per source change / comparator-or-predicate swap, never per row** (O(n log n) / O(n)). They compose (source → filter → sort → view). `SourceIndex(i)` maps display→source; `Close()` detaches from the source. `model.StringLess` = `lang.Compare` (#504) is the documented default comparator for user-visible text. **Perf contract**: reading rows is O(1) each, so a bound widget keeps O(visible)/frame — `BenchmarkSortProxyFrameWalk` is 0 alloc / 0 comparator calls; the once-per-change rebuild is ~33 ms at 100k rows.
- **`model.SelectionModel[T, K comparable]`** (`id func(T) K`) — tracks selection by **stable identity key, not row index**, so a selection survives a re-sort/re-filter/insert (the bug `widget.List`/`Table` positional `int` selection suffers). Single/Multi modes; `Select`/`Unselect`/`Toggle`/`Clear`/`SelectRange`; `IsSelected`/`Selected`/`Len`; and the index bridge `SelectIndex`/`ToggleIndex`/`IsIndexSelected` + `IndexOf(k)`/`SelectedIndices()` a widget adapter uses to turn a positional tap into an identity selection and re-derive the highlighted row after a reorder. Observable (fires on selection change).
- **Widget adapters** (in `widget`): `widget.BindListModel[T](list, m, create, update) (unbind)` and `widget.BindTableModel[T](t, m, cols, create, update)` set the widget callbacks (typed `update(item, cell)` — no positional indexing) and refresh on model change. `widget.BindListSelection[T,K](list, m, sel)` keeps a `List`'s selection in sync with a `SelectionModel` (tap→model via `SelectIndex`; on reorder/selection-change re-derive the highlight, guarded against the `list.Select` echo). **The `List` widget paints only one highlighted row** — for multi-selection have `update` call `sel.IsIndexSelected(i)` and style the row itself (the demo does this). `hack/modelprobe` is the live-verify demo (100k rows + live search + collated sort toggle + surviving multi-select).
- **FileTree.Sorter is intentionally not reimplemented on this layer**: `FileTree` is a `Tree` (string-keyed, with ancestor-visibility filter semantics), and Tree-shaped proxies are a separate later phase — the flat List/Table proxies do not model a hierarchy. `FileTree.Sorter` already uses `lang.Compare` (#504) directly for collated name order. Phase-1 out-of-scope follow-ups: in-place editing delegates, Tree-shaped proxies, and Table multi-column-sort header UI.
- **Table multi-column sort UI (#617)** — `widget.BindTableSort[T](t *Table, proxy *model.SortProxy[T], cols []widget.SortableColumn[T]) *widget.TableSorter[T]` adds header-click sorting on top of the #539 layer. Each `SortableColumn[T]{Title string; Less func(a, b T) bool}` declares a header label and an *ascending* comparator once (nil `Less` → inert display-only column; for user text use `model.StringLess`). `BindTableSort` enables `Table.ShowHeaderRow` and installs `CreateHeader`/`UpdateHeader` that render each title with a ↑/↓ arrow and a **tappable** header cell — it never touches `Length`/`CreateCell`/`UpdateCell`, so it composes with `widget.BindTableModel` over the *same* proxy. The header cell (`tableSortHeader`) is a Tappable Label: data cells are deliberately non-Tappable so the Table keeps cell input (`tableCellHost`), but nothing consumes header taps, so the arrow widget receives them; column-resize drag (Table `MouseDown`/`Hoverable`) is untouched since the header cell is neither Mouseable nor Hoverable. Clicking a column cycles it **none → asc → desc → none** and makes it the **primary** key; earlier-clicked columns stay active as **stable tie-breakers**, so click A then B sorts by B then A (the proxy sorts stably). The composed comparator is rebuilt and pushed via `SortProxy.SetLess` on every change (nil when no keys → source order), which re-sorts and refreshes the table — re-running `UpdateHeader` so arrows track state. `TableSorter` drives the sort programmatically (`SortByColumn(col)`, `Clear()`) and reports state (`Sorts() []ColumnSort`, `DirectionOf(col) SortDirection`); `Unbind()` clears the installed header callbacks. Main-goroutine discipline like the other adapters.

### Data Model Layer — Write Path & Editing Delegates (#615)
The follow-up write path to #539 (which was read-only). Two pieces, mirroring the read-path split (`data/model` core + `widget` adapters, one-way `widget → data/model`, no cycle):
- **`model.MutableModel[T]`** (`data/model/mutable.go`) — a `Model[T]` plus `SetItem(i int, item T)`, the write counterpart to the read-only `Model[T]`. `SliceModel` already satisfied it (its existing `SetItem` writes the slice + notifies); `SortProxy`/`FilterProxy` now implement `SetItem` too, so they satisfy `MutableModel` and **write-through**: `proxy.SetItem(displayIndex, item)` maps display→source via the existing `SourceIndex(i)` and writes the underlying source. Because a proxy's source may itself be a proxy, this composes down a **chain** (filter→sort→view): editing a *displayed* row updates the correct *source* row regardless of the active sort/filter. **Non-mutable-source decision**: if a proxy's ultimate source is not a `MutableModel` (or the index is out of range), `SetItem` is a **logged no-op via `bellui.LogError`, never a panic** — a bound editor degrades gracefully. Writing through the source fires the source's change notification, which the proxy is already subscribed to, so **one edit ⇒ one re-index + one notification at the bound level** (verified by `TestSetItem_NotifiesOnce`).
- **Editing delegates** (`widget/editmodel.go`): `widget.BindListEditing[T](list, m, createDisplay, updateDisplay, editor) (*ListEditor[T], func())` and `widget.BindTableEditing[T](t, m, cols, createDisplay, updateDisplay, editors) (*TableEditor[T], func())` swap a row/cell to an **inline `Entry`** on activate and commit the edited value back through the `MutableModel` as one gated write. The cell/row template is a `layout.NewStackLayout()` container of `{display, editEntry}` (the internal `editEntry` embeds `Entry`, committing on Enter/`OnSubmitted` and focus-loss, cancelling on Escape); `UpdateItem`/`UpdateCell` show exactly one, seeding the editor from `CellEditor.Text` **only on entry** (guarded so a `Refresh` mid-edit doesn't wipe typing).
  - **`CellEditor[T]`** describes the exchange: `Text func(item T) string` (seed), `Commit func(item T, text string) (T, error)` (parse; a **non-nil error rejects** the edit — editor stays open, model untouched — which is how validation gates the commit), optional `Validator bellui.StringValidator` (live in-field feedback only). A nil `Commit` marks the column/row **not editable**. Table `editors` is indexed by column.
  - **Controller** (`ListEditor`/`TableEditor`): `Edit(row)` / `Edit(TableCellID)` begins editing; `Commit() error` writes one gated `SetItem` (returns the validation error on rejection, keeps the editor open); `Cancel()` discards; `Editing()` reports state. All main-goroutine, like every widget mutation.
  - **Compose with `SelectionModel`**: activation defaults to the widget's own selection (`OnSelected` → `Edit`, chaining any prior callback) via `EditOnActivate` (default `true`). Set it `false` to drive editing from a `model.SelectionModel` instead — e.g. `ctrl.Edit(sel.IndexOf(key))` — so identity-keyed selection and inline editing coexist without both fighting over `OnSelected`.

#### Tree-Shaped Proxies (#616)
`model.TreeProxy` is the tree-shaped counterpart of the flat `SortProxy`/`FilterProxy`, layered over the string-keyed `Root`/`ChildUIDs`/`IsBranch` callback shape a `widget.Tree` consumes. It expresses two semantics a flat proxy cannot:
- **`model.TreeSource`** — the read side of a hierarchy (`Root() string`, `Children(uid) []string`, `IsBranch(uid) bool`). `model.NewTreeSource(root, childrenFn, isBranchFn)` wraps an existing tree's callbacks; `TreeProxy` is itself a `TreeSource`, so proxies compose.
- **`model.NewTreeProxy(src)`** with `SetLess(func(a,b string) bool)` (per-**sibling-group** sort — children of each node are ordered among themselves, hierarchy preserved, **not** a global flattened order) and `SetPredicate(func(uid string) bool)` (**ancestor-keeping** filter). Ancestor-keeping = a node is visible iff it matches OR has any visible descendant, so a deep leaf match keeps its whole ancestor chain reachable while non-matching siblings drop; a branch is kept by its own-id match too. `IsBranch` under a filter reports true only when the node has visible children (no dead expand arrows). `SetKeepMatchingSubtree(true)` additionally reveals the *entire* subtree under a branch that matches by its own id (file-explorer "folder name matches → show contents"), vs the default reachability-only paths.
- **Perf/reactivity**: a filter change walks the source once (O(n)) to compute the visible set; a sort-only change is lazy (per-parent sort, cached) — never per-frame, so a bound tree keeps O(visible). The comparator/predicate receive the node **id** (map id→label in the closure for label-based ordering, e.g. via `lang.Compare`). Unlike the flat proxies the source is a raw callback tree (not an observable `Model`), so after the underlying data changes call `TreeProxy.Refresh()` to rebuild + notify. A defensive `seen`-set cycle guard keeps a malformed source from looping.
- **Widget adapter**: `widget.BindTreeModel(tree *Tree, p *model.TreeProxy) (unbind func())` (in `widget/bindmodel.go`) wires the proxy's `Root`/`Children`/`IsBranch` into the tree and `tree.Refresh`es on every view change; the app still supplies `CreateNode`/`UpdateNode`. Drive `SetLess`/`SetPredicate`/`Refresh` on the main goroutine.
- **`widget.FileTree.Sorter` stays as-is** (decision reconsidered per #616): `FileTree` lists directories **lazily and asynchronously** off the main goroutine, so it must never enumerate the whole tree — but a `TreeProxy` *filter* requires a full walk from the root to compute ancestor visibility. `FileTree` also already has its own ancestor-visibility filter (`Filter` keeps directories) and collated `Sorter` (`lang.Compare`) applied per-listing off-thread; rewiring it onto `TreeProxy` would either force eager listing or duplicate the semantics for no gain. `TreeProxy` targets **finite, enumerable** trees (symbol trees, category trees, in-memory hierarchies) where a per-filter O(n) walk is fine. Documented rather than adapted.

### Responsive Layout (bellui-x-inspired, #444)
`layout.NewResponsiveLayout(objects...)` + `layout.Responsive(obj, ratios...)` — bootstrap-style adaptive rows: each child declares a width ratio (0–1] per size class, rows wrap when ratios would exceed 1 (float epsilon absorbs thirds), members get the row height, ratios summing to 1 fill the row exactly. Size classes default to the **MD3 window size classes in dp** (compact <600, medium <840, expanded <1200, large <1600, extra-large) via `DefaultResponsiveBreakpoints`; set `ResponsiveLayout.Breakpoints` for a custom table (e.g. Bootstrap `{576, 768, 992, 1200}`). Missing ratios inherit the previous class. The class derives from the **container** width (not the window), so a subtree inside Split/Paned adapts to its pane. Rows mirror under RTL (`MirrorChildren`). The `Responsive` wrapper is a plain stack-layout `*bellui.Container` whose ratio config rides in its layout (`responsiveStack`; layout package cannot import widget) — **never a type embedding `bellui.Container`**: the object-tree walker (`internal/driver.walkObjectTree`, behind painting/hit-testing/a11y/markup) and the test markup renderer match `*bellui.Container` by exact type, so an embedder's children lay out but are silently never painted or hit-testable (#767, latent since #450). The rule generalizes to any custom container-like CanvasObject in the fork: use a plain `*bellui.Container` (config in the Layout or a lookaside) or a real `core.Widget` with a renderer.

### About Dialog (#446)
`dialog.NewAbout(content string, links []*widget.Hyperlink, a bellui.App, w bellui.Window)` / `NewAboutWindow(content, links, a)` + `ShowAbout`/`ShowAboutWindow` — MD3-native about box from `App.Metadata()`: centered icon (96dp), name in `TypographyHeadlineSmall`, version in `TypographyBodyMedium` (each omitted when the metadata field is empty), scrollable RichText markdown content (`AllowRemoteContent` stays false — app-supplied markdown is treated as untrusted per #285), dot-separated links footer, localized "About <Name>" title. ### Accessibility Semantic Layer (#484, epic #490)
Screen-reader support is built in two layers:
- **Public semantics (always compiled)** — `core/accessible.go`: `core.Accessible` (`AccessibleRole()`, `AccessibleLabel()`) plus optional `AccessibleDescriber`/`AccessibleValuer`/`AccessibleStateful`/`AccessibleActioner`, ~45 `Role*` constants, `AccessibleState` bitmask and `Action*` names. Most stock widgets implement it (see `widget/accessible_test.go`). `AccessibleRole.ChildrenPresentational()` mirrors WAI-ARIA "children presentational": leaf controls (button, label, text inputs, …) are one semantic unit whose internal accessible widgets (e.g. the `RichText` painting a Button's label) are dropped from the tree. `core.SnapshotAccessible(obj)` captures one object's properties; `core.WalkAccessibleTree` is the geometry-free public walk.
- **Bounds-aware walker (`-tags accessibility` only)** — `internal/accessibility`: `BuildTree(roots...)`/`CanvasNodes(canvas, menu)` walk the rendered tree via `driver.WalkVisibleObjectTree` (containers *and* widget renderers, so content inside Scroll is found) and yield `Node{AccessibleNode, Pos, Size, Clip, Children}` with absolute dp bounds, nested under the closest accessible ancestor, in tree = reading order (order is unchanged under RTL/DirectionScope — bounds reflect mirrored positions; backends convert dp→px via `internal/scale`). `accessibility.Enabled` is the const drivers branch on. Platform backends (NSAccessibility #485, UIA #487, mobile #488) consume these nodes; none of the neutral layer touches a platform API. CI runs the tagged tests on the linux + macOS legs of platform_tests.
- **Widget coverage (#486)** — beyond the #484 set, semantics extend to per-item internals (`radioItem`; `listItem`/`gridWrapItem` as RoleListItem with select actions; `tabButton`/`segmentWidget`/nav bar+rail items as RoleTab with StateSelected; `menuItem`; drawer items) and container/value widgets (`GridWrap`; `PopUp` — RoleDialog+StateModal when modal / RoleGroup otherwise, so dialogs/sheets/drawers/FABMenu get a dialog node for free; `DatePicker`/`TimePicker`/`DateTimePicker` as RoleGroup with locale-formatted `AccessibleValue`; `Carousel`, `StatusBar`, `ScrollIndicator`). Icon-only widgets are named via `BaseWidget.SetAccessibilityLabel(label)` (the `core.AccessibleLabelOverrider` seam — a non-empty override wins over the intrinsic `AccessibleLabel` in `core.SnapshotAccessible`); pickers/carousel label their internal prev/next IconButtons with `lang.L` strings. `AccessibleValuer`'s `(0,0,0)` range sentinel yields `HasRange=false` (#500), so backends can trust the flag. **`StateDisabled` is derived structurally, not per widget** (#52): `buildNode` ORs the bit in whenever the object is a `core.Disableable` reporting `Disabled()`, *after* the `AccessibleStateful` block — `Disableable` is authoritative for that bit, OR-ing preserves whatever else the widget reported, and no widget has to re-declare what it already is. Before this, seven accessible+disableable widgets (`Button`, `FAB`, `IconButton`, `SplitButton`, `RadioGroup`, `SpinBox`, `Slider`) implemented no `AccessibleState` and so were announced as actionable while disabled on **every** backend (darwin `AXEnabled`, UIA `IsEnabled`, AT-SPI `ENABLED`/`SENSITIVE`, the mobile wire node) — a control that reads as available and silently does nothing. A newly-added `Disableable` widget now gets the bit for free. Later phases: text-bearing roles use `NonInteractiveChildrenPresentational` — the walker keeps embedded interactive controls (Entry ActionItem buttons, links in RichText) while dropping value-painting internals (#522/#523); DatePicker day cells are tappable RoleButton widgets (#521); realized Table cells are wrapped in an accessible `tableCellHost` (RoleTableCell + `core.AccessibleGridItem` row/col; `UpdateCell` still receives the bare template via `unwrapTableCell`) and Tree rows implement RoleTreeItem + expand/collapse/select + `core.AccessibleLeveler` (#524).
- **Screen-reader announcements (#525)** — `internal/accessibility.Announce(text, assertive)` pushes transient status text ("live region") to backend listeners registered via `AddAnnouncementListener`; no-op without the tag or without listeners; call on the main goroutine. `Toast.Show`/`Snackbar.Show` announce their text (Danger/Warning toasts assertive, the rest polite). Apps use `bellui.AnnounceToScreenReader` (optional `bellui.AccessibilityAnnouncer` driver interface; glfw + mobile drivers implement it). The darwin bridge delivers via `NSAccessibilityAnnouncementRequested` (high/medium priority) posted on the key window.
- **Live-verify harness (#561)** — `hack/a11yprobe`: two-window probe app (`go run -tags accessibility ./hack/a11yprobe`) exercising every bridge feature (plus a virtualized Table for the coordinate patterns), raw-AX ObjC clients under `hack/a11yprobe/darwin/` (needed because System Events cannot set range-typed AX attributes) and PowerShell UIA clients under `hack/a11yprobe/windows/` (`uiatree`/`uiaact`/`uiatext` over `System.Windows.Automation`). Its README records the operational gotchas (display sleep makes AX go dark — `caffeinate -d -u`; clip-culling vs height-starved widgets; custom-action discovery via `actions of`). Use it to acceptance-test bridge changes. **Windows-over-SSH gotcha**: an SSH session lives in a session-0 window station where GLFW windows stay invisible and UIA desktop enumeration cannot see them — and each ssh command gets its *own* station, so a probe launched in one command is invisible to a client in the next. Off-viewport `Table.GetAccessibleAt` realizes the cell through the neutral `accessibility.RealizeCell` seam (#637) via `bellui.DoAndWait` (the one handler that must reach the main goroutine; the provider mutex is never held across the hop — the reconcile takes it there), cached per window keyed by stable identity (FIFO, `accessibility.RealizedCap`) and **promoted** into the reconcile map when the cell scrolls into view so its path survives. Announcements (#525) emit from the application root. Live-verified with `busctl` against a GNOME/Wayland session (`hack/a11yprobe` + `hack/a11yrealizeprobe`; recipe in the a11yprobe README); Orca table-navigation speech pass tracked in #1063.

### Widget-Tree Inspector (DevTools, #540)
`dev/inspector` — an opt-in, **read-only** runtime widget-tree inspector for debugging layouts (the human-facing half of the #490-deferred introspection seam). `inspector.Show(w bellui.Window) *Inspector` opens a **separate** native window (desktop-only; mobile/wasm are single-window and out of scope) targeting `w`; apps gate it themselves (e.g. `if os.Getenv("BELLUI_INSPECT") == "1" { inspector.Show(w) }`). Heavy code is only linked when the package is imported (`theme/cjk` placement pattern); the existing lightweight `dev.Enable(w)` F12 overlay is unrelated and untouched.
- **Tree pane** (`tree.go`): a full object forest built by `snapshotRoots` over the target's content + overlays (minus the inspector's own highlight/pick surfaces), driven by the same `internal/driver.WalkVisibleObjectTree` the painter/hit-test use — so it descends **both containers and widget-renderer internals**, and records absolute positions + clip bounds identically. Nodes get stable per-refresh path UIDs (`"0/1/2"`) fed to a `widget.Tree`; a `byObj` map keys nodes by live object for pick. **On-demand only** — a Refresh button (no ticker), so a closed/idle inspector costs nothing.
- **Detail pane** (`detail.go`): `describe(node)` is a pure function → Position/Size/MinSize (dp), absolute bounds, `Visible()`, clip, `*container.Scroll` offset+content size, `*container.DirectionScope.ScopedDirection()`, `*container.ThemeOverride` presence, and the a11y snapshot via `core.SnapshotAccessible` (role/label/value). Role names come from the new **`core.AccessibleRole.String()`** (added in `core/accessible_role_string.go`; a slice indexed in iota order, falls back to `AccessibleRole(n)`).
- **Highlight** (`pick.go`): selecting a node adds a stroke-only `canvas.Rectangle` overlay to the **target** canvas at the node's absolute bounds. **Pick mode**: the Pick button adds a transparent full-canvas `pickOverlay` (Hoverable+Tappable+Focusable) on the target; hover previews the deepest object under the cursor (`resolveObjectAt` → `driver.FindObjectAtPositionMatching` over content only, so overlays/highlight are never picked), click selects it in the tree (refresh → `byObj` lookup → open ancestors → `Tree.Select`), Escape cancels (the overlay grabs keyboard focus so the app's own key handler is untouched). Everything added to the target is removed on the inspector window's `SetOnClosed`.
- Snapshot accessor methods are **nil-receiver-safe** — the `widget.Tree` lays out (calling `childUIDs`/`isBranch`) during `SetContent` before the first `refresh()` populates `snap`. Phase 2 candidates (refresh counters, MinSize-chain explanation, snapshot diff, text export) are listed in #540, not built.
- **Public pick primitive (#602)**: the forward hit-test the inspector uses internally is also exposed publicly for out-of-module tooling (the design-tool preview pane's pick-to-source, goed#35) — `driver.ObjectAtPosition(c core.Canvas, pos) (obj, bounds, ok)` and `driver.ObjectAtPositionMatching(c, pos, matches)` in the public `driver` package (`driver/objectat.go`, mirroring `driver.ClipBoundsForObject`), thin wrappers over `internal/driver.FindObjectAtPositionMatching` (overlays top-down then content, honoring input-pass-through overlays) that also return the object's absolute canvas bounds. The reverse (object→highlight) was already public via `bellui.Driver.AbsolutePositionForObject` + a `canvas.Rectangle` overlay.

### Analytics — Consent-First, Battery-Safe Event Package (#526, Phase 1)
`analytics` is an **opt-in package beside the toolkit** (the `theme/cjk` placement pattern): Bellui core, drivers and widgets are 100% analytics-unaware and the package costs nothing unless imported. The only toolkit integration point is the public `bellui.Lifecycle`. It gives every app the event queue, consent gate, batching loop and flush-on-background logic that they would otherwise hand-roll (and get wrong on mobile). Phase 2 (semantic auto-capture via the accessibility tree) is the separate #527 and is **not** built here — instrumentation is explicit-`Track`-only.
- **Public API** — `analytics.Tracker` interface (`Track(event, props)`, `Identify(id, traits)`, `Flush() error`, `SetEnabled(bool)`), `analytics.New(sink Sink, opts ...Option) Tracker`, package-level default tracker (`SetDefault`/`Default` + free `Track`/`Identify`/`Flush`/`SetEnabled` delegating to it; the default is a safe no-op until installed), `analytics.Attach(t, lc)` (wires session lifecycle) and `analytics.Close(t)` (stops the worker; both operate on the interface via internal assertion, keeping the `Tracker` interface at exactly the 4 spec methods). `Event{Kind, Name, Props, Traits, UserID, SessionID, Timestamp}`; `Sink` interface `Send(batch []Event) error`.
- **Consent invariant (enforced by construction, tested)** — a `Tracker` **starts DISABLED**. Until `SetEnabled(true)`, `Track`/`Identify` drop events: nothing is queued in memory, nothing spooled to disk, nothing sent (`TestConsentGate_NothingBeforeEnable`). The package generates **no device identifiers** — no advertising ID, no fingerprint, no random install ID; identity is supplied by the app via `Identify` only. The per-run `SessionID` is ephemeral (rotated every launch, never persisted as identity) so it is not a device/install ID (`TestNoDeviceIdentifierGenerated`). `SetEnabled(false)` drops the in-memory queue and clears the disk spool (`TestDisableClearsSpool`). This keeps the **Google Play Data-safety / GDPR** story honest: consent withheld ⇒ no collection, no identifier to declare; consent granted ⇒ only app-declared events + app-supplied identity, so the Data-safety form maps 1:1 to the app's explicit `Track`/`Identify` calls.
- **Battery model (hard API contract, documented on methods, tested)**, `tracker.go`:
  1. `Track` is **fire-into-queue, never fire-into-socket** — it appends to the in-memory ring, checkpoints the spool, and (past the batch threshold) asks the background worker to flush via a non-blocking channel signal; it never calls `Sink.Send`. Proven by `TestTrack_NeverSendsSynchronously` (a threshold-crossing `Track` returns promptly even while a blocking sink is stuck) and the sink call-count assertions.
  2. Batch flush policy (all `Option`s, radio-conservative defaults): `WithBatchSize` (≥30 events) ∨ `WithInterval` (≥60 s foreground) ∨ `EnteredBackground` (the `SetOnExitedForeground` edge) ∨ explicit `Flush()`.
  3. The interval **ticker is suspended while backgrounded** (`ctrlSuspend` stops it; mobile processes freeze) and resumed on foreground; the background-edge flush is the workhorse (`attach` → `SetOnExitedForeground` tracks `session_end`, forces a flush, then suspends). Deterministically tested with a fake clock/ticker — no wall-clock, no sleeps (`TestIntervalFlush`, `TestIntervalSuspendedWhileBackground`).
  4. **Disk spool** via a `Store` (default `BelluiStore` over `bellui.Storage`; in-memory fallback when no app): the ring is checkpointed on every enqueue and after a successful flush, survives process death, drains **oldest-first** on the next `SetEnabled(true)` (`TestSpoolRoundTrip`), and is bounded by `WithMaxSpool` with oldest-first eviction so a dead sink can't grow it without limit (`TestMaxSpoolEviction`).
  5. Batch bodies are **gzipped by the Sink** (`analytics.PostJSONGzip`); exactly one request per flush.
  6. A failed flush **retains** the events and arms **exponential backoff with full jitter** (`WithBackoff`); non-forced flushes are gated until the window elapses so we never retry into a dead radio (`TestBackoffRetainsAndGates`). Offline is a normal state, not an error.
  7. **Documented limitation**: pure-Go apps have no JNI surface for Android WorkManager / iOS BGTaskScheduler, so there is no OS-scheduled deferred upload. Compensation is bigger batches, longer intervals, the background-edge flush and the next-launch drain; one-session analytics latency is acceptable by design.
- **Determinism seams** — `WithClock(Clock)`, `WithJitterSource(func() float64)` and `WithStore(Store)` inject time, jitter and persistence so all timing/backoff tests are deterministic (fake clock + manual ticker; no real sleeps).
- **Vendor sinks** are dumb single-file optional subpackages over `net/http` + `analytics.PostJSONGzip`: `analytics/ga4` (GA4 Measurement Protocol; `New(measurementID, apiSecret)`; ≤25 events/request; `client_id` from the app-supplied `UserID`, else the ephemeral `SessionID` — never synthesised) and `analytics/posthog` (`New(apiKey)` / `NewWithHost`; `/batch/` capture; `distinct_id` likewise). Stdlib-only (`net/http`, `compress/gzip`, `encoding/json`); apps can bring their own `Sink`.
- **Remaining (manual follow-up, not attempted here)**: live-verify against a real backend (PostHog or GA4-MP) from desktop plus the Android probe app, observing batch cadence (mitmproxy / backend timestamps) rather than per-event traffic.

### Analytics — Semantic Auto-Capture (#527, Phase 2)
Opt-in sugar on top of phase 1: turn taps into `"ui.activate"` events with **no per-widget instrumentation**, deriving role/label/state from the public accessibility layer. Explicit `Track` remains the primary model; this is purely additive.
- **Seam = a `core` hook** (`core/activation.go`, mirrors the `SetFontFallbackRegister`/`RegisterTextMeasure` pattern — keeps `core` widget-free, nothing added to `CanvasObject`): `var core.OnActivation func(obj CanvasObject, viaKeyboard bool)` + guarded `core.NotifyActivation(obj, viaKeyboard)`. Nil unless a consumer is installed, so an app that never imports auto-capture pays **one nil check per activation** (`TestOnActivation_NilByDefault`). Drivers call `core.NotifyActivation(co, false)` at each tap-dispatch site, right where `wid.Tapped(ev)` fires, once per activation: glfw `window.go` (single-tap + `waitForDoubleTapEnded` fallback — mutually exclusive, so one fire; wasm rides the same glfw path), mobile `driver.go` `TapUp`, embedded `driver.go` `TapUp`.
- **Screen-reader activations** (`-tags accessibility`): the a11y AXPress/UIA/mobile-activate paths call `obj.Tapped(...)`/`PerformAccessibleAction(...)` **directly**, NOT through the driver tap-dispatch seam, so they are *not* covered "for free" by the driver-site placement (the #527 issue note assumed otherwise). To deliver the intended screen-reader parity, `core.NotifyActivation(obj, false)` is also fired at each a11y primary-activation entry point: darwin `belluiAccessibilityPerformPress` (both branches), windows `belluiWinA11yInvoke`/`Toggle`/`Select` (each success branch, once — Toggle/Select fall through to Invoke so no double-fire), mobile `accessibility.go` activate (both branches). Increment/decrement/expand/collapse/rename/delete are secondary actions and deliberately do **not** fire. Darwin is compile-verified under `-tags accessibility`; windows/mobile cgo are CI-verified per repo convention.
- **Consumer** (`analytics/autocapture.go`): `analytics.EnableAutoCapture(t Tracker, opts ...CaptureOption)` sets `core.OnActivation`; `analytics.DisableAutoCapture()` clears it. On activation it snapshots via `core.SnapshotAccessible(obj)` and maps **Role→verb** (`verbForRole`: Button/Link/MenuItem→`press`, Checkbox/Switch→`toggle`, ListItem/Tab→`select` — the `core.ActionPress/Toggle/Select` vocabulary; **every other role is skipped**, no event) then emits `t.Track("ui.activate", props)`. Everything inherits phase 1's consent gate + spool + batching + backoff — it is **impossible to wire auto-capture to a raw sink**, it only ever calls `Tracker.Track` (`TestAutoCapture_ConsentGate`: disabled tracker captures nothing; enabled flows through the queue + sink).
- **Privacy guardrails (all enforced in `onActivation`, none optional):**
  - **Role/label/state ONLY** — props are `role` (lowercased `AccessibleRole.String()`), `verb`, `label` (omitted when empty), `state` (`[]string` of active flag names, omitted when none), `via:"keyboard"` when keyboard-sourced. The mapper **never reads `node.Value` or `node.Description`** — that is the privacy line (`TestAutoCapture_NeverValueOrDescription` populates value/description with sentinels and asserts they never appear under any key).
  - **Concealed exclusion**: a new optional interface `core.AccessibleConcealed{ AccessibleConcealed() bool }` (implemented by `widget.Entry`, true iff `Password`); a target reporting true is skipped wholesale, regardless of role (`TestAutoCapture_ConcealedExcluded`). Belt-and-suspenders on top of never capturing values.
  - **`NoCapture` subtree opt-out (option B — top-down ancestor walk, NO `CanvasObject` change):** `analytics.NoCapture(content core.CanvasObject) core.CanvasObject` wraps content in a layout-transparent `*bellui.Container` whose `Layout` is the private `noCaptureLayout` marker. At capture time the consumer resolves the object's canvas (`bellui.CurrentApp().Driver().CanvasForObject(obj)`) and walks the root→obj ancestor chain via the new public **`driver.AncestorsOfObject(c core.Canvas, obj) ([]core.CanvasObject, bool)`** (`driver/ancestors.go`, sibling to `driver.ObjectAtPosition`, reuses `internal/driver.WalkVisibleObjectTree`; touches zero widgets); if any ancestor is the marker container the event is skipped (`TestAutoCapture_NoCaptureSubtree`). Taps are rare, so the O(tree) walk per activation is fine.
  - **Sampling**: `WithSampling(n)` captures 1-in-N of the **eligible** activations via a deterministic atomic counter (not wall-clock), applied *after* the privacy filters so it is a true 1-in-N of would-be events; non-capturable activations (a tapped label) do not advance the counter (`TestAutoCapture_Sampling`, `TestAutoCapture_SamplingCountsOnlyEligible`).
- **Keyboard activation coverage — PARTIAL, by design (documented, not chased).** Enter/Space on a focused widget does **not** route through the driver tap-dispatch seam: widgets self-handle keys internally (e.g. `Button.TypedKey(Space)` calls its own `Tapped(nil)`, bypassing the driver site). The only central keyboard point (`window.go` `focused.TypedKey(keyEvent)`) is a raw key dispatch, not an "activated" signal — firing there would false-positive on every arrow/backspace/space-in-an-Entry. Per the issue's fallback instruction, no per-widget changes were made. Net: **keyboard activation is captured only for widgets whose key handler routes back through the driver `Tapped` dispatch (rare); most Enter/Space activations are not auto-captured.** Pointer taps and screen-reader activations are fully covered. The `viaKeyboard` seam param exists for any future central keyboard-activation point. (No separate issue filed, per instruction.)

## Backlog Protocol

The toolkit backlog lives in the **Bellui Backlog** GitHub project (trendvidia/projects/2):
fields Workstream / Priority (P0–P2) / Tranche (Now, Next, Later, Parked), plus native
blocked-by edges between issues. Before picking up work:

1. Run `hack/plan/plan.sh` — renders the live plan: startable items (unblocked, by tranche
   then priority), blocked items with their open blockers, parked items. Work only unblocked
   items; Parked means decline-unless-triggered (the trigger is recorded in the issue).
2. The issue body is the work spec; the project answers *what/when*. New issues are
   auto-added to the project by `.github/workflows/add-to-project.yml` — set their
   Workstream/Priority/Tranche when triaging.
3. Issues labeled `design-tool` are additionally tracked in the AppViewer Platform project
   (trendvidia/projects/1) as part of the cross-repo design-tool story — its plan wins for
   sequencing those (see trendvidia/appviewer docs/STORY.md).

### Follow-up rule (no silent tech debt)

While executing any issue, discovered work is never left as a TODO comment, a "later" note in
the PR description, or unstated scope creep. Exactly one of:

1. **In-scope**: small, same repo, and needed for this issue's acceptance → do it in the same PR.
2. **File it now**: everything else → open an issue *before* the originating PR merges —
   in this repo, or in the owning trendvidia repo when the gap belongs to a dependency we own
   (glfw, glfw-js, protowire-go, govm, fycoder, tools/CLI, …). Triage it on the spot
   (Workstream/Priority/Tranche here; `design-tool` label if story-related), wire a blocked-by
   edge if it blocks planned work, and cross-link it from the originating issue/PR.
3. Third-party (not ours) → record the limitation in the issue/CLAUDE.md with the upstream link.

A phase/issue is not done while a discovered follow-up exists only in prose.
