# Accessibility

Fork-specific design detail for this area. Issue numbers refer to the Bellui
Backlog.

### Accessibility Semantic Layer (pre-rebrand tracker #484, epic pre-rebrand tracker #490)
Screen-reader support is built in two layers:
- **Public semantics (always compiled)** — `core/accessible.go`: `core.Accessible` (`AccessibleRole()`, `AccessibleLabel()`) plus optional `AccessibleDescriber`/`AccessibleValuer`/`AccessibleStateful`/`AccessibleActioner`, ~45 `Role*` constants, `AccessibleState` bitmask and `Action*` names. Most stock widgets implement it (see `widget/accessible_test.go`). `AccessibleRole.ChildrenPresentational()` mirrors WAI-ARIA "children presentational": leaf controls (button, label, text inputs, …) are one semantic unit whose internal accessible widgets (e.g. the `RichText` painting a Button's label) are dropped from the tree. `core.SnapshotAccessible(obj)` captures one object's properties; `core.WalkAccessibleTree` is the geometry-free public walk.
- **Bounds-aware walker (`-tags accessibility` only)** — `internal/accessibility`: `BuildTree(roots...)`/`CanvasNodes(canvas, menu)` walk the rendered tree via `driver.WalkVisibleObjectTree` (containers *and* widget renderers, so content inside Scroll is found) and yield `Node{AccessibleNode, Pos, Size, Clip, Children}` with absolute dp bounds, nested under the closest accessible ancestor, in tree = reading order (order is unchanged under RTL/DirectionScope — bounds reflect mirrored positions; backends convert dp→px via `internal/scale`). `accessibility.Enabled` is the const drivers branch on. Platform backends (NSAccessibility pre-rebrand tracker #485, UIA pre-rebrand tracker #487, mobile pre-rebrand tracker #488) consume these nodes; none of the neutral layer touches a platform API. CI runs the tagged tests on the linux + macOS legs of platform_tests.
- **Widget coverage (pre-rebrand tracker #486)** — beyond the pre-rebrand tracker #484 set, semantics extend to per-item internals (`radioItem`; `listItem`/`gridWrapItem` as RoleListItem with select actions; `tabButton`/`segmentWidget`/nav bar+rail items as RoleTab with StateSelected; `menuItem`; drawer items) and container/value widgets (`GridWrap`; `PopUp` — RoleDialog+StateModal when modal / RoleGroup otherwise, so dialogs/sheets/drawers/FABMenu get a dialog node for free; `DatePicker`/`TimePicker`/`DateTimePicker` as RoleGroup with locale-formatted `AccessibleValue`; `Carousel`, `StatusBar`, `ScrollIndicator`). Icon-only widgets are named via `BaseWidget.SetAccessibilityLabel(label)` (the `core.AccessibleLabelOverrider` seam — a non-empty override wins over the intrinsic `AccessibleLabel` in `core.SnapshotAccessible`); pickers/carousel label their internal prev/next IconButtons with `lang.L` strings. `AccessibleValuer`'s `(0,0,0)` range sentinel yields `HasRange=false` (pre-rebrand tracker #500), so backends can trust the flag. **`StateDisabled` is derived structurally, not per widget** (#52): `buildNode` ORs the bit in whenever the object is a `core.Disableable` reporting `Disabled()`, *after* the `AccessibleStateful` block — `Disableable` is authoritative for that bit, OR-ing preserves whatever else the widget reported, and no widget has to re-declare what it already is. Before this, seven accessible+disableable widgets (`Button`, `FAB`, `IconButton`, `SplitButton`, `RadioGroup`, `SpinBox`, `Slider`) implemented no `AccessibleState` and so were announced as actionable while disabled on **every** backend (darwin `AXEnabled`, UIA `IsEnabled`, AT-SPI `ENABLED`/`SENSITIVE`, the mobile wire node) — a control that reads as available and silently does nothing. A newly-added `Disableable` widget now gets the bit for free. Later phases: text-bearing roles use `NonInteractiveChildrenPresentational` — the walker keeps embedded interactive controls (Entry ActionItem buttons, links in RichText) while dropping value-painting internals (pre-rebrand tracker #522/#523); DatePicker day cells are tappable RoleButton widgets (pre-rebrand tracker #521); realized Table cells are wrapped in an accessible `tableCellHost` (RoleTableCell + `core.AccessibleGridItem` row/col; `UpdateCell` still receives the bare template via `unwrapTableCell`) and Tree rows implement RoleTreeItem + expand/collapse/select + `core.AccessibleLeveler` (pre-rebrand tracker #524).
- **Screen-reader announcements (pre-rebrand tracker #525)** — `internal/accessibility.Announce(text, assertive)` pushes transient status text ("live region") to backend listeners registered via `AddAnnouncementListener`; no-op without the tag or without listeners; call on the main goroutine. `Toast.Show`/`Snackbar.Show` announce their text (Danger/Warning toasts assertive, the rest polite). Apps use `bellui.AnnounceToScreenReader` (optional `bellui.AccessibilityAnnouncer` driver interface; glfw + mobile drivers implement it). The darwin bridge delivers via `NSAccessibilityAnnouncementRequested` (high/medium priority) posted on the key window.
- **Live-verify harness (pre-rebrand tracker #561)** — `hack/a11yprobe`: two-window probe app (`go run -tags accessibility ./hack/a11yprobe`) exercising every bridge feature (plus a virtualized Table for the coordinate patterns), raw-AX ObjC clients under `hack/a11yprobe/darwin/` (needed because System Events cannot set range-typed AX attributes) and PowerShell UIA clients under `hack/a11yprobe/windows/` (`uiatree`/`uiaact`/`uiatext` over `System.Windows.Automation`). Its README records the operational gotchas (display sleep makes AX go dark — `caffeinate -d -u`; clip-culling vs height-starved widgets; custom-action discovery via `actions of`). Use it to acceptance-test bridge changes. **Windows-over-SSH gotcha**: an SSH session lives in a session-0 window station where GLFW windows stay invisible and UIA desktop enumeration cannot see them — and each ssh command gets its *own* station, so a probe launched in one command is invisible to a client in the next. Run probe + client from one script scheduled onto the interactive desktop (`schtasks /Create ... /IT` + `/Run`, output to a file).
- **Windows UIA backend (pre-rebrand tracker #487, `-tags accessibility` + windows)** — `internal/driver/glfw/accessibility_windows.{go,h,c}` + `accessibility_text_windows.go` (stub for other builds: `accessibility_stub.go`): same reconcile model as darwin — elements keyed by CanvasObject/VirtualID, props diffed in C, UIA events raised only on real changes, clip-culling with the focused element kept as `IsOffscreen`. The C layer is plain C over the mingw-w64 `uiautomationcore.h` C interfaces (manual vtables filled with the header's own Vtbl structs; links `-lole32 -loleaut32 -luiautomationcore -luuid`; builds under both CI mingw flavors — winlibs gcc x64 and llvm-mingw arm64): per-HWND fragment roots behind a `WM_GETOBJECT` subclass (`UiaReturnRawElementProvider`), patterns Invoke/Toggle/ExpandCollapse/SelectionItem/Value/RangeValue/Text/Grid/GridItem gated per node. Role→control type in Go (`a11yControlType`); radio/tab selection state travels through SelectionItem (UIA convention — darwin uses AXRadioButton value instead); headings are Text + `UIA_HeadingLevelPropertyId`; unlabeled groups report IsControl/IsContentElement=false; modal dialogs set `UIA_IsDialogPropertyId`. `RangeValue.SetValue` steps the widget's own increment/decrement actions toward the target (widget owns the step size). The **Text pattern keeps range endpoints as rune offsets** — UIA text units are abstract, so unlike darwin no UTF-16 mapping is needed; character/word/line(=paragraph)/document units resolve through the shared `internal/accessibility.TextIndex` (hoisted out of glfw in pre-rebrand tracker #992, shared with darwin and the AT-SPI backend; word unit = word + trailing whitespace, character unit = UAX #29 grapheme cluster pre-rebrand tracker #991, line unit = visual soft-wrapped line when the widget implements `core.AccessibleTextLayouter` pre-rebrand tracker #990, else logical) and text mutation goes through `Value.SetValue` → `AccessibleTexter`. Text-changed/selection-changed events diff a cheap version stamp (rope-memo string-data pointer; password fields use mask length) so big documents are never snapshotted per frame; text elements resolve their Value pattern live and offer no Invoke. Announcements → `UiaRaiseNotificationEvent` (the one dynamically-loaded API, Win10 1709+). `Table` reports its full extent via `core.AccessibleGridDimensioner` → Grid RowCount/ColumnCount while only realized cells exist as GridItem children (`Grid.GetItem` returns null for unrealized cells). Rename/delete actions have no UIA custom-action rotor and are not exposed. Verified end-to-end via `hack/a11yprobe/windows/`; Narrator/NVDA speech + focus-tracking pass still needs a physical interactive session.
- **Mobile backends (pre-rebrand tracker #488, `-tags accessibility` + android/ios)** — `internal/driver/mobile/accessibility.go` (shared, host-slice-testable) + `accessibility_ios.{go,m,h}` + `accessibility_android.{go,c}` + the Java overlay in `app/GoNativeActivity.java` (stub: `accessibility_stub.go`). Unlike the desktop trees, mobile ATs navigate a **flat element sequence**, so the shared layer flattens `accessibility.BuildTree` (content → windowHead → menu → overlays) into wire nodes — role/flags int enums kept in sync across Go/ObjC/Java, native-px bounds, clip-culled, container roles dropped (children surface at top level in reading order), empty text/images dropped as decorative — keyed by a stable **handle registry** (mutex-guarded: unlike desktop, action callbacks arrive on the UIKit main thread / Android UI thread, not the main goroutine; dispatch is queued via `DoFromGoroutine`, per the #193 threading model). Update runs after every published dirty frame (`handlePaint`); on Android it is skipped entirely while no accessibility service runs (`AccessibilityManager.isEnabled`, with a turn-on → refresh poke via the pseudo action kind 5), while iOS publishes **unconditionally** — Voice Control and the Xcode Accessibility Inspector run without the VoiceOver flag, so there is no reliable "any AT running" check — made cheap by a Go-side per-handle wire-node diff (unchanged elements send no ObjC dispatch, unchanged order skips the set-elements call). **iOS**: reconciled `BelluiA11yElement` (`UIAccessibilityElement` subclass, MRC) list on the root view — all UIKit work forwarded to the main dispatch queue, frames stored view-local in points and converted lazily per `accessibilityFrame` read, traits from roles, checkable state spoken via value ("checked"/"not checked", `lang.L`); `accessibilityActivate` (NO → VO falls back to a synthesized tap through the normal touch path), increment/decrement, `accessibilityPerformEscape` → dismiss. **VoiceOver text editing (pre-rebrand tracker #570)** works via a Flutter-style input-proxy swap, live-iterated on the real iPad: activate-dispatch mirrors the touch pipeline's *focus* duties (`Entry.Tapped` never focuses — the dispatch calls `canvas.Focus` for `mobile.Keyboardable` targets and `Unfocus` when activating anything else, or a focused entry keeps yanking the keyboard back), and while a text element holds canvas focus the bridge publishes the real `BelluiTextInputView` input view (`belluiKeyboardInputView()` accessor) in its place, overlaid on the entry (zero-frame views are invisible to VO focus; caret hidden via clear tint) — iOS only raises the software keyboard when VO focus sits on the actual first responder, and even then only if first responder is (re)claimed *after* the focus transition settles (one-shot `belluiKeyboardExpectRaise` handshake → `accessibilityElementDidBecomeFocused` re-claims 0.6s later, skipped when `keyboardHeight > 0` already). Keyboard-dismiss pulls VO focus back to the proxy (`resignFirstResponder` override, 0.4s, only while still overlaid); swap-back hands the cursor to the entry's element only when it was on the proxy (`UIAccessibilityFocusedElement` guard). A pure focus change must reach `BelluiA11ySetElements` even with unchanged order (`iosA11yLastFocusText` in the Go diff). **Android**: a **virtual-node `AccessibilityNodeProvider`** (pre-rebrand tracker #1104, the ExploreByTouchHelper/Flutter/Compose model) on ONE full-screen touch-transparent host View (`A11yHostView`, decor-attached): each commit reconciles per-node state records (`A11yProxy`) keyed by the stable Go handles, and the provider builds `AccessibilityNodeInfo`s from them on demand — so TalkBack can re-resolve any cached node id regardless of per-frame churn (the former per-node real-View overlay's removeView/addView invalidated the id TalkBack's scroll pipeline had cached → `AccessibilityInteractionClient` null → two-finger scroll dead). Accessibility focus and touch-exploration hover are owned by the bridge (ACTION_ACCESSIBILITY_FOCUS/CLEAR handled in the provider with events routed via `getParent().requestSendAccessibilityEvent` so ViewRootImpl tracks the virtual focus; `dispatchHoverEvent` maps hovers to virtual ids); a commit fires one explicit `TYPE_WINDOW_CONTENT_CHANGED(SUBTREE)` (no real child Views = no framework auto-invalidation) and an AT scroll action answers with an optimistic `TYPE_VIEW_SCROLLED`. Value/hint/state flags and role→class mapping (`EditText`/`SeekBar`/`CheckBox`/... + `setHeading`/`setPassword`/`setHintText` API-guarded) are unchanged; actions dispatch from the provider (never from real touches) → `accessibilityAction` JNI up-call → `app.SetAccessibilityActionHandler`; commit diffs a signature to skip redundant rebuilds. **Custom accessibility actions (pre-rebrand tracker #1025, Android)**: a declared widget action with no standard semantic (Entry/RichEntry's `undo`/`redo` — declared via `core.AccessibleActioner`, gated on history/read-only/password like the context menu) rides the wire node as (registry id, localized label) pairs (`mobileA11yCustomActions`, the mobile mirror of darwin's `a11yCustomActions`; press-mapped/increment/decrement/dismiss excluded) and is registered by the Java delegate as an `AccessibilityNodeInfo.AccessibilityAction` (id `A11Y_CUSTOM_ACTION_BASE + id`) in TalkBack's actions menu, dispatched back through the existing int-kind up-call as `mobileA11yActionCustom + id` and re-validated against the node's current declaration. darwin (VoiceOver rotor, pre-rebrand tracker #501) and Linux AT-SPI pick the same declarations up data-driven for free; UIA has no custom-action surface; the iOS `UIAccessibilityCustomAction` mapping is a follow-up. **Visual-layout sidecar (pre-rebrand tracker #995, Android)**: the FOCUSED editable node additionally publishes a bounded per-frame sidecar (`mobileA11yTextLayout`, rides the wire as the `addAccessibilityNodeV5` encoded string; V-versioned add methods degrade V5→V1 on older embedded dexes) when the widget implements `core.AccessibleTextLayouter`: visual line boundaries caret ±100 lines feed `MOVEMENT_GRANULARITY_LINE` traversal (legacy TalkBack < ~14 can't self-compute soft-wrap lines; outside the window it falls back to the logical/paragraph handling) and per-UTF-16-char rectangles around the selection (≤256, surrogate pairs repeat their rune's rect) serve `EXTRA_DATA_TEXT_CHARACTER_LOCATION_KEY` — the request is synchronous on the UI thread, so the per-frame push is the optimistic-apply analog; uncovered chars answer null rects and TalkBack falls back to element bounds. Announcements (pre-rebrand tracker #525) wired on both: `UIAccessibilityAnnouncementNotification` (polite = queued attributed string) / `announceForAccessibility`. The Java half ships via the gendex-embedded dex — regenerate the in-repo `cmd/bellui/internal/mobile/dex.go` (`go run gendex/gendex.go -o dex.go` with `ANDROID_HOME` set) after touching `GoNativeActivity.java`.
- **macOS NSAccessibility backend (pre-rebrand tracker #485, `-tags accessibility` + darwin)** — `internal/driver/glfw/accessibility_darwin.{go,h,m}` (+ `accessibility_stub.go` for other builds): after every dirty-window repaint (`drawSingleFrame`) and on `Show`, `window.updateAccessibility()` feeds `accessibility.CanvasNodes(w.canvas, w.canvas.menu)` into an ObjC bridge of `NSAccessibilityElement` subclasses attached to the GLFW content view (per-view associated roots + one-time swizzle of `accessibilityChildren`/`accessibilityFocusedUIElement`, so multiple windows don't share state). Elements are **reconciled, not rebuilt**: keyed by `CanvasObject` identity (virtual nodes — RichText headings — by `VirtualID`), props diffed in ObjC (AX notifications only on real changes) so VoiceOver's cursor survives unrelated repaints; nodes wholly outside their `Clip` are culled with their subtree, except the keyboard-focused object, which stays alive so scrolling it out of view doesn't drop the VO cursor. Subroles: password → `AXSecureTextField`, list → `AXContentList`, tree row → `AXOutlineRow` + `AXDisclosing`/`AXDisclosureLevel` (settable disclosure fires expand/collapse); `RoleHeading` → `AXHeading` with the level as `AXValue` (WebKit convention, feeds the heading rotor). Screen frames are computed lazily in `accessibilityFrame` from the stored local frame (dp × `canvas.Scale()` = window points), so window moves need no tree update. AXPress routes back via a handle registry → `PerformAccessibleAction(press/toggle/select/dismiss)` or `Tapped` fallback; AXIncrement/AXDecrement fire the `increment`/`decrement` actions (sliders, spinboxes), and every other declared action (expand/collapse/rename/delete/…) is offered data-driven as an `NSAccessibilityCustomAction` in VoiceOver's actions rotor (pre-rebrand tracker #501); AX focus → `canvas.Focus`; all arrive on the main goroutine inside `WaitEventsTimeout` (same model as GLFW input callbacks — no locks). Text fields speak the NSAccessibility text protocol (pre-rebrand tracker #501) via `core.AccessibleTexter` (implemented by `Entry`, and read-only by selectable `Label`/`RichText` (pre-rebrand tracker #556) — selection get/set through the shared `selectable` helper, `ReplaceAccessibleSelection` no-ops; rune-offset contract, password fields return the mask): character count, selection/caret line queries, settable selection range and text — mutations route through `Entry.Select`/`ApplyEdits` (gated, one undo step); `accessibility_text_darwin.go` answers queries through a single-entry cached text index (`internal/accessibility.TextIndex`, hoisted from glfw in pre-rebrand tracker #992: rune slice + newline/astral/grapheme offsets, one O(n) build per text version, O(log) queries — pre-rebrand tracker #555; the standalone `BuildTextIndex` serves the AT-SPI per-node model) keyed on **string-data-pointer identity** (Go string `==` has no same-pointer fast path; the rope's memoized string keeps identity stable between edits), and the reconcile diffs rune-space selection to post `AXSelectedTextChanged`. Teardown funnels through `destroyWindow` → `cleanupAccessibilityForWindow`. The ObjC is MRC (no ARC): parents retain children via `childElements`, back-refs are `assign`.
- **Linux AT-SPI2 backend (pre-rebrand tracker #981, `-tags accessibility` + linux)** — `internal/driver/glfw/atspi_linux.go` + `accessibility_linux.go` + `atspi_{roles,cache,p1,p3}_linux.go`: a **pure-Go** AT-SPI2 provider speaking the `org.a11y.atspi.*` D-Bus protocol directly over godbus — no cgo, no AccessKit (route de-risked by the `hack/atspiprobe` spike, pre-rebrand tracker #489/#982). One application root per process (Socket.Embed handshake against the registry; degrades to a no-op when no a11y bus exists), one frame subtree per window, reconciled per dirty frame from `accessibility.CanvasNodes` keyed by CanvasObject/NodeID like the other backends — but D-Bus method handlers run on **godbus goroutines**, so every read is served from reconcile-time snapshots under the provider mutex and mutations hop back via `bellui.Do`. P0 (pre-rebrand tracker #985): Accessible/Component/roles/states/extents (Wayland has no screen origin — screen coords collapse to window-relative), focus + window-activate events, clip-culling with the focused node exempt. P1 (pre-rebrand tracker #986): Action, Value (property-only), Text/EditableText over a **per-node** `accessibility.TextIndex` (unlike darwin/windows' single-entry focused-field cache) with O(edit) text-changed diffs. P2 (pre-rebrand tracker #987): the `org.a11y.atspi.Cache` GetItems fast path + mandatory Add/RemoveAccessible bookkeeping (GNOME bug 650090). P3 (pre-rebrand tracker #988): **Selection** on item containers (role-based; SelectChild dispatches the item's `select` action; deselection reported honestly — no deselect affordance exists), **Table** on `AccessibleGridDimensioner` grids (full virtual extent, index↔coordinate math, null header accessors) and **TableCell** on `AccessibleGridItem` cells (span/position/owning-table, the grid ancestor threaded through the reconcile), plus tree outline relations — flat rows with levels get `NODE_CHILD_OF`/`NODE_PARENT_OF` in `GetRelationSet` (GTK flat-tree convention) recomputed per reconcile. Off-viewport `Table.GetAccessibleAt` realizes the cell through the neutral `accessibility.RealizeCell` seam (pre-rebrand tracker #637) via `bellui.DoAndWait` (the one handler that must reach the main goroutine; the provider mutex is never held across the hop — the reconcile takes it there), cached per window keyed by stable identity (FIFO, `accessibility.RealizedCap`) and **promoted** into the reconcile map when the cell scrolls into view so its path survives. Announcements (pre-rebrand tracker #525) emit from the application root. Live-verified with `busctl` against a GNOME/Wayland session (`hack/a11yprobe` + `hack/a11yrealizeprobe`; recipe in the a11yprobe README); Orca table-navigation speech pass tracked in pre-rebrand tracker #1063.

- **Keyboard Tab-ring guarantees vs embedded content (#126)** — the Tab ring's contract is: plain Tab / Shift+Tab always reach the next focusable, *unless* the focused object is an `event.Tabbable` answering `AcceptsTab() == true` — the widget then owns Tab (multiline `Entry`, `DAGCanvas`, and the Linux webview host). A widget claiming Tab would recreate the WCAG 2.1.2 trap the ring exists to prevent, so the drivers give every such widget the same exit (#340): **Ctrl+Tab / Ctrl+Shift+Tab** move focus out of it (`internal/driver.TabDirection`, used by the glfw, embedded and mobile drivers). On a widget that does not claim Tab, Ctrl+Tab stays on the shortcut path so apps can bind it; on a widget that does, the escape wins over a main-menu or widget binding for the same keys. The CEF composited host also makes the escape in its own `KeyDown` (so it works with no page alive), and the glfw driver treats a Tab press whose `KeyDown` moved focus as handled — no second move, no shortcut, no `TypedKey`; an inert host (no engine) declines the capture so it cannot strand focus. Browsers keep Ctrl+Tab for their own tab switching, so on the web (wasm) build that escape never reaches the page; the second exit works everywhere, the web included (#357): **Escape, then Tab / Shift+Tab** (`internal/driver.TabEscape`, the CodeMirror/Monaco convention). Escape keeps its default meaning first — an Escape that closes a pop-up or dialog, or that the focused widget uses itself (`event.EscapeHandler`), does not arm it — and any key other than a modifier between the Escape and the Tab cancels it. This is the embedded-browser convention (F6/Ctrl+Tab in every major browser's embedding guidance) and the exact "documented method to exit" WCAG 2.1.2 permits. `widget.NativeViewHost` remains the opposite ruling — not a Tab stop at all — because there the OS owns the keyboard and no exit could be guaranteed.
