# Rendering & Canvas

Fork-specific design detail for this area. Issue numbers refer to the Bellui
Backlog.

### Text-Along-Path
`canvas.TextOnPath` and `canvas.NewTextOnPath(text, color, buildPath)` — renders text along an arbitrary path with per-glyph positioning and rotation. Path construction via `MoveTo`/`LineTo`/`QuadTo`/`CubicTo`/`Close` (same API as `canvas.Path`). Arc-length parameterized glyph placement via `PathSampler`. Configurable `Offset` (starting distance along path) and `BaselineShift` (perpendicular offset from path). Per-glyph rendering: each glyph is shaped via HarfBuzz, rendered to a temp image, then affine-transformed (rotated + translated) onto the output. GL and software painter support.

### Per-Character Styled Text
`canvas.StyledText` and `canvas.NewStyledText(runs, defaultColor)` — multi-styled inline text at the canvas level. `TextRun` struct with independent `Text`, `Color`, `TextSize`, `TextStyle`, and `FontSource` per run. Zero-value fields inherit from `StyledText` defaults. Single-line primitive (wrapping is left to `widget.RichText`). Shared baseline across runs (max ascent). GL and software painter support.

### Streaming Rasters — Video Frame Upload (#34)
`canvas.Raster.Streaming` + `SetPixels(pix, w, h)` is the video-playback path: the painter keeps the raster's GPU texture alive across frames (`internal/driver/common.Canvas.freeObject` deliberately skips streaming rasters) and re-uploads only the pixels. It used to be **GL-only**, which on the default WebGPU desktop build meant a nil-`Generator` raster — the documented SetPixels-only usage — **segfaulted on first paint**, and supplying a `Generator` to dodge that left the image **frozen on frame 1** (the texture was cached forever). Both are fixed:
- **`Raster.PixelImage(w, h) image.Image`** (`canvas/raster.go`) is the single pixel source every painter reads: SetPixels data when present (copied, so a caller may reuse its frame buffer), else `Generator`, else **nil** — so a raster with neither is skipped rather than dereferenced. The GL (`newGlRasterTexture`), WebGPU (`rasterizeRaster`) and software (`drawRaster`) paths all route through it; a nil return means "no content this frame".
- **WebGPU honours streaming**: `Device.WriteTexturePixels` is the `TexSubImage2D` counterpart (`queue.WriteTexture`), `Texture` now carries its allocated `w,h` (`Texture.Size()`) so a same-size frame updates **in place** and a size change drops the texture (`dropTexture` → `ReleaseTextureAfterFrame`, so draws already recorded this frame stay valid) for `getTexture` to reallocate. `painter.drawRaster` calls `updateStreamingTexture` before drawing, mirroring the GL painter. SetPixels data uploads **without a copy**, under `StreamMu`; the Generator path rasterizes outside the lock.
- GL fix alongside: `newGlRasterTexture` recorded `StreamTexW/H` from the *widget's* size, so a video whose frame size differed from the widget ping-ponged between delete and recreate and never updated in place. It now records the dimensions actually uploaded.
- **`Translucency` now applies to rasters on every painter (#38)**: the GL painter always passed `Raster.Alpha()`, but the WebGPU *and* software painters passed a hard-coded opaque `1.0`, so `Raster.Translucency` silently did nothing on the default desktop build and in every software-rendered test. Both now pass `Alpha()`, matching `canvas.Image`.
- **Verify**: `hack/rasterstream` (`-auto` captures the canvas twice and reports per-raster changed-pixel counts — 0 = frozen — then compares an opaque square against a `Translucency: 0.5` one). Confirmed on-GPU under both painters, and confirmed to reproduce the original segfault, the freeze and the ignored translucency when the fixes are stashed.

### Y'CbCr Video Frames (#1107)
`Raster.SetYCbCr(img, matrix, fullRange)` holds a decoded video frame as its planes, so a player need not convert to RGBA on the processor. **Experimental**: the shape follows x/mmedia; `SetPixels` is the stable path. `SetYCbCr` and `SetPixels` replace each other.
- **One conversion, three places.** `internal/ycbcr` owns the maths: `Coefficients(matrix, fullRange)` (an affine map from unorm samples to RGB, rows `(y, cb, cr, offset)`) and `ToRGBA` (fixed point). `PixelImage` uses `ToRGBA`, so the software painter, every painter's first paint, and capture all agree. Go's own `image.YCbCr` conversion is JFIF (BT.601, full range) and would get most video wrong.
- **WebGPU converts on the GPU, into an ordinary texture.** A Y'CbCr raster's cached `Texture` is RGBA8 unorm (render-attachment usable) with `yuvPlanes` hung off it: three R8 plane textures, a 48-byte uniform buffer and a bind group, released with the texture. Each frame writes the planes and runs `yuv.wgsl` (one triangle from the vertex index) into the RGBA texture; the `simple` shader then draws it, so clipping, rounding, opacity, transforms and capture need nothing new. The pass is **submitted on its own command buffer** ahead of the frame's, which keeps the frame's render pass unbroken (a break costs a full-surface store and load on tiling GPUs). The target is unorm, not the surface format, so it stores the bytes an RGBA upload would have. Any subsample ratio works: chroma textures are sized by `ycbcr.ChromaSize` and sampled with normalised coordinates (linear filtering, chroma treated as centre-sited). If the device cannot make the textures, `createTexture` falls back to `PixelImage`.
- **GL converts on the processor** in `updateStreamingTexture` (no shader: the GL painter is being removed).
- **Pinned by colour bars**: `internal/ycbcr/ycbcrtest` holds the 75% bars as FFmpeg encodes them (BT.601/BT.709/BT.2020, limited and full), checked against the published tables. Every painter's test draws them; a second frame uses the bars in reverse order, because every set encodes the same colours and a frozen first frame would otherwise pass.

### Image Colour Profiles (#802, part of #373)
`canvas.Image` converts a decoded PNG or JPEG to sRGB from the colour profile the file declares (`internal/colorprofile`, called from `canvas/image.go` `decodeImage`). Bellui draws untagged 8-bit sRGB, so without this a Display P3 or Adobe RGB photo was drawn as if its values were sRGB: washed out or shifted.
- **Read:** PNG `iCCP` (zlib, capped at 4 MB), `sRGB`, `gAMA` + `cHRM`; JPEG `APP2` `ICC_PROFILE` segments in any order. A `gAMA` of 1/2.2 with no `cHRM` is taken as sRGB, as browsers do. Not read: PNG `cICP`, EXIF's colour-space tag, WebP/AVIF profiles.
- **Converted:** RGB matrix/TRC profiles (primaries plus `curv`/`para` tone curves, which covers Display P3, Adobe RGB, ProPhoto and nearly every camera and display profile), relative colorimetric, clipped to sRGB. **Not converted, drawn as sRGB and logged once per kind:** lookup-table (`A2B0`-only), CMYK, Lab and greyscale profiles. An embedded profile that matches sRGB is recognised and skipped.
- **Only images Bellui decodes:** an `image.Image` an app sets on `canvas.Image.Image` or a `Raster` is drawn as given; the app owns its colour space.
- **Proof:** `TestToSRGB_MatchesColorSync` compares against macOS ColorSync's conversion of the same tagged grids (testdata holds both): every channel within one 8-bit step. The test profiles are built by the tests, so no third-party ICC data is in the repo.
- **Cost** (M3 Max, 16 cores, a 12 MP JPEG): Display P3 adds 12 ms to a 116 ms decode; an embedded sRGB profile adds 18 µs; no profile, nothing measurable. Not measured on a phone.
- Converting to sRGB clips wide-gamut colours. Wide-gamut output is #803's design question; the converter takes its source profile, so a different destination space can be added there.

### Transforms (#997)
`core.Transformable` objects compose: a child's world transform is `parent.worldTransform * Translate(child.Position()) * child.Transform()`. Every part of the pipeline uses that one product.
- **Drawing:** each object is drawn from its paint origin, the world transform's image of its (0, 0) (`RenderCacheNode.PaintOrigin`), with the transform's linear part applied about it (the GPU painters' `anchor`, the software painter's `drawTransformed`). So a pure translation moves an object, a `NewRotationAround` pivot is honoured, and the children of a transformed widget turn with it as one piece. Before #997 the GPU painters turned each leaf about its own origin and dropped every translation, and the software painter dropped a pure translation.
- **Hit-testing** (`driver.LocalHitPoint`, shared by the tree walk and the spatial index) maps the pointer through the inverse world transform.
- **Clips:** the walk carries what the transforms above it do to walk positions, so a clipping object clips its children where it is drawn: its box moved, or under a rotation the bounding box of where it is drawn (`common.WorldBox`). A rounded clip is exact under any transform, because its stencil is stamped with the object's transform (set before the clips since #997; it used to be the last drawn object's).
- **Partial repaint and culling:** the region and the dirty-region skip use the world box (`common.PaintBounds`); the clip cull is off at and below a transformed object.
- **Positions (#1003, owner's decision):** `Driver.AbsolutePositionForObject` stays the position from layout, the sum of positions, and ignores transforms. It is a v1 method, and changing what it returns would silently change apps that call it (`TestAbsolutePositionForObject_IgnoresTransforms` pins this). Where a point of an object is drawn is `bellui.AbsolutePositionForPoint(obj, pos)`, and its inverse `bellui.PositionForAbsolutePoint`; a driver provides them through the optional `PositionMappingDriver`, and without it they fall back to the layout position. The main module's popups, menus and tooltips anchor through them, and the touch scroll chain relocates through the inverse. Two places keep the layout position on purpose: `driver.ObjectAtPositionMatching`'s rectangle (its contract is `AbsolutePositionForObject`'s space) and the popup menus' own fit checks (popups are never transformed). Still to move: the `x/` modules, which pin a release without the new functions (#1010), and the selection handles' offsets, which are not rotated or scaled with their text (#1008).
- **RepaintBoundary under a rotation or scale (#1003, owner's decision):** its texture is blitted axis-aligned and unscaled, so while its world transform does more than move it (a rotation, a scale or a skew, on it or above it) the walks draw its subtree directly (`RenderCacheNode.CachesAsBoundary`). The texture is used again once the transform is back to a move. The cost is no caching for the length of, say, a card's tilt.
- **Rectangle clips under a rotation (#1003, owner's decision):** a scissor is axis-aligned, so alone it clips a turned rectangle clip (a `ClipToBounds` container or a scroll whose world transform turns or skews it) to the box around it, and its children show in that box's corners. Such a clip is also a stencil clip with no corner radius, stamped with its transform (`common.PaintClips`), nested in any rounded clip around it by stencil depth (#1012); the scissor stays as its bound. A move or a scale keeps the scissor alone, which is exact there. The cost is one stencil stamp and erase per turned clip per frame, only while it is turned. The hit-test follows: below a turned clip the tree walk and the spatial index test the pointer against the turned rectangle as well (`driver.turnedClipMisses`, `SpatialIndex.insideCuts`), so what is clipped away cannot be hit. Rounded corners stay coarse for the hit-test, and the software painter clips to the box (it has no stencil clips at all).
- **Verify:** `TestWorldTransformDraws` in `internal/driver/glfw/realloop` (darwin, WebGPU, and GL under `-tags gl`), and `hack/swipecardprobe -auto -composite`, which prints how far the GPU painter draws the label from where the software painter does.

### Out of Sight (#1061)
Something hidden can keep running on its own clock: an animation, a video, a live chart on a tab that is not selected. Two things keep that from costing frames.
- **A refresh out of sight draws no frame**, with nothing to opt into. Walks record what is out of sight (`common.Canvas.noteOffscreen`): a hidden object they skip, and a hidden object whose node leaves the tree. The second is how an unselected tab goes: `AppTabs` hides its content *and* stops listing it in `Objects()`, so no walk sees it as a hidden child. Everything under the hidden object is recorded with it, from the renderers that exist. `Canvas.Refresh` still queues such an object, so the frame that shows it again frees what the refresh made stale, but marks nothing dirty while that hidden object stays hidden. Only positive records count: an object merely out of the tree may be a new one no walk has placed yet, or a child a renderer swapped back in and refreshes alone, and skipping those would show stale content (`TestRefreshOfObjectSwappedBackDraws`). What left the tree for good is dropped once nothing has found it for `offscreenKeep`, and at once by the next full walk when the parent it was recorded under left the trees too (#1074): replaced content goes with the frame that shows what replaced it, as an idle app makes no walk a minute later. The spare hit-test index lets go of its objects for the same reason. The same walk releases replaced content from the widget caches (#1075), and frees its textures and WebGPU boundary targets (#1082): at once on WebGPU when no frame is open (`gpu.BetweenFramesPainter`), as no unsubmitted command then samples them, and at the start of the next frame on GL, which needs its context. The texture cache otherwise kept each image, with its decoded pixels, until a frame a minute after it was last drawn. Measured on DaySong (player#389): an unselected tab with two animated glows drew 10 frames a second on main, 1 with this.
- **`bellui.Release(obj)`** (owner's pick of an explicit call over an automatic trigger, 2026-11-07; shape proposed in the PR for #1083) lets go at once of content the app dropped from a container, as the MD3 gallery's `setPage` does by assigning `Objects`. It runs the same release as a replaced tree (#1075, #1082) on obj's canvas at the next frame, which it marks dirty: everything that canvas no longer shows, not only obj, since walking down from obj misses what a widget holds outside its renderer's objects (a list's pooled rows, the buttons tabs measure). So a pooled row elsewhere gets a new renderer when next shown, once per call. Nothing triggers it on a container change: lists take rows out of the tree to reuse them, and a sweep there would rebuild their renderers on every scroll (`TestListPoolKeepsRenderersAcrossScrolls`). The release also unfocuses a focused object it leaves out: the focus manager kept it, and sent it the keys typed after, and only a replaced tree gets a new focus manager. A driver provides it through the optional `ReleasingDriver`; without one the content goes when the caches expire it.
- **`bellui.IsOnScreen(obj)`** (owner's pick of the query over a notification, 2026-11-07) is for the work done *before* refreshing: decoding, computing values. A driver answers it through the optional `OnScreenDriver`: the window is shown, the last walk placed obj (`Canvas.InSight`), and obj and every node above it are still visible, so a hide or a tab switch reads false at once. A show or a tab selected again reads true at once too (#1069), before the walk that places obj: that walk is the paint of the next frame, and the ticks run before it, so a consumer reading false there skipped its values for that frame, which then drew the tab as it was when hidden (measured on DaySong, player#389: one frame, 6.5 ms at 144 Hz). `Canvas.shownAgain` answers it from the out-of-sight record, which now keeps the hidden object's parent: the hidden object is shown, its parent is in sight and still lists it, and obj is still under it with nothing between hidden. The cost is a walk of that subtree, through existing renderers, per question until the walk (`BenchmarkInSightOnReturn`: about 1 µs for a 10-row tab, 160 µs for 1000 rows on an M3 Max), and only in that one frame. An object added under the hidden object since the walk that recorded it is not found, and reads true from the walk that places it. Scrolled out of a scroll's view still counts as on screen (owner, 2026-11-07). It names visibility, never "stop": each consumer decides, and `ProgressBarInfinite` and `Activity` skip their ticks while it is false, keeping their place in time. A query, not a notification, because every consumer named has a clock of its own; what would call for a notification is one that must react with no clock of its own. The test driver answers by walking a window's visible objects and existing renderers.

### Rendering Engine Enhancements
- **Shader-based ripple** (`canvas.Ripple`) — radial touch feedback with SDF-based rounded-corner clipping. Custom GLSL shader.
- **FBO support** — Framebuffer Objects for off-screen rendering. `CreateFramebuffer`, `BindFramebuffer`, etc.
- **Gaussian blur shadows** (`canvas.BoxShadow`) — 9-tap separable blur via FBO ping-pong. Replaces gradient-strip shadows for `ShadowAround`.
- **Backdrop blur** (`canvas.BackdropBlur`) — Frosted glass effect. Reads framebuffer pixels, blurs, composites. Opt-in, GPU readback is expensive.
- **Stencil clipping** — `StartRoundedClipping`/`StopRoundedClipping` on Painter. Auto-detected via `RoundedClipCornerRadius()` on renderers. Card content clips to rounded corners. Rounded clips nest by depth (#1012): a clip at depth d stamps d only where its enclosing clip left d-1, and its Stop decrements back, so an inner clip narrows the outer one and the outer applies again after it. Outside every clip the depth bits stay zero, so an unnested clip clears nothing (#466). The 8-bit stencil is split (#1015, `internal/painter/stencil.go`): a path fill or path clip counts its winding in the low 4 bits, modulo 16, and only where the innermost clip's depth is, so it is cut by the rounded clips around it. Depth sits in the high 4 bits as a Gray code, because a stencil increment lands in the low bits and a replace writes the value it compares against: consecutive depths differ in one bit, so a stamp tests the other three. A path clip is a clip level of its own: after its winding pass, one full-target draw sets the depth bits to the next level wherever the winding is not zero, and its Stop erases that level over the whole target. So a rounded clip or a path inside a path clip is cut by it too. Limits, pinned by `TestRoundedClipsNestToMaxDepth` and `TestClipDepthCodes`: clips nest 14 deep (one code is kept for a skipped clip), and a deeper one is logged once and cut by the clip around it only; a winding count of 16 reads as outside the path. Before, both shared the whole stencil: a path inside a rounded clip was confined to the path only, and on GL was not drawn at all, and anything inside a path clip dropped it.
- **Group opacity** (#977) — an object implementing `core.OpacityGroup` (`container.Opacity` is the ready-made one) has its whole subtree drawn with alpha multiplied by `GroupOpacity()`; groups nest, multiplying. Both paint walks keep it on `internal/driver.OpacityStack`, pushed and popped for every node regardless of culling, and the painter hears only of changes. The desktop walk also dims disabled widgets to 38% through the same stack (the mobile walk does not dim them). A `RepaintBoundary` inside a group caches its content at full opacity and its blit carries the group's opacity, so the opacity applies once and changing it needs no re-render. Each draw is faded on its own: overlapping children show through each other, unlike an offscreen composite. Opacity 0 skips the draws, since the painters read a group opacity of 0 as unset. The software painter behind test images (and headless capture) keeps the same stack and blends each draw by it, drawing the object into a layer the size of its clip and compositing that through a uniform mask; it does not dim disabled widgets (#1139).
- **Multi-stop gradients** — `GradientStop` type with `Position` (0-1). `LinearGradient.Stops` and `RadialGradient.Stops` fields.
- **RepaintBoundary** (`container.RepaintBoundary`) — FBO-cached subtree isolation. Wrapping a subtree in `NewRepaintBoundary(content)` renders it into an off-screen framebuffer. When the subtree is unchanged, it blits the cached texture as a single quad instead of walking/drawing every object. Dirty propagation: `Refresh()` on any descendant marks only the nearest ancestor boundary's FBO as dirty. Supports GLFW and mobile drivers. Scale changes invalidate all boundary FBOs. A boundary's texture starts at its position snapped down to a device pixel, less a 2 px margin for anti-aliased fringes, and is blitted there, so the copy lands pixel for pixel; its content is rendered at the sub-pixel offset the boundary has, and a boundary that moves by a fraction of a pixel is rendered again. Drawn through a boundary, content then matches drawing it in place except for ±1 on partly transparent edges, where a cache composites over transparency before the background (#570; GL also #580). Overflow past the margin, such as a blurred shadow, is cut at the texture's edge.
- **Dirty-region culling** (on by default on desktop and in packaged Android and iOS apps, which paint with WebGPU; off on the web, under the GL painter on Android and iOS, and under the `mobile` test tag (`internal/build/partialrepaint_off.go`); `partialrepaint` / `nopartialrepaint` build tags force it on or off, and `BELLUI_PARTIAL_REPAINT=0` turns it off at run time) — A persistent full-canvas texture (`DirtyRegionPainter`, on the GL and WebGPU painters) retains frame content between frames. `Canvas.PartialDirtyRegion` computes what to redraw: the old and new painted bounds of every object refreshed or moved since the last paint (a box shadow's bounds include its blur), plus where objects that left the tree were drawn. Only that region is cleared and redrawn; overlays are drawn whole on the surface every frame. The region walk culls what the paint walk culls, and is skipped when the refreshed objects already cover the canvas, so the frame is a full repaint for no more CPU than one (#496). It walks only from the objects that reported a change: Bellui's canvas objects, containers and widgets tell their canvas when they are moved, resized or hidden, and a container when its objects change (`MarkPlacementDirty`), as a refresh does. What no node can report walks everything: showing a hidden object or setting a canvas object's transform (counted by `internal/paintgen`), or a replaced tree. A widget that implements `core.Transformable` reports its own node when it refreshes, so a widget outside Bellui changes its transform and calls `Refresh` (#1072). Setting an object's `Hidden` field and refreshing it reports only the refresh: shown that way, the region walks the parent the object was last skipped under as hidden; hidden that way, it walks from above the hidden ancestor (#619). An object that cannot report, such as an app's own `CanvasObject` type, has its parent walked every frame (#599). The canvas texture is cleared fully when it is new or resized, and on every frame once a resume has made its retention unreliable.
  - *Verifying it on a real GPU:* run with `BELLUI_PARTIAL_VERIFY=N` (desktop driver; partial repaint must be on). Every N frames the window is captured as partial repaint left it, then after a forced full repaint, and the two are compared; any differing pixel is logged (and saved as PNGs under `BELLUI_PARTIAL_VERIFY_DIR`), with a summary at exit. A check whose two full repaints differ is counted as *unstable* — the scene changed during it, as a video decoded on another goroutine does — and proves nothing. `N=1` checks every frame but leaves each check one partial frame to get wrong; a larger N lets errors accumulate across partial frames.
- **Frames that cannot begin** — On macOS a window that is fully covered, or whose app is hidden, has no surface, so the WebGPU painter begins no frame and the paint shows nothing. The desktop driver then marks the canvas dirty again and retries every 100 ms (`paintRetry`), not every frame, until a frame begins; the painters make that frame a full repaint (#564, #595). Before this a change made while the window was covered stayed off screen once it was uncovered, until something else changed (#864). `Canvas.Capture` returns nil for such a frame (#631). Neither driver walks the window while the painter reports no open frame (`gpu.FramePainter`): every draw would be refused, and each rounded clip's stencil write was logged as a dropped draw (#1019). The walk resumes with the retry. Verify with `HIDE=1 DELAY_MS=1500 go run ./hack/stalepaintprobe`.
- **GPU-accelerated 3D** — `canvas.Scene3D` rendered via GL pipeline in the GL painter. Meshes expanded to interleaved VBOs (position + normal + per-face color, stride 10 floats). Dedicated `scene3d.vert`/`scene3d.frag` shaders with MVP transform and Phong-style ambient+diffuse lighting. Rendered to FBO with depth texture attachment for hardware z-buffering. FBO color texture cached via existing texture pipeline — only re-rendered on `Refresh()`. Software `Scene3D.Render()` path preserved for the software painter. `canvas.PerspectiveMatrix()` and `canvas.LookAtMatrix()` exported.
