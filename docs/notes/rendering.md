# Rendering & Canvas

Fork-specific design detail for this area. Issue numbers refer to the Bellui
Backlog.

### Text-Along-Path
`canvas.TextOnPath` and `canvas.NewTextOnPath(text, color, buildPath)` — renders text along an arbitrary path with per-glyph positioning and rotation. Path construction via `MoveTo`/`LineTo`/`QuadTo`/`CubicTo`/`Close` (same API as `canvas.Path`). Arc-length parameterized glyph placement via `PathSampler`. Configurable `Offset` (starting distance along path) and `BaselineShift` (perpendicular offset from path). Per-glyph rendering: each glyph is shaped via HarfBuzz, rendered to a temp image, then affine-transformed (rotated + translated) onto the output. GL and software painter support.

### Per-Character Styled Text
`canvas.StyledText` and `canvas.NewStyledText(runs, defaultColor)` — multi-styled inline text at the canvas level. `TextRun` struct with independent `Text`, `Color`, `TextSize`, `TextStyle`, and `FontSource` per run. Zero-value fields inherit from `StyledText` defaults. Single-line primitive (wrapping is left to `widget.RichText`). Shared baseline across runs (max ascent). GL and software painter support.

### Streaming Rasters — Video Frame Upload (#34)
`canvas.Raster.Streaming` + `SetPixels(pix, w, h)` is the video-playback path: the painter keeps the raster's GPU texture alive across frames (`internal/driver/common.Canvas.freeObject` deliberately skips streaming rasters) and re-uploads only the pixels. It used to be **GL-only**, which on the default WebGPU desktop build meant a nil-`Generator` raster — the documented SetPixels-only usage — **segfaulted on first paint**, and supplying a `Generator` to dodge that left the image **frozen on frame 1** (the texture was cached forever). Both are fixed:
- **`Raster.PixelImage(w, h) image.Image`** (`canvas/raster.go`) is the single pixel source every painter reads: SetPixels data when present (copied, so a caller may reuse its frame buffer), else `Generator`, else **nil** — so a raster with neither is skipped rather than dereferenced. The GL (`newGlRasterTexture`), WebGPU (`rasterizeRaster`) and software (`drawRaster`) paths all route through it; a nil return means "no content this frame".
- **WebGPU honours streaming**: `Device.WriteTexturePixels` is the `TexSubImage2D` counterpart (`queue.WriteTexture`), `Texture` now carries its allocated `w,h` (`Texture.Size()`) so a same-size frame updates **in place** and a size change drops the texture (`dropTexture` → `ReleaseTextureAfterFrame`, so draws already recorded this frame stay valid) for `getTexture` to reallocate. `painter.drawRaster` calls `updateStreamingTexture` before drawing, mirroring the GL painter. SetPixels data uploads **without a copy**, under `StreamMu`; the Generator path rasterizes outside the lock.
- GL fix alongside: `newGlRasterTexture` recorded `StreamTexW/H` from the *widget's* size, so a video whose frame size differed from the widget ping-ponged between delete and recreate and never updated in place. It now records the dimensions actually uploaded.
- **`Translucency` now applies to rasters on every painter (#38)**: the GL painter always passed `Raster.Alpha()`, but the WebGPU *and* software painters passed a hard-coded opaque `1.0`, so `Raster.Translucency` silently did nothing on the default desktop build and in every software-rendered test. Both now pass `Alpha()`, matching `canvas.Image`.
- **Verify**: `hack/rasterstream` (`-auto` captures the canvas twice and reports per-raster changed-pixel counts — 0 = frozen — then compares an opaque square against a `Translucency: 0.5` one). Confirmed on-GPU under both painters, and confirmed to reproduce the original segfault, the freeze and the ignored translucency when the fixes are stashed.

### Image Colour Profiles (#802, part of #373)
`canvas.Image` converts a decoded PNG or JPEG to sRGB from the colour profile the file declares (`internal/colorprofile`, called from `canvas/image.go` `decodeImage`). Bellui draws untagged 8-bit sRGB, so without this a Display P3 or Adobe RGB photo was drawn as if its values were sRGB: washed out or shifted.
- **Read:** PNG `iCCP` (zlib, capped at 4 MB), `sRGB`, `gAMA` + `cHRM`; JPEG `APP2` `ICC_PROFILE` segments in any order. A `gAMA` of 1/2.2 with no `cHRM` is taken as sRGB, as browsers do. Not read: PNG `cICP`, EXIF's colour-space tag, WebP/AVIF profiles.
- **Converted:** RGB matrix/TRC profiles (primaries plus `curv`/`para` tone curves, which covers Display P3, Adobe RGB, ProPhoto and nearly every camera and display profile), relative colorimetric, clipped to sRGB. **Not converted, drawn as sRGB and logged once per kind:** lookup-table (`A2B0`-only), CMYK, Lab and greyscale profiles. An embedded profile that matches sRGB is recognised and skipped.
- **Only images Bellui decodes:** an `image.Image` an app sets on `canvas.Image.Image` or a `Raster` is drawn as given; the app owns its colour space.
- **Proof:** `TestToSRGB_MatchesColorSync` compares against macOS ColorSync's conversion of the same tagged grids (testdata holds both): every channel within one 8-bit step. The test profiles are built by the tests, so no third-party ICC data is in the repo.
- **Cost** (M3 Max, 16 cores, a 12 MP JPEG): Display P3 adds 12 ms to a 116 ms decode; an embedded sRGB profile adds 18 µs; no profile, nothing measurable. Not measured on a phone.
- Converting to sRGB clips wide-gamut colours. Wide-gamut output is #803's design question; the converter takes its source profile, so a different destination space can be added there.

### Transforms (#997)
`core.Transformable` objects compose: a child's world transform is `parent.worldTransform * Translate(child.Position()) * child.Transform()`. Every part of the pipeline uses that one product.
- **Drawing:** each object is drawn from its paint origin, the world transform's image of its (0, 0) (`RenderCacheNode.PaintOrigin`), with the transform's linear part applied about it (the GPU painters' `anchor`, the software painter's `drawTransformed`). So a pure translation moves an object, a `NewRotationAround` pivot is honoured, and the children of a transformed widget turn with it as one piece. Before #997 the GPU painters turned each leaf about its own origin and dropped every translation, and the software painter dropped a pure translation.
- **Hit-testing** (`driver.LocalHitPoint`, shared by the tree walk and the spatial index) maps the pointer through the inverse world transform.
- **Clips:** the walk carries what the transforms above it do to walk positions, so a clipping object clips its children where it is drawn: its box moved, or under a rotation the bounding box of where it is drawn (`common.WorldBox`). A rounded clip is exact under any transform, because its stencil is stamped with the object's transform (set before the clips since #997; it used to be the last drawn object's).
- **Partial repaint and culling:** the region and the dirty-region skip use the world box (`common.PaintBounds`); the clip cull is off at and below a transformed object.
- **Positions (#1003, owner's decision):** `Driver.AbsolutePositionForObject` stays the position from layout, the sum of positions, and ignores transforms. It is a v1 method, and changing what it returns would silently change apps that call it (`TestAbsolutePositionForObject_IgnoresTransforms` pins this). Where a point of an object is drawn is `bellui.AbsolutePositionForPoint(obj, pos)`, and its inverse `bellui.PositionForAbsolutePoint`; a driver provides them through the optional `PositionMappingDriver`, and without it they fall back to the layout position. The main module's popups, menus and tooltips anchor through them, and the touch scroll chain relocates through the inverse. Two places keep the layout position on purpose: `driver.ObjectAtPositionMatching`'s rectangle (its contract is `AbsolutePositionForObject`'s space) and the popup menus' own fit checks (popups are never transformed). Still to move: the `x/` modules, which pin a release without the new functions (#1010), and the selection handles' offsets, which are not rotated or scaled with their text (#1008).
- **Not yet:** a `RepaintBoundary` under a rotation or scale, and exact rectangle clips under a rotation (#1003, undecided).
- **Verify:** `TestWorldTransformDraws` in `internal/driver/glfw/realloop` (darwin, WebGPU, and GL under `-tags gl`), and `hack/swipecardprobe -auto -composite`, which prints how far the GPU painter draws the label from where the software painter does.

### Rendering Engine Enhancements
- **Shader-based ripple** (`canvas.Ripple`) — radial touch feedback with SDF-based rounded-corner clipping. Custom GLSL shader.
- **FBO support** — Framebuffer Objects for off-screen rendering. `CreateFramebuffer`, `BindFramebuffer`, etc.
- **Gaussian blur shadows** (`canvas.BoxShadow`) — 9-tap separable blur via FBO ping-pong. Replaces gradient-strip shadows for `ShadowAround`.
- **Backdrop blur** (`canvas.BackdropBlur`) — Frosted glass effect. Reads framebuffer pixels, blurs, composites. Opt-in, GPU readback is expensive.
- **Stencil clipping** — `StartRoundedClipping`/`StopRoundedClipping` on Painter. Auto-detected via `RoundedClipCornerRadius()` on renderers. Card content clips to rounded corners. Rounded clips nest by depth (#1012): a clip at depth d stamps d only where its enclosing clip left d-1, and its Stop decrements back, so an inner clip narrows the outer one and the outer applies again after it. Outside every clip the stencil stays zero, so an unnested clip clears nothing (#466). A path fill or path clip uses the whole stencil, so afterwards the painter stamps the active rounded clips again; the path's own pixels are confined to the path, not to the rounded clips around it.
- **Group opacity** (#977) — an object implementing `core.OpacityGroup` (`container.Opacity` is the ready-made one) has its whole subtree drawn with alpha multiplied by `GroupOpacity()`; groups nest, multiplying. Both paint walks keep it on `internal/driver.OpacityStack`, pushed and popped for every node regardless of culling, and the painter hears only of changes. The desktop walk also dims disabled widgets to 38% through the same stack (the mobile walk does not dim them). A `RepaintBoundary` inside a group caches its content at full opacity and its blit carries the group's opacity, so the opacity applies once and changing it needs no re-render. Each draw is faded on its own: overlapping children show through each other, unlike an offscreen composite. Opacity 0 skips the draws, since the painters read a group opacity of 0 as unset. The software painter behind test images ignores it.
- **Multi-stop gradients** — `GradientStop` type with `Position` (0-1). `LinearGradient.Stops` and `RadialGradient.Stops` fields.
- **RepaintBoundary** (`container.RepaintBoundary`) — FBO-cached subtree isolation. Wrapping a subtree in `NewRepaintBoundary(content)` renders it into an off-screen framebuffer. When the subtree is unchanged, it blits the cached texture as a single quad instead of walking/drawing every object. Dirty propagation: `Refresh()` on any descendant marks only the nearest ancestor boundary's FBO as dirty. Supports GLFW and mobile drivers. Scale changes invalidate all boundary FBOs. A boundary's texture starts at its position snapped down to a device pixel, less a 2 px margin for anti-aliased fringes, and is blitted there, so the copy lands pixel for pixel; its content is rendered at the sub-pixel offset the boundary has, and a boundary that moves by a fraction of a pixel is rendered again. Drawn through a boundary, content then matches drawing it in place except for ±1 on partly transparent edges, where a cache composites over transparency before the background (#570; GL also #580). Overflow past the margin, such as a blurred shadow, is cut at the texture's edge.
- **Dirty-region culling** (on by default on desktop and in packaged Android and iOS apps, which paint with WebGPU; off on the web, under the GL painter on Android and iOS, and under the `mobile` test tag (`internal/build/partialrepaint_off.go`); `partialrepaint` / `nopartialrepaint` build tags force it on or off, and `BELLUI_PARTIAL_REPAINT=0` turns it off at run time) — A persistent full-canvas texture (`DirtyRegionPainter`, on the GL and WebGPU painters) retains frame content between frames. `Canvas.PartialDirtyRegion` computes what to redraw: the old and new painted bounds of every object refreshed or moved since the last paint (a box shadow's bounds include its blur), plus where objects that left the tree were drawn. Only that region is cleared and redrawn; overlays are drawn whole on the surface every frame. The region walk culls what the paint walk culls, and is skipped when the refreshed objects already cover the canvas, so the frame is a full repaint for no more CPU than one (#496). It walks only from the objects that reported a change: Bellui's canvas objects, containers and widgets tell their canvas when they are moved, resized or hidden, and a container when its objects change (`MarkPlacementDirty`), as a refresh does. What no node can report walks everything: showing a hidden object or setting a transform (counted by `internal/paintgen`), or a replaced tree. Setting an object's `Hidden` field and refreshing it reports only the refresh: shown that way, the region walks the parent the object was last skipped under as hidden; hidden that way, it walks from above the hidden ancestor (#619). An object that cannot report, such as an app's own `CanvasObject` type, has its parent walked every frame (#599). The canvas texture is cleared fully when it is new or resized, and on every frame once a resume has made its retention unreliable.
  - *Verifying it on a real GPU:* run with `BELLUI_PARTIAL_VERIFY=N` (desktop driver; partial repaint must be on). Every N frames the window is captured as partial repaint left it, then after a forced full repaint, and the two are compared; any differing pixel is logged (and saved as PNGs under `BELLUI_PARTIAL_VERIFY_DIR`), with a summary at exit. A check whose two full repaints differ is counted as *unstable* — the scene changed during it, as a video decoded on another goroutine does — and proves nothing. `N=1` checks every frame but leaves each check one partial frame to get wrong; a larger N lets errors accumulate across partial frames.
- **Frames that cannot begin** — On macOS a window that is fully covered, or whose app is hidden, has no surface, so the WebGPU painter begins no frame and the paint shows nothing. The desktop driver then marks the canvas dirty again and retries every 100 ms (`paintRetry`), not every frame, until a frame begins; the painters make that frame a full repaint (#564, #595). Before this a change made while the window was covered stayed off screen once it was uncovered, until something else changed (#864). `Canvas.Capture` returns nil for such a frame (#631). Verify with `HIDE=1 DELAY_MS=1500 go run ./hack/stalepaintprobe`.
- **GPU-accelerated 3D** — `canvas.Scene3D` rendered via GL pipeline in the GL painter. Meshes expanded to interleaved VBOs (position + normal + per-face color, stride 10 floats). Dedicated `scene3d.vert`/`scene3d.frag` shaders with MVP transform and Phong-style ambient+diffuse lighting. Rendered to FBO with depth texture attachment for hardware z-buffering. FBO color texture cached via existing texture pipeline — only re-rendered on `Refresh()`. Software `Scene3D.Render()` path preserved for the software painter. `canvas.PerspectiveMatrix()` and `canvas.LookAtMatrix()` exported.
