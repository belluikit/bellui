### Advanced Text Layout
`bellui.TextStyle` has three new fields for fine-grained text control. All three are **pointer** types with a **nil** sentinel — in struct literals wrap the value with `bellui.Ptr(...)` (e.g. `bellui.TextStyle{Weight: bellui.Ptr(bellui.WeightBold)}`); a bare `bellui.WeightBold` will not compile:
- `Weight *TextWeight` — font weight from 100 (Thin) to 900 (Black). Constants: `WeightThin`, `WeightExtraLight`, `WeightLight`, `WeightNormal` (400), `WeightMedium` (500), `WeightSemiBold` (600), `WeightBold` (700), `WeightExtraBold`, `WeightBlack`. When nil, falls back to the `Bold` bool (Bold=true → WeightBold). Weight >= 600 selects the bold font variant.
- `LineHeightScale *float32` — multiplier for line height. nil (or a pointer to 1.0) = default (font-metric-derived). Values > 1.0 increase vertical space.
- `LetterSpacing *float32` — extra horizontal space in points between glyphs. nil = no extra. Can point to a negative value to tighten.

All three flow through the go-text/typesetting HarfBuzz shaping pipeline and affect both measurement (`MeasureText`) and rendering consistently.

`bellui.TextStyle` also has a `Language string` field (BCP 47 tag, e.g. `"sr-Cyrl"`) that overrides the locale-derived `shaping.Input.Language` for script-specific OpenType feature selection and localized glyph forms. Zero value (empty) follows the active locale. Resolved by `resolveLanguage()` in `internal/painter/font.go` (mirrors `resolveBaseDirection`); only affects content shaping, not font selection or bidi ordering.

### Text Decorations — Underline + Strikethrough (pre-rebrand tracker #541)
`TextStyle.Underline` and `TextStyle.Strikethrough` (the latter added for upstream-2.8 parity; matching field name for cherry-pick compat) both render as decoration lines over **general text** — `canvas.Text`, `canvas.StyledText`, Label, RichText — not just TextGrid. All three painters (WebGPU, GL, software) rasterize text through the shared `paint.DrawString`/`DrawStyledRuns` in `internal/painter/font.go`, so the decoration is drawn once there: `drawUnderline` (2/5-descent below baseline) and `drawStrikethrough` (~0.3×ascent above baseline ≈ x-height center) both feed `drawDecorationLine(dst, clr, y, x0, x1, scale)`, which spans the glyph **advance** (so `LetterSpacing` is respected) in the run's own colour (`g.colors[0]` per StyledText run). Decoration bits are in the `fontSizeEntry` texture/metrics cache key (`internal/cache/text.go`) — the #70 lesson — so a toggled decoration re-renders instead of serving a stale texture (they're **not** in `cacheID`, the face-selection key, since they don't change face). Markdown `~~x~~` sets `Strikethrough` (composes with bold/italic); HTML `<s>`/`<del>`/`<strike>` → strikethrough and `<u>`/`<ins>` → underline (`widget/html.go` `htmlStyle`). TextGrid keeps its own cell-level underline path, unchanged.

### Font Fallback (CJK / non-Latin)
Glyphs not covered by the active font fall back per-rune through `dynamicFontMap.ResolveFace` (`internal/painter/font.go`): own faces → **app-registered fallbacks** → system-font scan (`fontscan`) → `.notdef`. The bundled default fonts are Latin-only, and **system-font scanning is unavailable on WebAssembly** (no scannable fonts) and unreliable on some mobile setups, so non-Latin text (CJK especially) renders as tofu there unless a fallback is **compiled in**.
- `bellui.RegisterFontFallback(res bellui.Resource)` (`font.go`) — appends a face to the global fallback chain, consulted (in registration order) *before* the system scan. Portable: works on every platform including wasm. Register once at startup; registering later invalidates the font + metrics caches (`ClearFontCache` + `cache.ResetThemeCaches`). Wired into the painter via the `bellui.SetFontFallbackRegister` hook (mirrors `RegisterTextMeasure`); the painter impl is `registerFallback`/`resolveFallback` in `internal/painter/font_fallback.go`.
- `theme/cjk` — opt-in package bundling a ~6.5 MB subset of Noto Sans CJK SC (common GB2312/Shift-JIS/EUC-KR Han, Hiragana, Katakana, common Hangul, CJK punctuation, Latin; SIL OFL 1.1). `import _ "github.com/belluikit/bellui/theme/cjk"` self-registers it on init (or call `cjk.Register()`); `cjk.Font` is the resource. The font is only linked when the package is imported, keeping default/wasm binaries lean. For glyphs outside the subset, register a fuller font.
- A custom `TextStyle.FontSource` chain also includes the bundled emoji face and benefits from registered + system fallbacks via the same `ResolveFace` path.
- **Bundled UI-symbol fallbacks (pre-rebrand tracker #686)** — common symbol glyphs the primary bundled fonts lack (✓ ✗ ☐ ★ ⌘ ⌥ ⇧ arrows, geometric shapes, math operators, enclosed alphanumerics, ‣ ※, …) used to fall through to the host system-font scan, giving **host-dependent text metrics** (macOS vs Linux golden-markup drift, tofu on wasm). Four OFL Noto subsets (`theme/font/NotoSansSymbols2-bellui.ttf` + `NotoSansSymbols-bellui.ttf` + `NotoSansPunct-bellui.ttf` + `NotoSansMath-bellui.ttf`, ~385 KB total, exposed as `theme.DefaultSymbolsFallbackFonts()`) are now part of every chain — appended after theme/emoji faces but **before the host locale face** (`addSymbolsFallbackFaces` in `internal/painter/font_symbols.go`, parsed once, shared across chains; also in the custom-`FontSource` and Symbol-style chains, and the Symbol chain now falls back to the bundled text font so mixed symbol/text strings stay host-independent). Strip with `-tags no_symbols`. Coverage is locked by `TestBundledFacesCoverCommonSymbols` (`internal/painter/font_symbols_test.go`). Diagnostic: set `BELLUI_DEBUG_FONTESCAPE=1` to log every rune whose resolution escapes the compiled-in faces to a host-dependent source (locale face, registered fallback, system scan).

### Per-Subtree / Per-Window Layout Direction
Layout direction is normally a process global (`bellui.SetLayoutDirection`). Two overrides let a subtree flow against the global — e.g. an LTR settings dialog inside an RTL app (#66, RTL Phase 6):
- `container.DirectionScope` / `container.NewDirectionScope(content, dir)` — wraps a subtree in an ambient direction. `DirectionLTR`/`DirectionRTL` force a direction; `DirectionAuto` inherits the enclosing one (no-op). Scopes nest, innermost wins. `SetDirection(dir)` updates it.
- `Canvas.SetDirection(dir)` / `Direction()` — an optional interface on `bellui.Canvas` (implemented by the GLFW/mobile canvas via `internal/driver/common.Canvas`) that scopes a whole window/canvas. Reach it with `w.Canvas().(interface{ SetDirection(bellui.Direction) }).SetDirection(dir)`.

**Mechanism** (mirrors the per-widget `ThemeOverride` two-seam pattern): an ambient direction is layered *under* `lang.IsRTLDirection()` via a per-goroutine stack in `internal/uidir` (`Push`/`Pop`/`Current`, keyed by `thread.GoroutineID()`), so every existing consumer (mirroring, `ResolveAlign`, `resolveBaseDirection`) becomes scope-aware with no call-site changes. `DirectionScope`'s renderer pushes around `Layout`/`MinSize`; `internal/driver/common.Canvas.EnsureMinSize` pushes per-`DirectionScope` node (alongside the existing `ThemeOverride` push) and wraps the whole walk in the per-canvas direction; the GLFW paint walk wraps the paint pass in the per-canvas direction.

**Phase 6/7 scope:** both scopes are now fully direction-correct at layout *and* paint time. Phase 6 delivered layout mirroring, leading/trailing alignment, focus order and measured base direction for both scopes, plus full paint-time text base direction for a *per-canvas* scope (the canvas wraps both layout and paint). Phase 7 (#178, Seam B) closes the remaining gap for a *container* `DirectionScope`: each driver's paint walk now pushes the scope's direction onto the per-goroutine `uidir` stack around its subtree (`internal/driver.Push/PopDirectionScope`, the paint-time mirror of the `EnsureMinSize` layout hook), so paint-time base direction of mixed-bidi text and the alignment of slack-width standalone `canvas.Text`/`StyledText` primitives inside a container scope resolve against the scope rather than the global. The hook is replicated across the GLFW (`glPaintWalk`), mobile (`mobileTreeWalker`) and software/test (`software.Painter`) walks; `DirectionScope.ScopedDirection()` lets the canvas-free painters detect the scope structurally without importing `container`. Per-run `TextStyle.Direction` remains an escape hatch. Live in-place direction toggling without a relayout follows the same runtime-refresh limitation as the global `SetLayoutDirection` (#65); the new direction is applied on the next relayout.


### HTML Parsing
`widget.RichText` supports HTML content via `NewRichTextFromHTML()`, `ParseHTML()`, and `AppendHTML()`. Handles headings, paragraphs, lists, tables, links, images, blockquotes, code blocks, and inline formatting. Nested inline styles (bold+italic) compose correctly. Unsupported tags are stripped with text content preserved.

### Untrusted-Content Security (RichText HTML/Markdown)
Parsed HTML/Markdown is treated as potentially untrusted (#285). Three defenses, all in the `widget` + `internal/repository` layers:
- **Images are not auto-fetched by default.** `RichText.AllowRemoteContent` (`bool`, default `false`) gates loading of `ImageSegment`s whose source is a remote (`http`/`https`) or local-`file` URI. When `false`, such images render `theme.BrokenImageIcon()` instead — no network request, no disk read happens on render. Set it to `true` only for content you trust (local docs, your own markdown). Applies to both the `notweb` and `wasm` image paths via the shared `richImage` (`widget/richtext_objects.go`).
- **No schemeless→file fallback.** A bare/relative `src` (e.g. `/etc/passwd`, `images/x.png`) no longer becomes a `file://` URI (the old `storage.NewFileURI(src)` fallback is gone); it yields a nil source / placeholder. Embed an explicit `file://` URI for genuinely-intended local images.
- **Link-scheme allowlist.** Links from parsed markup (`parsedLinkURL` in `richtext_objects.go`, used by `html.go`/`markdown.go`) only keep `http`/`https`/`mailto` (and relative refs); `file:`, `smb:`, `javascript:`, `search-ms:`, `ms-msdt:` etc. are dropped to `nil` so tapping does nothing.
- **Hardened HTTP repository.** `internal/repository/http.go`'s `safeClient` adds a 30s timeout, a 64 MiB `io.LimitReader` cap (OOM guard), and a dial-time SSRF guard (`isBlockedIP`) that refuses link-local/metadata (`169.254.169.254`, `fe80::/10`), multicast and unspecified targets on the initial request *and every redirect*. Loopback and RFC 1918/ULA are intentionally allowed (localhost/LAN apps).

### Entry Enhancements
- `Entry.Select(startRow, startCol, endRow, endCol)` — programmatic text selection with bounds clamping
- `Entry.SelectionRange() (TextRange, bool)` — reads the selection as a normalized half-open rune range; the caret sits at one end (`CursorTextOffset`), the anchor is the other (pre-rebrand tracker #431)
- `Entry.InsertText(text)` — inserts at the caret as one gated, undo-recorded edit with one `OnChanged` (the exported `insertRunesAtCursor`; use instead of routing programmatic inserts through `ComposeCommit`) (pre-rebrand tracker #432)
- `Entry.ApplyEdits([]TextEdit)` — atomic multi-range edit for block indent/dedent and replace-all: `TextEdit{Start, End, Text}` rune offsets into the pre-batch content, applied right-to-left, all-or-nothing gating through `ProtectedRanges`/`BeforeChange`, recorded as **one** undo step (compound `entryBatchModifyAction` in `entry_edits.go`) with one `OnChanged`/Validator run (one sync point under `DeferTextSync`); overlapping ranges are rejected (pre-rebrand tracker #433)
- `Entry.AddShortcut(shortcut, handler)` — register custom keyboard shortcuts
- `Entry.KeepSelectionVisible` — keeps selection highlight visible after focus loss
- `Entry.OnSelectChanged` — callback fired when text selection changes
- `SelectEntry.OnOptionSelected` — callback fired when a drop-down option is picked, after `SetText`/`OnChanged`; distinguishes a pick (a complete edit — e.g. an inline cell editor committing on pick) from free-text typing, which never fires it (pre-rebrand tracker #1047)
- `Entry.StyleOverlayForRow func(row int) []StyleRun` — a settable, pull-based, row-indexed **foreground** style overlay composited over `LineHighlighter` output (pre-rebrand tracker #1079). Foreground color only ever reaches glyphs through `StyleRun`, and `LineHighlighter` is line-at-a-time with no row index — so a host that colors from a *whole-document* analysis (LSP semantic tokens: absolute `(row,col,length,tokenType)` ranges, e.g. pre-rebrand goed tracker #208/fycoder#175) had no seam to deliver it. The overlay is consulted at render time for the rows the renderer materialises (visible window on large docs, O(viewport)); the runs tile the row from rune 0 by `Text` length (a zero-valued run is a **spacer** leaving its range unstyled, so a sparse overlay is spacer/token/spacer/token, and the tiling may stop short of the row end), and are merged over the base runs by `overlayRunsForRow`→`overlaySubrange`→`mergeStyleRun` (the generalization of the old preedit `underlineSubrange`, which is now `overlaySubrange` with an underline overlay). **Precedence** (`mergeStyleRun`): a non-nil `ForegroundColor` or non-empty `ColorName` on an overlay run replaces the base foreground *as a unit* (so an overlay `ColorName` isn't shadowed by a stale base direct color), `Bold`/`Italic` only switch on, `BackgroundColor` replaces, a set `Underline` carries its style+color, a set `StrikeThrough` carries its `StrikeColor` (pre-rebrand tracker #1087 — defaults to the run foreground when nil, like `UnderlineColor`; rendered as a solid mid-glyph line via `newStrikeDecoration`, the strike counterpart of `newUnderlineDecoration`); unset overlay fields keep the base run's values (semantic foreground overrides lexical color without clobbering bold or a diagnostic squiggle). The `StrikeThrough` field is the run-level seam an LSP host uses to render a `deprecated` symbol struck through. **Pure composition**: it runs *after* `HighlightRunsForRow`, never feeds the lexer state chain or invalidates `hlCache`, so a host `Refresh()` on new tokens repaints without re-lexing (`TestEntry_StyleOverlay_DoesNotRelex`). Composition order in `styleRunsForRow` is highlighter → overlay → IME preedit underline (preedit shifts the one composing row's overlay offsets until commit). With no `LineHighlighter`, a base run covering the row is synthesized so the runs still tile it; an overlay of only spacers returns nil (renderer skips the row). Tests: `widget/entry_styleoverlay_internal_test.go`.
- Multi-line entries no longer auto-select-all on focus gain
- Editor-style keyboard navigation (pre-rebrand tracker #377): `PageUp`/`PageDown` page the caret by one **viewport screenful** (a `pageRowCount()` = visible-rows-minus-one step) preserving the column, rather than jumping to the document extremes; `Ctrl+Home`/`Ctrl+End` (macOS `Cmd+ArrowUp`/`Cmd+ArrowDown`) jump to document **start/end**, both with `Shift` variants that extend the selection. Cursor moves drive `ensureCursorVisible`, so the viewport scrolls to follow. On the **web target** these keys are only usable because the `belluikit/glfw-js` fork now maps `PageUp/PageDown/Home/End/Insert` to their real DOM keyCodes (they were previously dropped) and registers the wheel listener `{passive: false}` so a wheel gesture scrolls the canvas (both fixed in glfw-js v1.0.2).

### Large-Document Entry Storage (rope, pre-rebrand tracker #381/#382)
The lazy single-segment editing path of `Entry`/`RichText` stores its text in `internal/textbuf.Buffer` — a flat-spine rope of ≤4 KiB UTF-8 chunks with per-chunk rune/newline counts. Edits are O(edit + chunks); the logical-line index lives in the buffer (`LineCount`/`LineStart`/`LineOfPos`, vectorized newline search). **Identity contract**: `Buffer.String()` is memoized and returns the *same string object* until the next splice; after every provider-mediated edit `Entry.Text == seg.Text == buf.String()` hold as one object, and `lazyCanEdit()`'s `seg.Text == lazyStr` pointer compare gates the fast path — assigning a *fresh* string to `seg.Text` silently degrades to full rebuilds (guarded by the `lazyFullBuilds` test hook + `TestLazyEdit_NoFullRebuildPerKeystroke`). The **per-keystroke floor** is one document materialization (alloc + memcpy) forced by the exported `Entry.Text` field — everything else is O(edit + window): undo/redo replay is delta-native (`entryUndoAction.Apply` splices the provider), selection reads via `textRange`/`Substring` (zero-copy against the clean memo), IME preedit splices through the buffer (`preeditApplied`), the highlight cache is windowed + edit-local (`ensureHighlightedThrough`, `noteLazyLinesEdited`) and re-chains after edits above a deep viewport jump over the trusted stretches (`hlTrusted`, a sorted list capped at `hlMaxTrustedStretches`; scattered batch edits between renders each split rather than discard the chained lines around them, pre-rebrand tracker #418) in O(edits + convergence + window) — only the first deep jump after SetText has to chain from line 0 (pre-rebrand tracker #412) and a background prefill (pre-rebrand tracker #417, armed in `updateText`, driven by a repeat-forever animation ticking `hlPrefillTick` in ~5 ms/frame slices) usually chains there first — a jump before it finishes pays only the gap above the watermark; and the wrap-off widest-line is cached (`vwLine`/`vwDirty`). `lineWrap` sub-row offsets are **line-relative** (converted at `lazyRowBoundary`/`lazyRowColFromTextPos`). Keystroke ≈0.6 ms at 3 MB / ≈6 ms at 30 MB (memcpy-bound, position-independent); `BenchmarkEntry*BigDoc` + the env-gated `TestEntryTypeFlatLatency` (`BELLUI_PERF=1`) are the perf gates; `internal/textbuf` has an oracle/fuzz suite (`FuzzSplice`).

**Opt-in lazy-Text mode (pre-rebrand tracker #410)**: `Entry.DeferTextSync` lifts the per-keystroke floor. Deferred edits splice only the buffer — `lazySpliceText` skips the materialization and sets `RichText.deferredDirty` (buf is ahead), while `Entry.Text == seg.Text == lazyStr` keep the *last-synced* string object so the identity gate still holds and `syncSegments`' store stays a no-op; rendering/caret/selection read the buffer so they are always live. `Text`, `OnChanged`, the `Validator` and binding writes update once per **sync point** — `Entry.SyncText()`, focus loss, Enter/Return submission — via `lazyMaterialize` + `syncDeferredTextNotify` (a sync during IME composition excludes the spliced preedit and leaves the anchor deferred). Direct `Text` writes between sync points discard pending edits (external write wins; `updateRowBoundsLazy`'s rebuild branch clears `deferredDirty`). Deferred keystroke ≈0.15-0.19 ms **flat** 3→30 MB (`BenchmarkEntryTypeBigDocDeferred`); mode off is byte-identical. Related fix: the lazy wrap-off row model is width-independent, so a width-only change (e.g. typing into the document's widest line growing the scroll extent) no longer forces an O(lines) rebuild (`rowBoundsCacheValid`).

### IME / Composition Support
Cross-platform input-method (preedit/composition) support for CJK and other input methods (§9, pre-rebrand tracker #35).
- `event.Composable` (in `event/event.go`) — optional capability interface embedding `Focusable`: `Compose(*PreeditEvent)`, `ComposeCommit(string)`, `ComposeCancel()`. `event.PreeditEvent{Text, CursorPos}` carries in-progress composition text. Drivers type-assert the focused object to it.
- `widget.Entry` implements `Composable`: the in-progress preedit is shown inline at the caret (underlined via the existing `StyleRun` path) without touching `Text`, `OnChanged`, undo or bindings; commit inserts the finalized text as a single edit. Implemented by splicing a *composed display string* through `syncSegments` (preedit lives in the layout segment, never in `Text`); `composedDisplay()`, `styleRunsForRow()`, and the extracted `insertRunesAtCursor()` are the key internals.
- Driver plumbing: `window.processCompose` (shared glfw `window.go`) forwards to the focused `Composable`; `processComposeCommit` (wasm) and `processComposeCancel` (desktop) live in the platform file where each is used.
- **Desktop**: uses the forked GLFW binding `github.com/belluikit/glfw` (vendored GLFW 3.4, adds the preedit API; swapped in for `go-gl/glfw/v3.3/glfw` by rewriting imports — no `replace`). `window_desktop.go` registers `SetPreeditCallback` (preedit → `Compose`; empty → `ComposeCancel`; committed text arrives via the char callback → `TypedRune`), toggles `glfw.IMEMode` via `canvas.OnFocus` when a `Composable` is focused, and positions the candidate window with `SetPreeditCursorRectangle` from `event.PreeditPositioner` (implemented by `Entry`, content coords minus scroll) translated via `AbsolutePositionForObject` + `scale.ToScreenCoordinate`. Covers macOS/Linux/Windows.
- **WebAssembly**: DOM `compositionstart`/`compositionupdate`/`compositionend` on the hidden input (`device_wasm.go`); char events gated while composing.
- **Mobile**: the Go-side seam (`internal/driver/mobile/event/composition.Event`, `keyboardComposing`/`keyboardComposeCommit` cgo exports, driver dispatch) is wired to the **native** side (#126): Android `InputConnection` (`GoNativeActivity.java`) and iOS marked-text (`BelluiTextInputView`, `darwin_ios.m`). Both drive the neutral **text-input mirror seam** (`internal/textinput`, pre-rebrand tracker #768) — see the Text-Input Mirror section below — so inline preedit + commit work on device. iOS CJK composition + selection (pre-rebrand tracker #747/#748) are **fixed** (pre-rebrand tracker #771); RichEntry rides the same seam via `AccessibleTexter` (pre-rebrand tracker #773). RichEntry still lacks pointer/touch selection + Entry's MD3 chrome (pre-rebrand tracker #749/#750, open).
- Test helpers: `test.Compose/ComposeCommit/ComposeCancel`.

### Text-Input Mirror Seam (pre-rebrand tracker #768)
`internal/textinput` is the neutral seam binding the focused editor to each platform's native text-editing/IME surface — the document-mirror generalization of the mobile driver's old bespoke keyboard-state cache. `textinput.Session` (created per driver, rebound on focus): `Bind(focused any)` binds any `core.AccessibleTexter` as the editor and (additionally) any `event.Composable` for IME; `Sync()` pushes the editor's `(text, selection)` `Snapshot` to the driver's `Backend.SetState` (redundant-push filtered); edit ops `Insert/Delete/Replace/SetSelection`→AccessibleTexter and `Compose/Commit/CancelCompose`→Composable, each auto-syncing. A leaf package (imports only `core`+`event`); drivers own the `Backend` and drive the session. The seam also owns the **pull-side document view** (`textinput.View{Text,SelStart,SelEnd,Caret}` via `Read(ed)`, with `View.Snapshot()` the push subset) and the **edit vocabulary** as package-level primitives over `core.AccessibleTexter` (`InsertText`/`ReplaceRange`/`ReplaceAll`/`Select`); `Session`'s edit methods and `Sync` delegate to them, and the desktop a11y-text backends call them directly, so the read + edit paths have one definition. Phases: P0 seam (pre-rebrand tracker #769), P1 Android reference (pre-rebrand tracker #770, `keyboardStateBackend`→`app.SetKeyboardState`→shadow EditText) — whose `BelluiInputConnection` **coalesces IME batch edits** (pre-rebrand tracker #1080, the corrected redo of the reverted pre-rebrand tracker #1015/#1067): while an outermost `beginBatchEdit`/`endBatchEdit` pair is open the per-op committed forwards are **deferred** (`super.*` still mutates the shadow `mBelluiBuffer`, `deferCommitted()` gates every `keyboard*` call) and `endBatchEdit` emits ONE surrogate-safe base→final `keyboardReplace` → one undo step (`flushBatchDiff`, snapshotting `batchBaseText` at the outermost `beginBatchEdit`) — Select-all-then-type / autocorrect delete+commit / chip `replaceText`, the iOS input-view model. The first attempt (pre-rebrand tracker #1067) forwarded per-op **and** at the batch boundary, which **doubled ordinary typing** because Gboard wraps even a single-char commit in a batch (device-caught pre-rebrand tracker #1071, reverted pre-rebrand tracker #1074); deferring the per-op forward is the fix. Crucially, `BaseInputConnection.commitText`/`replaceText`/`deleteSurroundingText`/`setComposingText` **internally** wrap their Editable mutation in `beginBatchEdit()`/`endBatchEdit()`, which dispatch virtually to the overrides — so `super.*` would trigger a spurious snapshot+flush and re-double every edit; a `superEdit` re-entrancy counter raised around every `super.*` edit call makes the batch overrides skip the snapshot/flush for those internal batches, so coalescing keys off the IME's *own* outer batch only (this was the actual on-device failure mode, verified fixed on the OnePlus Pad 2 + Smart Keyboard — the pre-rebrand tracker #1071 rig). Composition is excluded — a fresh preedit mid-batch flushes the pending committed diff first then forwards compose events immediately (clearing `batchBaseText`), and ops that don't mutate the buffer (Enter, forward-delete, hardware shortcuts) flush-then-forward too and pushes **partial extracted-text updates** (pre-rebrand tracker #1009: a TextWatcher span on `mBelluiBuffer` tracks the dirty region; monitor pushes carry only the delta via `partialStartOffset`/`partialEndOffset`, caret-only changes push nothing, and a direct `getExtractedText` re-baselines windowed at the IME's `hintMaxChars` — keystrokes cost O(edit), not O(document)), **P2 iOS (pre-rebrand tracker #771)**, **P3 desktop a11y-text consolidation (pre-rebrand tracker #772)** — macOS NSAccessibility (`accessibility_text_darwin.go`) + Windows UIA Text (`accessibility_text_windows.go`) protocols resolve the per-handle editor then read/edit via the seam's `Read`/primitives instead of calling `AccessibleTexter` ad-hoc (behavior-preserving; the duplicated whole-doc "set value" and per-callback reads collapse onto `ReplaceAll`/`Read`); desktop IME stays string-oriented (GLFW `Composable`, no document mirror). P4 RichEntry consumer (pre-rebrand tracker #773).
- **Android one-writer key reroute (pre-rebrand tracker #1061)**: on Android a hardware key is delivered twice while a prose field is focused — Gboard applies it to the bellui-owned `mBelluiBuffer` through the InputConnection (`commitText`/`setComposingRegion`/`deleteSurroundingText`/`sendKeyEvent` → the IC channel), *and* the raw key still traverses the NativeActivity input queue tagged `Native`. Applying both was the dual write that doubled characters and left a spurious space after autocorrected words, and forced the driver to drop word-boundary autocorrections it couldn't reconcile. `driver.suppressNativeTextKey`/`imeOwnsNativeKey` (`internal/driver/mobile/driver.go`) makes the IC the **single writer** by ignoring the redundant native echo of any bare printable key or Backspace while a **prose** field is focused (`keyboardType` ∈ {Default, SingleLine}); so Gboard's autocorrect/auto-capitalization simply land as the committed edits it already sends. **Password/number fields are excluded** — they disable composition, so Gboard passes their hardware keys *only* through the native queue (device-verified: suppressing there kills all typing). Non-text keys (arrows/Enter/Tab) are never suppressed. This retired the three delivery-keyed reconciliation mechanisms of pre-rebrand tracker #1057 (the `ic_echo.go` dedup, the stale-finalize drop, and `composeAdvance`), which are **deleted**. CJK is structurally unaffected (genuine composition keeps the editor composing and flows through the preedit/commit path). Verified on-device with a OnePlus Smart Keyboard (`hack/echoprobe966`).
- **Android hardware-keyboard shortcuts (pre-rebrand tracker #1077)**: Ctrl+A/C/V/X/Z/Y from a hardware keyboard used to be lost — Gboard hands a shortcut combo (Ctrl/Alt/Meta held, `getUnicodeChar()==0`) to `BelluiInputConnection.sendKeyEvent`, which delegated to `super` (the inert host `EditText`), never reaching bellui. Now `sendKeyEvent` forwards it via a new `keyboardShortcut(keyCode, metaState)` JNI up-call → `keyboardShortcutKey` (`android.go`) → a non-native `key.Event` with `Modifiers` (from `androidKeyModifiers`) → `typeDownCanvas`, which builds the built-in `bellui.Shortcut` via the **shared** `common.BuiltinKeyboardShortcut(keyName, clipboard)` (extracted from the glfw driver's `triggersShortcut`, now used by both drivers) and dispatches it to the focused `bellui.Shortcutable` (with the desktop's disabled-widget Copy-only guard) — firing only when the modifier is *exactly* Control or Meta (a Shift-mixed combo still reaches `TypedKey`, pre-rebrand tracker #1042). Because the hardware key **also** dual-delivers on the native queue (like text), `imeOwnsNativeKey` now suppresses the native echo of **any** shortcut combo (Ctrl/Alt/Meta) in every field type — otherwise the shortcut dispatched twice (device-verified: Ctrl+V pasted the clipboard twice; A/C/X are idempotent so only V/Z show it). Verified on-device (`hack/echoprobe966`). Needed the embedded-dex regen (`cd cmd/bellui/internal/mobile && go generate` — `GoNativeActivity.java` changed).
- **Android hardware-keyboard Shift+Arrow selection (pre-rebrand tracker #1083)**: Shift+Arrow didn't extend an Entry's selection. Hardware arrows are delivered *only* via the IME's `sendKeyEvent` DPAD block → `keyboardArrow` (they never reach the native queue — `convAndroidKeyCode` leaves DPAD unmapped), and that call **dropped the meta-state**; the Shift key itself reaches `processKey` but only as `TypedKey` (never `KeyDown`, so `Entry.selectKeyDown` stays unset), and the pre-rebrand tracker #1061 action-inversion would break a `KeyDown`-based fix anyway. Fix: `keyboardArrow(code, metaState)` now carries the modifiers, and the **mobile driver implements `desktop.KeyModifierDriver`** (`CurrentKeyModifiers`/`AddKeyModifierListener`, tracking `keyMods` from each key event's modifiers in `typeDownCanvas` — immune to the inversion because it reads the meta-state, not the key direction). `Entry.TypedKey` already consults the driver's `CurrentKeyModifiers()` for shift state; it now asserts the narrower `desktop.KeyModifierDriver` (not `desktop.Driver`) so the mobile driver qualifies (glfw satisfies both; the test driver satisfies neither, so its `KeyDown`-based selection tests are unchanged). Verified on-device. Also needs the same dex regen.
- **iOS backend — `BelluiTextInputView` (pre-rebrand tracker #1117/#1119, epic pre-rebrand tracker #1115; supersedes the pre-rebrand tracker #771 `GoInputView` UITextView proxy):** a hidden **bare `UIView<UITextInput,UITextInputTraits>`** (`darwin_ios.m`), the Flutter `FlutterTextInputView` model, hosted in the app **window** as a sibling of the GLKView — never a GLKView subview, whose CAMetalLayer entanglement froze rendering on keyboard presentation (pre-rebrand tracker #1124). It owns an authoritative UTF-16 document mirror (text + selection + marked range) and intercepts edits **at source** (`insertText:`/`deleteBackward:`/`setMarkedText:`/`unmarkText`/`replaceRange:`) — no `textViewDidChange:` diffing — forwarding per-rune `keyboardTyped` (preserves `NumericEntry`'s filter), `keyboardReplace` (pre-rebrand tracker #748), `keyboardComposing`/`keyboardComposeCommit` (pre-rebrand tracker #747) and `keyboardSetSelection`; Go `SetKeyboardState`→`belluiSetDocument` reseeds the mirror per repaint (no-op while composing). Owning the view means owning its **tokenizer** (`BelluiTokenizer`, pre-rebrand tracker #1113 — a UITextView subclass cannot replace its tokenizer) and its **geometry** (the pre-rebrand tracker #1107 sidecar answers `selectionRectsForRange:`/`caretRectForPosition:` from bellui's real layout). Under VoiceOver the a11y bridge publishes **the input view itself** as the focused element — first responder and VO-focused element must be the **same object** for insertion-point editing (pre-rebrand tracker #1124; a detached forwarding element engages reading/cut but never caret navigation). **Interrupted composition finalizes deterministically** (pre-rebrand tracker #1118): an external caret move mid-composition (tap; VO tap arrives via `setSelectedTextRange:`, a bellui-side tap via the push's caret-vs-anchor signal, per the pre-rebrand tracker #1057 anchor-collapse invariant) commits the marked text as typed, places the caret at the target, then tells the keyboard via `textWillChange`/`textDidChange` — never wait for the IME to finalize (Apple Pinyin commits then restores *its own* caret); `Entry.ComposeCommit` preserves an out-of-preedit caret (extension of pre-rebrand tracker #945). ### Mobile Touch Text Selection (pre-rebrand tracker #758)
Native-parity touch selection UX for `widget.Entry` on mobile (Android/iOS/embedded):
- **Hold-fire long-press** (`internal/driver/common/touch.go`): when the driver sets `TouchHandler.LongPressCallback` (mobile + embedded canvases do), a stationary touch dispatches `LongPressed` at `TapSecondaryDelay` (300 ms) **while the finger is still down** — native timing — instead of on release; the release of a hold-fired touch then dispatches `SecondaryTappable`, so a widget implementing both gets "select on hold, menu on lift". Targets that aren't `LongPressable` keep the old release-time dispatch. State is guarded by `TouchCancelLock` (the `waitForDoubleTap` pattern); moving past the tap slop or lifting early cancels via a per-touch arm generation (`longPressSeq`).
- **`Entry.LongPressed`** implements `event.LongPressable`: places the caret at the press point and selects the word under it (`selectWordAtCursor`, shared with `DoubleTapped`); a password field only places the caret (word boundaries of concealed text must not be revealed). Desktop right-click still goes straight to `TappedSecondary` — unchanged. Since #266 the glfw driver hold-fires too (a stationary primary press ≥300 ms — see the LongPressable note in `widgets.md`), so a desktop *slow-click* in an Entry now word-selects like a mobile hold; the release stays silent (no tap, and unlike mobile no secondary), so no context menu pops from a slow click.
- **Selection handles** (`widget/entry_handles.go`): while a focused mobile Entry has a non-empty **touch-initiated** selection (long-press, mobile double-tap, touch drag-select, Select all from the context menu — tracked by `Entry.touchSelection`, set via `markTouchSelection()`; keyboard/programmatic selections summon none, keeping shared render masters stable across the desktop/mobile CI legs), an **input-pass-through** canvas overlay (`entrySelectionHandles`, the pre-rebrand tracker #569 Toast pattern) shows two draggable dots hanging below the selection edges. Dragging a handle moves that edge — the caret follows the dragged edge so `ensureCursorVisible` auto-scrolls; the other edge stays pinned and the pair is clamped to a non-empty selection (no crossing). Handles implement `RetainsFocus() bool` — a marker the `TouchHandler.TapDown` unfocus logic consults (structurally, like `TapThroughDismiss`) so grabbing a handle doesn't yank the keyboard off the entry — and no-op `mobile.Touchable` so the touch doesn't fall through to the entry and move the caret. Geometry: `caretRect` − `scroll.Offset` + `AbsolutePositionForObject`, re-synced on every entry refresh plus a repeat-forever per-frame animation (the pre-rebrand tracker #417 prefill pattern) so handles track parent scrolls; a handle whose edge leaves the entry's viewport hides.
- **Fixed alongside**: `Entry.TouchDown` now adds `e.scroll.Offset` like `MouseDown` — before this, a tap in a scrolled multiline entry placed the caret a viewport off.
- Tests: `widget/entry_handles_mobile_test.go` + `internal/driver/mobile/canvas_selhandles_mobile_test.go` (mobile-tagged, run by the mobile CI leg), `internal/driver/mobile/canvas_longpress_test.go` (hold-fire pipeline), `widget/entry_touch_internal_test.go` (scroll-offset regression).
- **Shipped follow-ups**: magnifier/loupe overlay (pre-rebrand tracker #942, `widget/entry_loupe.go` — retained-mode re-typeset of the dragged row at 1.5×, `selectionLoupeHost` optional seam), caret drag-handle after a plain tap (pre-rebrand tracker #943, `widget/entry_caret_handle.go`, Entry-only), selectable Label/RichText parity (pre-rebrand tracker #944, the `selectionHandleHost` seam in `widget/text_sel_handles.go`), Android device pass (pre-rebrand tracker #945).
- **RichEntry parity (pre-rebrand tracker #888, `widget/richentry_handles.go`)**: RichEntry implements `LongPressable` (word-select at the finger), `selectionHandleHost` (edges/drag mapped through its offset-based document position model; `caretRectAt` is the shared caret geometry) and the loupe seams. Its embedded `selectable` forwards `TouchDown`/`MouseDown`/`TappedSecondary` to the host (like Tapped/Dragged), so pointer-type tracking and the context menu reach the editor — RichEntry gained its own `TappedSecondary` menu (Undo/Redo/Cut/Copy/Paste/Select all), which also serves the handle-lift "toolbar reappears" flow. The loupe grew a **styled-run path** (`selectionLoupeStyledHost` → `canvas.StyledText` with per-run zoomed sizes; `lineSizeToColumn` measures per-segment, so 1×-visual-x × zoom stays glyph-exact), adopted by both RichEntry and the standalone selectable (multi-style RichText rows magnify true; Entry keeps the plain path). Caret drag-handle for RichEntry and an on-device pass are the remaining follow-ups.

### Editable Rich Text — widget.RichEntry (epic pre-rebrand tracker #648)
`widget.RichEntry` (`widget/richentry.go` + `richentry_doc.go` + `richentry_undo.go` + `richentry_html.go`) is the **editable** counterpart to read-only `RichText`, which it reuses as its measure/render engine (the way `Entry` hosts `textProvider()`). `Entry` is the wrong vehicle for this — it is flat-string / single-`TextSegment` with `int` rune offsets throughout — so RichEntry is a new widget with its own document model. `richtext.go`/`entry.go`/`selectable.go` are **untouched** by the whole epic (same-package internal reuse → no regression surface); the only shared change is additive `ImageSegment` fields.
- **Document / position model** (`richentry_doc.go`): an ordered `[]RichTextSegment` of inline `TextSegment`s plus block `ImageSegment` atoms. A caret position is a global offset where each text rune counts 1 and **each atom counts exactly 1** (`segPositions`) — the `(segmentIndex, runeOffset)` space the epic needed. `insertText` splits a run on a style change, `deleteRange` merges adjacent equal-style runs, `applyStyle` splits a range, `segmentsBetween`/`replaceRange`/`insertSegments` capture and splice styled fragments (shared by undo + paste). Style equality is **value-based** (`richStyleEqual`) because `bellui.TextStyle`'s `Weight`/`LineHeightScale`/`LetterSpacing` are pointer fields — a plain `==` would never merge visually-identical runs.
- **Geometry**: the caret currency is `(row, col)`, because RichText's flat-offset helpers (`textPosFromRowCol`, `selectable.go`) are single-segment-only while `lineSizeToColumn` (`richtext.go`) measures multi-segment rows. **Wrapping is off** — each `\n`-separated line and each block image is one row; the row model is an atom-aware segment walk **validated in tests against `provider.rows()`** so it matches RichText's actual `updateRowBoundsInner` layout. An image row's caret sits at the row's left edge (RichText's column space is zero-width for images). Word-wrap is deferred to pre-rebrand tracker #653.
- **Editing**: Focusable; typing / Backspace / Delete / arrows / Home/End / Shift-select; `SetSegments`/`Segments`/`String`/`SelectedText`; `ApplyStyle(RichTextStyle)`; `InsertImage(image.Image)` / `InsertImageResource(bellui.Resource)`.
- **Undo/redo** (`richentry_undo.go`, pre-rebrand tracker #656): every mutation is captured as one reversible `richEntryEdit` delta ("replace positions [from,to) with these segments"), derived from the document length change, so insert / delete / type-over-selection / restyle / paste all route through the single `mutate` wrapper → `richEntryUndoStack`. Style- **and image-preserving**; contiguous same-style typing merges into one step with word-granular breaks. `ShortcutUndo`/`ShortcutRedo` wired; `SetSegments` clears history.
- **Change notification**: `OnChanged func()` (any edit) and `OnContentChanged func([]RichTextSegment)` (typed, live segments, pre-rebrand tracker #660) — both fire from `afterEditNotify` so they also cover undo/redo.
- **In-memory images** (pre-rebrand tracker #655): `ImageSegment` gained `Image image.Image` and `Resource bellui.Resource` sources; `richImage.loadImage` renders them directly (`canvas.NewImageFromImage`/`NewImageFromResource`), **bypassing the `AllowRemoteContent` gate** since nothing is fetched. Also usable from plain `RichText`.
- **Flavor-aware clipboard** (pre-rebrand tracker #657/#666): negotiates the pre-rebrand tracker #513 optional interfaces (asserted from the passed clipboard). Paste: image → `InsertImage`; HTML → `NewRichTextFromHTML` + `flattenHTMLToInline` (block boundaries → `\n`, styles kept, images as atoms) spliced as one undo step; else plain (CRLF normalized). Copy/cut: a lone in-memory image → `SetImage`; styled text → `SetHTML` (`segsToHTML` — b/i/u/s + `<br>`, escaped) with a plain fallback. Inline boundary whitespace (a space *at a style boundary*) now round-trips through our own HTML (pre-rebrand tracker #668 fixed; `TestRichEntry_HTMLRoundTripPreservesBoundaryWhitespace`).
- **IME composition** (pre-rebrand tracker #658): implements `event.Composable` (Compose/ComposeCommit/ComposeCancel) + `event.PreeditPositioner`. The preedit is shown inline underlined via **display-only segment injection** (`displaySegments` splices the preedit run at the caret; the document, undo and change callbacks are untouched until commit); the caret is mapped against a display document (`caretDoc`) so it tracks inside the preedit, and `PreeditCursorRectangle` positions the candidate window. A typed rune commits (desktop char-callback path), Escape cancels, focus loss cancels. The existing glfw/wasm driver plumbing drives it (RichEntry is auto-detected as `Composable`). Incremental/lazy measurement for large rich docs (the provider re-lays-out per keystroke) is a separate perf follow-up.
- **Status — feature phases complete** (all pre-rebrand tracker #648 sub-issues shipped): inline images (pre-rebrand tracker #665), segment-aware undo/redo (pre-rebrand tracker #656), flavor-aware clipboard (pre-rebrand tracker #657/#666), IME `Composable` (pre-rebrand tracker #658), accessibility `AccessibleTexter` + custom actions (pre-rebrand tracker #659/#1025), word-wrap (pre-rebrand tracker #653), typed `OnContentChanged` (pre-rebrand tracker #660), lazy incremental measure, HTML-whitespace fidelity (pre-rebrand tracker #668) and the mobile caret drag-handle (pre-rebrand tracker #999). **Remaining is verification, not code**: on-device / on-GPU interactive passes via `hack/richentryprobe` (pre-rebrand tracker #667/#674) — the epic is otherwise covered by unit tests + software-rendered masters.
