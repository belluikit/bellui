### Data Model Layer — Sort/Filter/Selection (#539)
`data/model` is a generic, observable data layer that sits **between** app data and the `List`/`Table` widgets (Qt `QSortFilterProxyModel`/`QItemSelectionModel`-style), so apps stop hand-rolling sort state, filter re-indexing and the selection-remap bugs. It is **widget-free** (imports only `data/binding` + `lang`); the widget adapters live in `widget` (the B2 placement — one-way `widget → data/model`, no cycle).
- **`model.Model[T]`** — read-only observable sequence (`Len`, `Item(i)`, `AddListener`/`RemoveListener` reusing `binding.DataItem`; a new listener fires immediately). `model.SliceModel[T]` is the in-memory backing (`Set`/`Append`/`SetItem` notify; `Set` defensive-copies). `model.FromDataList(binding.DataList)` adapts an existing binding for free.
- **`model.SortProxy[T]`** (`SetLess(func(a,b T) bool)`) and **`model.FilterProxy[T]`** (`SetPredicate(func(T) bool)`) — each is *itself* a `Model[T]` holding an index permutation into its source, rebuilt **once per source change / comparator-or-predicate swap, never per row** (O(n log n) / O(n)). They compose (source → filter → sort → view). `SourceIndex(i)` maps display→source; `Close()` detaches from the source. `model.StringLess` = `lang.Compare` (#504) is the documented default comparator for user-visible text. **Perf contract**: reading rows is O(1) each, so a bound widget keeps O(visible)/frame — `BenchmarkSortProxyFrameWalk` is 0 alloc / 0 comparator calls; the once-per-change rebuild is ~33 ms at 100k rows.
- **`model.SelectionModel[T, K comparable]`** (`id func(T) K`) — tracks selection by **stable identity key, not row index**, so a selection survives a re-sort/re-filter/insert (the bug `widget.List`/`Table` positional `int` selection suffers). Single/Multi modes; `Select`/`Unselect`/`Toggle`/`Clear`/`SelectRange`; `IsSelected`/`Selected`/`Len`; and the index bridge `SelectIndex`/`ToggleIndex`/`IsIndexSelected` + `IndexOf(k)`/`SelectedIndices()` a widget adapter uses to turn a positional tap into an identity selection and re-derive the highlighted row after a reorder. Observable (fires on selection change).
- **Widget adapters** (in `widget`): `widget.BindListModel[T](list, m, create, update) (unbind)` and `widget.BindTableModel[T](t, m, cols, create, update)` set the widget callbacks (typed `update(item, cell)` — no positional indexing) and refresh on model change. `widget.BindListSelection[T,K](list, m, sel)` keeps a `List`'s selection in sync with a `SelectionModel` (tap→model via `SelectIndex`; on reorder/selection-change re-derive the highlight, guarded against the `list.Select` echo). **The `List` widget paints only one highlighted row** — for multi-selection have `update` call `sel.IsIndexSelected(i)` and style the row itself (the demo does this). `hack/modelprobe` is the live-verify demo (100k rows + live search + collated sort toggle + surviving multi-select).
- **FileTree.Sorter is intentionally not reimplemented on this layer**: `FileTree` is a `Tree` (string-keyed, with ancestor-visibility filter semantics), and Tree-shaped proxies are a separate later phase — the flat List/Table proxies do not model a hierarchy. `FileTree.Sorter` already uses `lang.Compare` (#504) directly for collated name order. Phase-1 out-of-scope follow-ups: in-place editing delegates, Tree-shaped proxies, and Table multi-column-sort header UI.
- **Table multi-column sort UI (#617)** — `widget.BindTableSort[T](t *Table, proxy *model.SortProxy[T], cols []widget.SortableColumn[T]) *widget.TableSorter[T]` adds header-click sorting on top of the #539 layer. Each `SortableColumn[T]{Title string; Less func(a, b T) bool}` declares a header label and an *ascending* comparator once (nil `Less` → inert display-only column; for user text use `model.StringLess`). `BindTableSort` enables `Table.ShowHeaderRow` and installs `CreateHeader`/`UpdateHeader` that render each title with a ↑/↓ arrow and a **tappable** header cell — it never touches `Length`/`CreateCell`/`UpdateCell`, so it composes with `widget.BindTableModel` over the *same* proxy. The header cell (`tableSortHeader`) is a Tappable Label: data cells are deliberately non-Tappable so the Table keeps cell input (`tableCellHost`), but nothing consumes header taps, so the arrow widget receives them; column-resize drag (Table `MouseDown`/`Hoverable`) is untouched since the header cell is neither Mouseable nor Hoverable. Clicking a column cycles it **none → asc → desc → none** and makes it the **primary** key; earlier-clicked columns stay active as **stable tie-breakers**, so click A then B sorts by B then A (the proxy sorts stably). The composed comparator is rebuilt and pushed via `SortProxy.SetLess` on every change (nil when no keys → source order), which re-sorts and refreshes the table — re-running `UpdateHeader` so arrows track state. `TableSorter` drives the sort programmatically (`SortByColumn(col)`, `Clear()`) and reports state (`Sorts() []ColumnSort`, `DirectionOf(col) SortDirection`); `Unbind()` clears the installed header callbacks. Main-goroutine discipline like the other adapters.

### Data Model Layer — Write Path & Editing Delegates (#615)
The follow-up write path to #539 (which was read-only). Two pieces, mirroring the read-path split (`data/model` core + `widget` adapters, one-way `widget → data/model`, no cycle):
- **`model.MutableModel[T]`** (`data/model/mutable.go`) — a `Model[T]` plus `SetItem(i int, item T)`, the write counterpart to the read-only `Model[T]`. `SliceModel` already satisfied it (its existing `SetItem` writes the slice + notifies); `SortProxy`/`FilterProxy` now implement `SetItem` too, so they satisfy `MutableModel` and **write-through**: `proxy.SetItem(displayIndex, item)` maps display→source via the existing `SourceIndex(i)` and writes the underlying source. Because a proxy's source may itself be a proxy, this composes down a **chain** (filter→sort→view): editing a *displayed* row updates the correct *source* row regardless of the active sort/filter. **Non-mutable-source decision**: if a proxy's ultimate source is not a `MutableModel` (or the index is out of range), `SetItem` is a **logged no-op via `bellui.LogError`, never a panic** — a bound editor degrades gracefully. Writing through the source fires the source's change notification, which the proxy is already subscribed to, so **one edit ⇒ one re-index + one notification at the bound level** (verified by `TestSetItem_NotifiesOnce`).
- **Editing delegates** (`widget/editmodel.go`): `widget.BindListEditing[T](list, m, createDisplay, updateDisplay, editor) (*ListEditor[T], func())` and `widget.BindTableEditing[T](t, m, cols, createDisplay, updateDisplay, editors) (*TableEditor[T], func())` swap a row/cell to an **inline `Entry`** on activate and commit the edited value back through the `MutableModel` as one gated write. The cell/row template is a `layout.NewStackLayout()` container of `{display, editEntry}` (the internal `editEntry` embeds `Entry`, committing on Enter/`OnSubmitted` and focus-loss, cancelling on Escape); `UpdateItem`/`UpdateCell` show exactly one, seeding the editor from `CellEditor.Text` **only on entry** (guarded so a `Refresh` mid-edit doesn't wipe typing).
  - **`CellEditor[T]`** describes the exchange: `Text func(item T) string` (seed), `Commit func(item T, text string) (T, error)` (parse; a **non-nil error rejects** the edit — editor stays open, model untouched — which is how validation gates the commit), optional `Validator bellui.StringValidator` (live in-field feedback only). A nil `Commit` marks the column/row **not editable**. Table `editors` is indexed by column.
  - **Controller** (`ListEditor`/`TableEditor`): `Edit(row)` / `Edit(TableCellID)` begins editing; `Commit() error` writes one gated `SetItem` (returns the validation error on rejection, keeps the editor open); `Cancel()` discards; `Editing()` reports state. All main-goroutine, like every widget mutation.
  - **Compose with `SelectionModel`**: activation defaults to the widget's own selection (`OnSelected` → `Edit`, chaining any prior callback) via `EditOnActivate` (default `true`). Set it `false` to drive editing from a `model.SelectionModel` instead — e.g. `ctrl.Edit(sel.IndexOf(key))` — so identity-keyed selection and inline editing coexist without both fighting over `OnSelected`.

#### Tree-Shaped Proxies (#616)
`model.TreeProxy` is the tree-shaped counterpart of the flat `SortProxy`/`FilterProxy`, layered over the string-keyed `Root`/`ChildUIDs`/`IsBranch` callback shape a `widget.Tree` consumes. It expresses two semantics a flat proxy cannot:
- **`model.TreeSource`** — the read side of a hierarchy (`Root() string`, `Children(uid) []string`, `IsBranch(uid) bool`). `model.NewTreeSource(root, childrenFn, isBranchFn)` wraps an existing tree's callbacks; `TreeProxy` is itself a `TreeSource`, so proxies compose.
- **`model.NewTreeProxy(src)`** with `SetLess(func(a,b string) bool)` (per-**sibling-group** sort — children of each node are ordered among themselves, hierarchy preserved, **not** a global flattened order) and `SetPredicate(func(uid string) bool)` (**ancestor-keeping** filter). Ancestor-keeping = a node is visible iff it matches OR has any visible descendant, so a deep leaf match keeps its whole ancestor chain reachable while non-matching siblings drop; a branch is kept by its own-id match too. `IsBranch` under a filter reports true only when the node has visible children (no dead expand arrows). `SetKeepMatchingSubtree(true)` additionally reveals the *entire* subtree under a branch that matches by its own id (file-explorer "folder name matches → show contents"), vs the default reachability-only paths.
- **Perf/reactivity**: a filter change walks the source once (O(n)) to compute the visible set; a sort-only change is lazy (per-parent sort, cached) — never per-frame, so a bound tree keeps O(visible). The comparator/predicate receive the node **id** (map id→label in the closure for label-based ordering, e.g. via `lang.Compare`). Unlike the flat proxies the source is a raw callback tree (not an observable `Model`), so after the underlying data changes call `TreeProxy.Refresh()` to rebuild + notify. A defensive `seen`-set cycle guard keeps a malformed source from looping.
- **Widget adapter**: `widget.BindTreeModel(tree *Tree, p *model.TreeProxy) (unbind func())` (in `widget/bindmodel.go`) wires the proxy's `Root`/`Children`/`IsBranch` into the tree and `tree.Refresh`es on every view change; the app still supplies `CreateNode`/`UpdateNode`. Drive `SetLess`/`SetPredicate`/`Refresh` on the main goroutine.
- **`widget.FileTree.Sorter` stays as-is** (decision reconsidered per #616): `FileTree` lists directories **lazily and asynchronously** off the main goroutine, so it must never enumerate the whole tree — but a `TreeProxy` *filter* requires a full walk from the root to compute ancestor visibility. `FileTree` also already has its own ancestor-visibility filter (`Filter` keeps directories) and collated `Sorter` (`lang.Compare`) applied per-listing off-thread; rewiring it onto `TreeProxy` would either force eager listing or duplicate the semantics for no gain. `TreeProxy` targets **finite, enumerable** trees (symbol trees, category trees, in-memory hierarchies) where a per-filter O(n) walk is fine. Documented rather than adapted.
