### MD3 Foundation
- **State layers** (`theme/state.go`) — `StateLayerHover/Focus/Pressed/Dragged` compute content-derived overlays at MD3 opacities (8%/12%/12%/16%).
- **Shape scale** — 7 tokens: `SizeNameShapeNone` (0) through `SizeNameShapeFull` (9999/pill).
- **Animation curves** — 4 MD3 cubic-bezier curves: `AnimationEaseEmphasized`, `AnimationEaseStandard`, `AnimationEaseStandardAccelerate`, `AnimationEaseStandardDecelerate`. 10 duration tokens (Short1-4, Medium1-4, Long1-2).
- **Elevation tint** (`theme/elevation.go`) — `SurfaceWithElevation()` tints dark surfaces with primary color at elevation-dependent opacities.
- **Advanced text layout** — `TextStyle.Weight` (100-900), `LineHeightScale`, `LetterSpacing` (all `*pointer` types with a nil sentinel — use `bellui.Ptr(...)` in struct literals). Font weight 500 (Medium) supported via bundled Roboto-Medium.
- **Locale formatting** (`lang/format.go`) — `DatePattern()`/`FormatDate()`/`ParseDate()` (CLDR region-based short date patterns), `TimePattern()`/`FormatTime()`/`FormatDateTime()`/`ParseDateTime()`, `Prefers24HourClock()` (region-based 12h/24h detection), `FormatCurrency()`/`CurrencySymbol()`/`DefaultCurrency()` (locale-aware currency with symbol placement). Plus existing: `WeekStartDay()`, `FormatMonthYear()`, `FormatDecimal()`, `ParseLocaleFloat()`.
- **Active-locale override** — `lang.CurrentLocale()` returns the active locale honouring an override (the override-aware dual of `SystemLocale()`), and `lang.SetLocale(bellui.Locale)` sets it for translations, formatting, text direction and shaping language (empty reverts to the system locale). When the locale actually changes and an app is running, `SetLocale` re-lays-out and repaints every window (#87, like a theme change) — fixing direction mirroring, alignment, bidi ordering and format-on-refresh widgets. Call it on the main goroutine.
- **System locale parsing is defensive (#271)** — OS-reported locale strings pass through `parseUserLocales` (`lang/locale.go`) before `language.Parse`: Java `Locale.toString()` forms are normalized (underscores → hyphens, the trailing `#...` script/extension marker stripped), and an entry that still fails is logged with the raw string `%q`-quoted — the on-device capture instrument — then dropped rather than passed to the matcher as `und`, so one bad entry cannot cost the locale the parseable entries behind it; a `GetLocales` *error* discards the returned value entirely (go-locale hands back `[""]` alongside a failed Android JNI lookup, which is what #271's per-start "tag is not well-formed" actually was). `updateLocalizer` seats `currentTag` (region-carrying, drives CLDR formatting/collation/direction) from the first entry that *parsed*, not blindly the first entry reported; a failed or fully unparseable lookup degrades to English exactly like the C/POSIX empty list (#1148). The 2026-08-04 OPD2403 capture closed the mystery: the device's list is clean BCP-47 (`en-US,pt-US`) — the failure is `no current JVM`, because lang's package init resolves the locale during the .so global constructor, **before JNI_OnLoad**, deterministically on every Android start. The residual defect — the app settles on the fallback locale until something re-runs `updateLocalizer` after the JVM attaches — is #282 (P1): the re-resolve seam must respect explicit `SetLocale` overrides.
- **Live re-translation of static text** — the `SetLocale` relayout repaints existing text but does *not* re-evaluate the `lang.L`/`X`/`N` call that produced it, so a widget built from `lang.L("Cancel")` keeps its build-time string (#90). For text that should re-translate on a live language switch, drive it from `binding.NewLocalizedString(key, data...)` (a `binding.String` that re-runs `lang.Localize` on a locale change) bound to a widget — e.g. `widget.NewLabelWithData(binding.NewLocalizedString("Cancel"))`. The binding subscribes to locale changes only while it has listeners (no leak for transient bindings). For text on surfaces that have **no** data binding — a `widget.Button` label, a `Window` title, a `bellui.MenuItem` — use `lang.BindText(key, apply, data...) (remove func())` (#92): it calls `apply` with the current translation immediately and again on every locale change, e.g. `lang.BindText("Cancel", btn.SetText)` or `lang.BindText("My App", w.SetTitle)`; call the returned `remove` when the target is gone (long-lived UI may leave it for the app lifetime). Lower-level: `lang.AddLocaleChangeListener(fn) (remove func())` is the per-subscriber companion to the app-level `lang.RegisterLocaleChangeRefresh`.
- **Translation-catalog workflow** — keep the JSON catalog in sync with code via the fork's patched `bellui` CLI: `bellui translate translations/en.json ./...` recursively scans Go source, extracts message strings and merges *new* keys into the file (existing keys are left untouched unless `-u`; pass `-` as the filename to print to stdout). Then ship the JSON out for translation and register the result with `lang.AddTranslationsFS(fs, dir)` (or `AddTranslations(resource)`) at startup. The scanner recognizes both the classic `lang.L`/`Localize`, `N`/`LocalizePlural`, `X`/`LocalizeKey`, `XN`/`LocalizePluralKey` and — as of #503 — the fork's live-retranslation seams: `lang.BindText` and `binding.NewLocalizedString`/`NewLocalizedPlural` (key-only, key doubles as fallback like `L`/`N`) plus `binding.NewLocalizedStringWithKey`/`NewLocalizedPluralWithKey` (explicit key+fallback like `X`/`XN`); the plural forms land as `{"other": …}` objects. As of #505 it also recognizes the grammatical-select seams `lang.LSelect`/`LSelectPlural`: since the selector is usually a runtime variable, the scanner seeds the mandatory `<prefix>.other` variant (and any *literal* selector variant), never the bare prefix — so an existing key is never clobbered; `LSelectPlural` seeds a `{"other": …}` object. It matches the literal `lang`/`binding` receiver identifier (not the import path), so it works against the fork's module path unchanged. The `translate` command lives in the fork's patched CLI, co-located in this repo at `cmd/bellui` — never swap it for raw upstream `fyne.io/tools`.
- **Locale-aware collation** (`lang/collate.go`, #504) — sort user-visible strings by the active locale's collation order instead of by Unicode code point (which mis-sorts most non-English text: German `äpfel` belongs with `a`, Swedish `ö` sorts after `z`). `lang.Compare(a, b string) int` is the one-call form for a sort closure (`sort.Slice(s, func(i, j int) bool { return lang.Compare(s[i], s[j]) < 0 })`); it is **goroutine-safe** (backed by a `sync.Pool` of collators keyed by the current tag, so it also stays in step with `lang.SetLocale` — no explicit invalidation needed) and is what `widget.FileTree.Sorter` should use for name ordering. `lang.CompareFold` is the case- and accent-insensitive companion for search/filter matching. For sorting a large slice, `lang.NewCollator(opts…) *Collator` returns a reusable collator (`Compare`, `SortStrings`) — captured at the active locale, **not** concurrent-safe (mirrors `x/text/collate`), rebuild on locale change; options are `CollateNumeric` (`file2` < `file10`), `CollateIgnoreCase`, `CollateIgnoreDiacritics`. Wraps `golang.org/x/text/collate` (already in the dep graph). **Binary size**: referencing collation links the collation tables (~1.75 MB); this is dead-code-eliminated in binaries that never call `Compare`/`CompareFold`/`NewCollator`, so `FileTree`'s default `Sorter` stays nil (collated ordering is opt-in — no forced cost).
- **Grammatical select / gender** (`lang/select.go`, #505) — the ICU MessageFormat `select` case (grammatical gender, formality) that CLDR plural rules can't express. The blessed pattern is **one catalog key per variant, suffixed with the selector, plus a mandatory `.other` variant**; no new dependency, translator-visible, composes with plurals as key suffixes. `lang.LSelect(keyPrefix, selector, data…)` looks up `keyPrefix+"."+selector`, falling back to `keyPrefix+".other"`, then to `keyPrefix` itself (`lookupMessage` probes the catalog by MessageID so it can chain — unlike `LocalizeKey` it doesn't substitute a literal for a miss). `lang.LSelectPlural(keyPrefix, selector, count, data…)` picks the variant then resolves plural forms *inside* it via `LocalizePluralKey`, so gender × plurality compose. Worked example (catalog `profile_updated.female/.male/.other`, both en+de in `translations/base.{en,de}.json`): `LSelect("profile_updated", gender, map[string]any{"Name": name})` → en `"Alex updated her/his/their profile"`, de `"Alex hat ihr/sein/ihr Profil aktualisiert"`. Both react to `lang.SetLocale` for free (routed through `X`/`LocalizeKey`). `bellui translate` seeds these keys (see the catalog-workflow bullet).
- **CLDR long-tail formatting** (`lang/list.go`, `lang/unit.go`, #506) — locale-correct formatting beyond dates/numbers/currency:
  - `lang.FormatList(items []string) string` — joins with the active locale's CLDR list pattern (the conjunction word, separators and Oxford comma are per-locale data, sourced from catalog keys `list.two/start/middle/end`): `["a","b","c"]` → en `"a, b, and c"`, de `"a, b und c"`, fr `"a, b et c"`, ja `"a、b、c"`, zh-Hans `"a、b和c"`. Handles 0/1/2/N; items are inserted verbatim (no templating). Never hand-assemble a list with a literal `", "` + `"and"`. **All 15 bundled locales** carry authoritative CLDR `list.*` keys (#860) — cs/fr patterns include the CLDR NBSP / narrow-NBSP verbatim.
  - `lang.FormatUnit(value float64, unit Unit) string` — a **scoped** unit set (length: `UnitMeter/Kilometer/Mile/Foot`; mass: `UnitGram/Kilogram/Pound`; extend on demand, not the full CLDR grid). Numeric part uses `FormatDecimal` (locale separators — de `"3,5 km"`), the label comes from catalog keys `unit.*` (all 15 locales, #860 — Cyrillic `км`, Greek `χλμ.`, Chinese `公里`, Tamil `கி.மீ.`, French narrow-NBSP). The label is **count-inflected via the locale's CLDR plural rules** (#862): each `unit.*` value is a plural message object (`{one,few,many,other}` with a `{{.Value}}` placeholder), and `FormatUnit` routes through the plural machinery (in-package `localizeUnit` → `localize`, since the exported `LocalizePluralKey` is `int`-only and would mis-categorize fractions) keyed on `pluralCount(value)`. So Polish `UnitMile` renders `1 mila` / `2 mile` / `5 mil`, Ukrainian `1 миля` / `2 милі` / `5 миль`. Every `unit.*` message carries exactly the plural categories the locale uses (missing CLDR forms filled from `other`), so an invariant abbreviation (pl `km`) never triggers a "no plural form" error.
  - `lang.PreferredLengthUnit()` reports the locale's road-distance unit (`UnitMile` for US/GB/LR/MM via `mileRegions`, `UnitKilometer` elsewhere). Prefer the convenience helpers `lang.FormatDistance(meters float64)` and `lang.FormatMass(grams float64)` (#861) which take a **base-SI magnitude**, pick the locale unit system *and convert*: metric gets m/g below the 1 km / 1 kg threshold and km/kg above; imperial gets ft/mi (below/above 1 mile) and lb. Converted magnitudes are rounded to two decimals. Use `FormatUnit` directly only when you already hold a value in a specific unit.
  - **Non-Gregorian calendars are an explicit non-goal** of `lang.FormatDate`/`widget.DatePicker` (#506): Go's stdlib has no calendar-system support and `DatePicker` assumes Gregorian month/era structure throughout. Buddhist/Japanese-era/Hijri/Hebrew/Persian calendars are declined-unless-demanded — revisit only with a concrete consumer + vetted dependency.

### Custom Default Theme & Render Style System
The fork replaces Bellui's default theme with `enhancedTheme` (`theme/enhanced.go`), which implements Material Design 3 (MD3) color system and typography:

**MD3 Color System**: Colors are generated dynamically from the primary color using HCT (Hue-Chroma-Tone) tonal palettes (`theme/hct.go`). The `CorePalettesFromPrimary()` function generates 6 palettes (Primary, Secondary, Tertiary, Error, Neutral, NeutralVariant) from the selected primary color. `MD3Scheme` (`theme/md3_scheme.go`) maps these palettes to ~30 named color roles with proper tone assignments for dark/light variants.

**New MD3 Color Roles** (in `theme/color.go`):
- Primary group: `ColorNamePrimaryContainer`, `ColorNameOnPrimaryContainer`
- Secondary group: `ColorNameSecondary`, `ColorNameOnSecondary`, `ColorNameSecondaryContainer`, `ColorNameOnSecondaryContainer`
- Tertiary group: `ColorNameTertiary`, `ColorNameOnTertiary`, `ColorNameTertiaryContainer`, `ColorNameOnTertiaryContainer`
- Error group: `ColorNameErrorContainer`, `ColorNameOnErrorContainer`
- Surface hierarchy: `ColorNameSurface`, `ColorNameSurfaceDim`, `ColorNameSurfaceBright`, `ColorNameSurfaceContainerLowest/Low/Medium/High/Highest`
- On-surface: `ColorNameOnSurface`, `ColorNameOnSurfaceVariant`
- Outline: `ColorNameOutline`, `ColorNameOutlineVariant`
- Inverse: `ColorNameInverseSurface`, `ColorNameInverseOnSurface`, `ColorNameInversePrimary`
- Utility: `ColorNameScrim`

Legacy Bellui color names (Background, Foreground, Button, etc.) are mapped to their MD3 equivalents automatically.

**MD3 Typography Scale** (15 tokens in `theme/size.go`):
- Display: `SizeNameDisplayLarge` (57), `DisplayMedium` (45), `DisplaySmall` (36)
- Headline: `SizeNameHeadlineLarge` (32), `HeadlineMedium` (28), `HeadlineSmall` (24)
- Title: `SizeNameTitleLarge` (22), `TitleMedium` (16), `TitleSmall` (14)
- Body: `SizeNameBodyLarge` (16), `BodyMedium` (14), `BodySmall` (12)
- Label: `SizeNameLabelLarge` (14), `LabelMedium` (12), `LabelSmall` (11)

Pre-built `TextStyle` presets in `theme/typography.go` bundle weight, line-height scale, and letter spacing per MD3 spec (e.g., `TypographyBodyMedium`, `TypographyTitleMedium`).

**Render Style Selection**: Themes can implement the typed `internal/theme.RenderStyleTheme` interface (`RenderStyle() RenderStyle`) to select a visual style; a separate `internal/theme.MobileTheme` (`DeviceIsMobile() bool`) overrides the form factor. These replaced the old type-erased `FeatureTheme.Feature(name) any` lookup (#39), following the codebase's optional-interface pattern (`CloudApp`, `MasterWindow`, etc.) so callers no longer assert at runtime. Widget renderers check `internaltheme.RenderStyleForWidget(w)` and adjust visuals:
- `RenderStyleClassic` (default for themes without `RenderStyleTheme`) — original Bellui look
- `RenderStyleModern` — gradient button backgrounds, card background fills, deeper shadows

`DarkTheme()`/`LightTheme()` still return the original `builtinTheme` for backward compatibility. Only `DefaultTheme()` returns the `enhancedTheme`.

### Dense Theme
`theme.DenseTheme()` (`theme/dense.go`) — high-density desktop theme for information-packed applications (trading systems, monitoring dashboards). Key differences from enhanced theme:
- **Text**: 12px base (vs 14), 18px heading (vs 24), 10px caption (vs 11)
- **Spacing**: 2px padding (vs 6), 4px inner padding (vs 10), 2px line spacing (vs 4)
- **Icons**: 16px inline (vs 20)
- **Radii**: 4px inputs/buttons (vs 8)
- **Scrollbars**: 8px (vs 12), 2px small (vs 3)
- **Shadows**: disabled (depth 0)
- **Colors**: Uses MD3 color system from enhanced theme (same tonal palette generation)

### Theme Selector Widget
`widget.ThemeSelector` / `NewThemeSelector(changed)` (#430) — compact appearance picker for app settings pages: a System/Light/Dark `SegmentedButton` (localized) above the 8 `theme.PrimaryColorNames()` swatches with a selected ring. **Callback-driven**: holds `Selection ThemeSelection{Variant ThemeVariantSelection, Primary string}` and fires `OnChanged(ThemeSelection)`; the widget never writes the system-wide bellui settings (unlike `bellui_settings.LoadAppearanceScreen`). Companions:
- `ThemeSelection.Apply()` — re-themes the **running app only** via `Settings().SetThemeVariant` plus the optional `bellui.PrimaryColorSettings` interface (`SetPrimaryColor(name)`, implemented by the real app settings and the test app; also non-persistent). `ThemeVariantSystem` resolves the OS variant at call time (no live OS follow).
- `SaveThemeSelection(sel, p)` / `LoadThemeSelection(p) (ThemeSelection, bool)` — round-trip the choice through an app's own `bellui.Preferences`; apply the loaded selection at startup.
- Non-goals (per #430): per-role theme editor, scale/animation toggles (stay in `bellui_settings`); arbitrary custom primary color is a possible follow-up.
