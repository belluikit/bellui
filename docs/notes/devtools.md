### Widget-Tree Inspector (DevTools, pre-rebrand tracker #540)
`dev/inspector` — an opt-in, **read-only** runtime widget-tree inspector for debugging layouts (the human-facing half of the pre-rebrand tracker #490-deferred introspection seam). `inspector.Show(w bellui.Window) *Inspector` opens a **separate** native window (desktop-only; mobile/wasm are single-window and out of scope) targeting `w`; apps gate it themselves (e.g. `if os.Getenv("BELLUI_INSPECT") == "1" { inspector.Show(w) }`). Heavy code is only linked when the package is imported (`theme/cjk` placement pattern); the existing lightweight `dev.Enable(w)` F12 overlay is unrelated and untouched.
- **Tree pane** (`tree.go`): a full object forest built by `snapshotRoots` over the target's content + overlays (minus the inspector's own highlight/pick surfaces), driven by the same `internal/driver.WalkVisibleObjectTree` the painter/hit-test use — so it descends **both containers and widget-renderer internals**, and records absolute positions + clip bounds identically. Nodes get stable per-refresh path UIDs (`"0/1/2"`) fed to a `widget.Tree`; a `byObj` map keys nodes by live object for pick. **On-demand only** — a Refresh button (no ticker), so a closed/idle inspector costs nothing.
- **Detail pane** (`detail.go`): `describe(node)` is a pure function → Position/Size/MinSize (dp), absolute bounds, `Visible()`, clip, `*container.Scroll` offset+content size, `*container.DirectionScope.ScopedDirection()`, `*container.ThemeOverride` presence, and the a11y snapshot via `core.SnapshotAccessible` (role/label/value). Role names come from the new **`core.AccessibleRole.String()`** (added in `core/accessible_role_string.go`; a slice indexed in iota order, falls back to `AccessibleRole(n)`).
- **Highlight** (`pick.go`): selecting a node adds a stroke-only `canvas.Rectangle` overlay to the **target** canvas at the node's absolute bounds. **Pick mode**: the Pick button adds a transparent full-canvas `pickOverlay` (Hoverable+Tappable+Focusable) on the target; hover previews the deepest object under the cursor (`resolveObjectAt` → `driver.FindObjectAtPositionMatching` over content only, so overlays/highlight are never picked), click selects it in the tree (refresh → `byObj` lookup → open ancestors → `Tree.Select`), Escape cancels (the overlay grabs keyboard focus so the app's own key handler is untouched). Everything added to the target is removed on the inspector window's `SetOnClosed`.
- Snapshot accessor methods are **nil-receiver-safe** — the `widget.Tree` lays out (calling `childUIDs`/`isBranch`) during `SetContent` before the first `refresh()` populates `snap`. Phase 2 candidates (refresh counters, MinSize-chain explanation, snapshot diff, text export) are listed in pre-rebrand tracker #540, not built.
- **Public pick primitive (pre-rebrand tracker #602)**: the forward hit-test the inspector uses internally is also exposed publicly for out-of-module tooling (the design-tool preview pane's pick-to-source, pre-rebrand goed tracker #35) — `driver.ObjectAtPosition(c core.Canvas, pos) (obj, bounds, ok)` and `driver.ObjectAtPositionMatching(c, pos, matches)` in the public `driver` package (`driver/objectat.go`, mirroring `driver.ClipBoundsForObject`), thin wrappers that probe through the canvas's **own dispatch hit-walk** when it exposes one (an unexported capability assertion satisfied by the glfw and mobile canvases, #245) — so the desktop menu bar, the mobile window head/open menu and the spatial-index fast path all behave exactly as tap dispatch — falling back to `internal/driver.FindObjectAtPositionMatching` over overlays+content (the whole tree on the test/embedded canvases), honoring input-pass-through overlays, and returning the object's absolute bounds. The reverse (object→highlight) was already public via `bellui.Driver.AbsolutePositionForObject` + a `canvas.Rectangle` overlay. **Coordinate space (#235)**: probe and bounds are in the `Driver.AbsolutePositionForObject` space — the wrappers translate by the canvas `InteractiveArea()` inset on the way in and out, so composing the two public APIs is exact on every driver (the inset is non-zero on mobile and the test canvas; the raw-tree helpers `GeometryForObject`/`ClipBoundsForObject` deliberately stay in the other space, see their doc comments). Event positions are raw-tree too — the tap dispatcher feeds the hit-walk the same position it delivers as `event.PointEvent.AbsolutePosition` — so an event-sourced probe subtracts the inset before calling the public wrappers (a no-op on desktop).


### Analytics — Consent-First, Battery-Safe Event Package (pre-rebrand tracker #526, Phase 1)
`analytics` is an **opt-in package beside the toolkit** (the `theme/cjk` placement pattern): Bellui core, drivers and widgets are 100% analytics-unaware and the package costs nothing unless imported. The only toolkit integration point is the public `bellui.Lifecycle`. It gives every app the event queue, consent gate, batching loop and flush-on-background logic that they would otherwise hand-roll (and get wrong on mobile). Phase 2 (semantic auto-capture via the accessibility tree) is the separate pre-rebrand tracker #527 and is **not** built here — instrumentation is explicit-`Track`-only.
- **Public API** — `analytics.Tracker` interface (`Track(event, props)`, `Identify(id, traits)`, `Flush() error`, `SetEnabled(bool)`), `analytics.New(sink Sink, opts ...Option) Tracker`, package-level default tracker (`SetDefault`/`Default` + free `Track`/`Identify`/`Flush`/`SetEnabled` delegating to it; the default is a safe no-op until installed), `analytics.Attach(t, lc)` (wires session lifecycle) and `analytics.Close(t)` (stops the worker; both operate on the interface via internal assertion, keeping the `Tracker` interface at exactly the 4 spec methods). `Event{Kind, Name, Props, Traits, UserID, SessionID, Timestamp}`; `Sink` interface `Send(batch []Event) error`.
- **Consent invariant (enforced by construction, tested)** — a `Tracker` **starts DISABLED**. Until `SetEnabled(true)`, `Track`/`Identify` drop events: nothing is queued in memory, nothing spooled to disk, nothing sent (`TestConsentGate_NothingBeforeEnable`). The package generates **no device identifiers** — no advertising ID, no fingerprint, no random install ID; identity is supplied by the app via `Identify` only. The per-run `SessionID` is ephemeral (rotated every launch, never persisted as identity) so it is not a device/install ID (`TestNoDeviceIdentifierGenerated`). `SetEnabled(false)` drops the in-memory queue and clears the disk spool (`TestDisableClearsSpool`). This keeps the **Google Play Data-safety / GDPR** story honest: consent withheld ⇒ no collection, no identifier to declare; consent granted ⇒ only app-declared events + app-supplied identity, so the Data-safety form maps 1:1 to the app's explicit `Track`/`Identify` calls.
- **Battery model (hard API contract, documented on methods, tested)**, `tracker.go`:
  1. `Track` is **fire-into-queue, never fire-into-socket** — it appends to the in-memory ring, checkpoints the spool, and (past the batch threshold) asks the background worker to flush via a non-blocking channel signal; it never calls `Sink.Send`. Proven by `TestTrack_NeverSendsSynchronously` (a threshold-crossing `Track` returns promptly even while a blocking sink is stuck) and the sink call-count assertions.
  2. Batch flush policy (all `Option`s, radio-conservative defaults): `WithBatchSize` (≥30 events) ∨ `WithInterval` (≥60 s foreground) ∨ `EnteredBackground` (the `SetOnExitedForeground` edge) ∨ explicit `Flush()`.
  3. The interval **ticker is suspended while backgrounded** (`ctrlSuspend` stops it; mobile processes freeze) and resumed on foreground; the background-edge flush is the workhorse (`attach` → `SetOnExitedForeground` tracks `session_end`, forces a flush, then suspends). Deterministically tested with a fake clock/ticker — no wall-clock, no sleeps (`TestIntervalFlush`, `TestIntervalSuspendedWhileBackground`).
  4. **Disk spool** via a `Store` (default `BelluiStore` over `bellui.Storage`; in-memory fallback when no app): the ring is checkpointed on every enqueue and after a successful flush (each event is encoded once, when queued, and a checkpoint joins the cached pieces into the same PXF bytes a whole encode gives, #657; a batch being sent stays in the spool until its send succeeds, #670), survives process death, drains **oldest-first** on the next `SetEnabled(true)` (`TestSpoolRoundTrip`), and is bounded by `WithMaxSpool` with oldest-first eviction so a dead sink can't grow it without limit (`TestMaxSpoolEviction`).
  5. Batch bodies are **gzipped by the Sink** (`analytics.PostJSONGzip`); exactly one request per flush.
  6. A failed flush **retains** the events and arms **exponential backoff with full jitter** (`WithBackoff`); non-forced flushes are gated until the window elapses so we never retry into a dead radio (`TestBackoffRetainsAndGates`). Offline is a normal state, not an error.
  7. **Documented limitation**: pure-Go apps have no JNI surface for Android WorkManager / iOS BGTaskScheduler, so there is no OS-scheduled deferred upload. Compensation is bigger batches, longer intervals, the background-edge flush and the next-launch drain; one-session analytics latency is acceptable by design.
- **Determinism seams** — `WithClock(Clock)`, `WithJitterSource(func() float64)` and `WithStore(Store)` inject time, jitter and persistence so all timing/backoff tests are deterministic (fake clock + manual ticker; no real sleeps).
- **Vendor sinks** are dumb single-file optional subpackages over `net/http` + `analytics.PostJSONGzip`: `analytics/ga4` (GA4 Measurement Protocol; `New(measurementID, apiSecret)`; ≤25 events/request; `client_id` from the app-supplied `UserID`, else the ephemeral `SessionID` — never synthesised) and `analytics/posthog` (`New(apiKey)` / `NewWithHost`; `/batch/` capture; `distinct_id` likewise). Stdlib-only (`net/http`, `compress/gzip`, `encoding/json`); apps can bring their own `Sink`.
- **Remaining (manual follow-up, not attempted here)**: live-verify against a real backend (PostHog or GA4-MP) from desktop plus the Android probe app, observing batch cadence (mitmproxy / backend timestamps) rather than per-event traffic.

### Analytics — Semantic Auto-Capture (pre-rebrand tracker #527, Phase 2)
Opt-in sugar on top of phase 1: turn taps into `"ui.activate"` events with **no per-widget instrumentation**, deriving role/label/state from the public accessibility layer. Explicit `Track` remains the primary model; this is purely additive.
- **Seam = a `core` hook** (`core/activation.go`, mirrors the `SetFontFallbackRegister`/`RegisterTextMeasure` pattern — keeps `core` widget-free, nothing added to `CanvasObject`): `var core.OnActivation func(obj CanvasObject, viaKeyboard bool)` + guarded `core.NotifyActivation(obj, viaKeyboard)`. Nil unless a consumer is installed, so an app that never imports auto-capture pays **one nil check per activation** (`TestOnActivation_NilByDefault`). Drivers call `core.NotifyActivation(co, false)` at each tap-dispatch site, right where `wid.Tapped(ev)` fires, once per activation: glfw `window.go` (single-tap + `waitForDoubleTapEnded` fallback — mutually exclusive, so one fire; wasm rides the same glfw path), mobile `driver.go` `TapUp`, embedded `driver.go` `TapUp`.
- **Screen-reader activations** (`-tags accessibility`): the a11y AXPress/UIA/mobile-activate paths call `obj.Tapped(...)`/`PerformAccessibleAction(...)` **directly**, NOT through the driver tap-dispatch seam, so they are *not* covered "for free" by the driver-site placement (the pre-rebrand tracker #527 issue note assumed otherwise). To deliver the intended screen-reader parity, `core.NotifyActivation(obj, false)` is also fired at each a11y primary-activation entry point: darwin `belluiAccessibilityPerformPress` (both branches), windows `belluiWinA11yInvoke`/`Toggle`/`Select` (each success branch, once — Toggle/Select fall through to Invoke so no double-fire), mobile `accessibility.go` activate (both branches). Increment/decrement/expand/collapse/rename/delete are secondary actions and deliberately do **not** fire. Darwin is compile-verified under `-tags accessibility`; windows/mobile cgo are CI-verified per repo convention.
- **Consumer** (`analytics/autocapture.go`): `analytics.EnableAutoCapture(t Tracker, opts ...CaptureOption)` sets `core.OnActivation`; `analytics.DisableAutoCapture()` clears it. On activation it snapshots via `core.SnapshotAccessible(obj)` and maps **Role→verb** (`verbForRole`: Button/Link/MenuItem→`press`, Checkbox/Switch→`toggle`, ListItem/Tab→`select` — the `core.ActionPress/Toggle/Select` vocabulary; **every other role is skipped**, no event) then emits `t.Track("ui.activate", props)`. Everything inherits phase 1's consent gate + spool + batching + backoff — it is **impossible to wire auto-capture to a raw sink**, it only ever calls `Tracker.Track` (`TestAutoCapture_ConsentGate`: disabled tracker captures nothing; enabled flows through the queue + sink).
- **Privacy guardrails (all enforced in `onActivation`, none optional):**
  - **Role/label/state ONLY** — props are `role` (lowercased `AccessibleRole.String()`), `verb`, `label` (omitted when empty), `state` (`[]string` of active flag names, omitted when none), `via:"keyboard"` when keyboard-sourced. The mapper **never reads `node.Value` or `node.Description`** — that is the privacy line (`TestAutoCapture_NeverValueOrDescription` populates value/description with sentinels and asserts they never appear under any key).
  - **Concealed exclusion**: a new optional interface `core.AccessibleConcealed{ AccessibleConcealed() bool }` (implemented by `widget.Entry`, true iff `Password`); a target reporting true is skipped wholesale, regardless of role (`TestAutoCapture_ConcealedExcluded`). Belt-and-suspenders on top of never capturing values.
  - **`NoCapture` subtree opt-out (option B — top-down ancestor walk, NO `CanvasObject` change):** `analytics.NoCapture(content core.CanvasObject) core.CanvasObject` wraps content in a layout-transparent `*bellui.Container` whose `Layout` is the private `noCaptureLayout` marker. At capture time the consumer resolves the object's canvas (`bellui.CurrentApp().Driver().CanvasForObject(obj)`) and walks the root→obj ancestor chain via the new public **`driver.AncestorsOfObject(c core.Canvas, obj) ([]core.CanvasObject, bool)`** (`driver/ancestors.go`, sibling to `driver.ObjectAtPosition`, reuses `internal/driver.WalkVisibleObjectTree`; touches zero widgets); if any ancestor is the marker container the event is skipped (`TestAutoCapture_NoCaptureSubtree`). Taps are rare, so the O(tree) walk per activation is fine.
  - **Sampling**: `WithSampling(n)` captures 1-in-N of the **eligible** activations via a deterministic atomic counter (not wall-clock), applied *after* the privacy filters so it is a true 1-in-N of would-be events; non-capturable activations (a tapped label) do not advance the counter (`TestAutoCapture_Sampling`, `TestAutoCapture_SamplingCountsOnlyEligible`).
- **Keyboard activation coverage** (pre-rebrand tracker #700, superseding the original "partial, by design" note). Keyboard activations are captured, with `via:"keyboard"`, through two routes. (1) **Driver route:** a focused widget that implements `event.Activatable` and answers `ActivatedByKey(ev) == true` gets `core.NotifyActivation(obj, true)` from the driver just before its `TypedKey` runs — glfw `window.go`, mobile `driver.go` and embedded `driver.go` all do this. `Button`, `Hyperlink` and `Switch` implement it, so only a key the control treats as activation fires the signal, never an arrow, Backspace or a Space typed into an `Entry`. (2) **Self-notify route:** widgets that activate an inner item from their own key handler call `core.NotifyActivation(item, true)` themselves — `Check`, `List` and `GridWrap` items, `Table` cells, `Tree` nodes and menu items. A widget that activates on a key without taking either route is not captured; pointer taps and screen-reader activations are covered as before.
